## 1. 目的

この文書は、学習に使う Dataset の各列が何を意味し、どの値を許し、欠けたときに何が起きるかを定める。

同じ列について、3つの場所が別々のことを決めている。この文書は、その3つを1つの表に並べる。

| 決めている場所 | 決めていること |
| --- | --- |
| `ml/semiconductor_quality/domain.py` | どの列が在り、どれが数値でどれがカテゴリか、どれが答えか |
| `config/data_quality.yaml` | 各列がどの範囲の値を持ちうるか、どのカテゴリを宣言済みとするか |
| `services/prediction_api/schemas.py` | 推論の要求として受け入れる範囲 |

列の一覧は、コード側と `config/data_quality.yaml` の間で読み込み時に突き合わせる。
片方だけに列を足すと読み込みが失敗する（`ml/data_quality/contract.py`）。

## 2. 適用範囲

対象は Dataset `semiconductor-quality-data`（ClearML Project `Semiconductor Quality Prediction`）の
CSV `semiconductor_quality.csv` である。

ClearML が内部で持つ実体（Task・Model の属性）は対象外とする。

## 3. 前提

このデータは `tools/semiconductor_seed` が生成した合成データであり、実在の製造データではない。
値の分布は生成器が決めており、実工程の分布を再現したものではない。

## 4. 定義

### 4.1 Dataset

| 項目 | 内容 |
| --- | --- |
| Dataset 名 | `semiconductor-quality-data` |
| ClearML Project | `Semiconductor Quality Prediction` |
| ファイル | `semiconductor_quality.csv`（UTF-8、ヘッダ行あり、カンマ区切り） |
| 版 | 1.0.0（1,200行）、2.0.0（2,500行） |
| 学習時の別名 | `training-dataset` |
| 識別子 | `sample_id`。版の中で一意 |
| 更新頻度 | 生成コマンドを実行したときだけ。定期更新は無い |

版の違いは行数と、装置ごとの効果・雑音の大きさである（2.0.0 のほうが雑音が小さい）。

### 4.2 列の定義

11列ある。順序は CSV の並びである。

| # | 物理名 | 論理名 | 型 | 単位 | NULL | 値域（品質条件） | 推論 API の受入範囲 | 役割 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `sample_id` | 検体 ID | 文字列 | — | 不可 | 形式 `SAMPLE-00001`（連番5桁） | 1文字以上 | 識別子 |
| 2 | `equipment_id` | 装置 ID | 文字列 | — | 不可 | `EQ-01` / `EQ-02` / `EQ-03` / `EQ-04` | 1文字以上 | カテゴリ特徴量 |
| 3 | `process_step` | 工程 | 文字列 | — | 不可 | `CLEAN` / `DEPOSITION` / `ETCH` | 1文字以上 | カテゴリ特徴量 |
| 4 | `temperature` | プロセス温度 | 実数 | ℃ | 不可 | 0 〜 1000 | -273.15 〜 5000 | 数値特徴量 |
| 5 | `pressure` | 圧力 | 実数 | 装置指示値 | 不可 | 0 〜 1000 | 0 〜 100000 | 数値特徴量 |
| 6 | `process_time` | 処理時間 | 実数 | 秒 | 不可 | 0 〜 3600 | 0 〜 100000 | 数値特徴量 |
| 7 | `gas_flow` | ガス流量 | 実数 | 装置指示値 | 不可 | 0 〜 1000 | 0 〜 100000 | 数値特徴量 |
| 8 | `sensor_1` | センサ1（正規化済み） | 実数 | 無次元 | 不可 | -10 〜 10 | -1000000 〜 1000000 | 数値特徴量 |
| 9 | `sensor_2` | センサ2（正規化済み） | 実数 | 無次元 | 不可 | -10 〜 10 | -1000000 〜 1000000 | 数値特徴量 |
| 10 | `inspection_value` | 検査値 | 実数 | 装置指示値 | 不可 | 0 〜 100 | -1000000 〜 1000000 | 数値特徴量 |
| 11 | `result` | 判定結果 | 文字列 | — | 不可 | `pass` / `fail` | — | 目的変数 |

単位のうち「装置指示値」と書いたものは、生成器が単位を定めていない。実データを扱う場合は、
受け入れ時に単位を確定させる必要がある（§6）。

小数の桁数は、生成時に小数第5位まで書き出される。保存形式としての桁制限は無い。

### 4.3 値域の2つの意味

品質条件の値域（`config/data_quality.yaml`）は、その値が物理的にありうるかで決めてある。
いまの Dataset が収まっている範囲ではない。狭くしすぎると、正常な製造条件の変化で学習が止まる。

推論 API の受入範囲は、それより大幅に広い。測定値になりえない値（負の圧力、数千度の温度）を
422 で断ることだけが目的で、珍しい製品を断るためではない。珍しいかどうかを決めるのはモデルの側である。

### 4.4 現在の Dataset が実際に持つ値

生成器が使う分布である（`tools/semiconductor_seed/generator.py`）。
これは「いま入っている値」であり、許容範囲ではない。

| 列 | 生成の仕方 |
| --- | --- |
| `equipment_id` | 4種から一様に選ぶ |
| `process_step` | 3種から一様に選ぶ |
| `temperature` | 平均 450、標準偏差 18 の正規分布 |
| `pressure` | 平均 100、標準偏差 11 |
| `process_time` | 平均 60、標準偏差 8 |
| `gas_flow` | 平均 50、標準偏差 6 |
| `sensor_1` | `0.035 × (temperature - 450)` に標準偏差 0.8 の雑音 |
| `sensor_2` | `0.045 × (pressure - 100)` に標準偏差 0.9 の雑音 |
| `inspection_value` | 平均 10、標準偏差 1.2 |
| `result` | 温度の逸脱・圧力と時間の交互作用・`EQ-04` であること・センサ1の逸脱・検査値の超過を足した危険度が上位38%なら `fail` |

`sensor_1` と `sensor_2` は、それぞれ温度と圧力から導かれている。
独立した測定値ではないため、特徴量の重要度を読むときに注意が要る（20 §既知の弱点）。

`EQ-04` は他の装置より不良が出やすいように作られている。装置と結果の関係は、
生成器が意図的に入れたものである。

### 4.5 欠損・異常の扱い

欠損値は許さない。空欄・数値に変換できない値・列の過不足は、学習を始める前に拒否される
（`ml/semiconductor_quality/dataset.py`）。拒否のときは、問題のある列と行を挙げる。

したがって「NULL の意味」は定義しない。欠損を意味として受け取る経路が無いためである。
実データを受け入れる場合は、欠損が「測っていない」のか「測れなかった」のかを区別する必要がある（§6）。

列が揃っていても学習に使うべきでない状態は、別の判定が見る（`ml/data_quality`）。

| 観点 | 条件 | 超えたときの扱い |
| --- | --- | --- |
| 値域外 | 各数値列が §4.2 の範囲を外れる | 違反として報告し、終了コードで落とす |
| 未知のカテゴリ | 宣言していない `equipment_id` / `process_step` が1件でもある | 同上（許容割合 0.0） |
| ラベルの偏り | `pass` または `fail` の割合が 5% を下回る | 同上 |
| 識別子の重複 | `sample_id` の重複が1件でもある | 同上（許容割合 0.0） |
| 行数 | 各ラベルが3行未満 | 3分割できないため学習入力として拒否する |

装置を増設したら `config/data_quality.yaml` の `allowed` に足す。足さずに流すと、
モデルが一度も見たことのない装置で判定することになる。

### 4.6 データの取得元と来歴

現在の取得元は生成器だけである。来歴は3段で記録する（`ml/data_quality/lineage.py`）。

| 段 | 意味 | 現在の中身 |
| --- | --- | --- |
| `raw` | 工程から届いたままの測定値 | 生成器の出力 |
| `curated` | 残すと決めたもの（行の除外、列名の統一、単位の正規化） | 現在は raw と同一 |
| `training` | 学習に使ってよい Dataset。ClearML が版を持つ | 登録された Dataset 版 |

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 列の定義をコードに、値域を YAML に置く | 値域は工程とともに変わり、変える人と配備する人が別だから |
| 両者を読み込み時に突き合わせる | 片方にだけ列を足すと、その列が黙って検査されなくなるから |
| 未知カテゴリの許容を 0 にする | 増設は宣言してから流す運用を強制するため |
| `fail` を正例とする | 不良を見つけられないモデルは、全体の正解率が高くても役に立たないため |

## 6. 未決事項

* `pressure`・`gas_flow`・`inspection_value` の単位。生成器は無次元の指示値として扱っている。
* 実データを受け入れる場合の欠損の意味と、その扱い。
* 桁数の制約。現在は生成時の小数第5位が事実上の精度であり、要求として定めていない。
* データ保持期間と削除条件。12（データ保持ポリシー）で定める。未着手。
