# docs

本プロジェクトの設計・運用資料を置く。

## 1. 構成

| 場所 | 内容 |
| --- | --- |
| `docs/*.md` | 番号付きの体系資料。要件から運用・ガバナンスまでを、番号帯で分けて並べる |
| `docs/backlog/` | 未解決ストーリー。着手していない実装・文書・確認を、着手条件つきで残す |
| `docs/_archive/` | 2026-09-12 の体系整備以前の資料。ADR・runbook・脅威モデルをそのまま凍結してある |

番号帯は次のとおり。

| 帯 | 分類 |
| --- | --- |
| 00番台 | 上流設計（要件・非機能要件・方式・構成・基本設計・詳細設計） |
| 10番台 | データ管理 |
| 20番台 | ML固有（モデルカード・データセットカード・再現性・評価基準・リスク） |
| 30番台 | テスト・品質保証 |
| 40番台 | 運用 |
| 50番台 | セキュリティ・ガバナンス |
| 60番台 | チーム開発標準 |
| 70番台 | プロジェクト管理 |

## 4. `_archive/` の扱い

`_archive/` の資料は更新しない。ADR 10本は意思決定の記録として、runbook 9本は実機で確認した手順として、
書かれた時点の内容のまま残す。新しい体系資料は、判断の経緯や具体的な操作手順を写し取らず、
`_archive/` の該当箇所へリンクする。

| 種別 | 本数 | 参照のされ方 |
| --- | --- | --- |
| `_archive/adr/` | 10 | 「なぜその方式を選んだか」の根拠。03・61 から参照する |
| `_archive/runbooks/` | 9 | 「どう操作するか」の手順。40番台（未着手）と 22 から参照する |
| `_archive/security/001_20260908_threat_model.md` | 1 | データ分類と信頼境界。02 と 50番台（未着手）から参照する |

移設に伴い、コード・設定・CI 内のパス参照（13ファイル）も `docs/_archive/` へ書き換えてある。
`x-plan-改訂/` 配下は履歴として凍結する取り決めのため、旧パスのまま残してある。

## 5. ここに置かないもの

学習用のメモは `x-docs/`、計画と進捗は `x-plan-改訂/` にある。
ここに置くのは、別の人が同じことを再現できるかを基準にした資料に限る。
