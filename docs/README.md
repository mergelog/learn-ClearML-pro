# docs

本プロジェクトの設計・運用資料を置く。

## 1. 構成

| 場所 | 内容 |
| --- | --- |
| `docs/phase*/` | 番号付きの体系資料。`x-plan-改訂/20_ドキュメント作成プラン.md` の Phase ごとに分ける |
| `docs/backlog/` | 未解決ストーリー。着手していない実装・文書・確認を、着手条件つきで残す |
| `docs/_archive/` | 2026-09-12 の体系整備以前の資料。ADR・runbook・脅威モデルをそのまま凍結してある |

Phase とファイル名の番号帯は対応している。ファイル名の番号は移動前から変えていないため、
どのフォルダに在っても文書 ID は一意である。

| Phase | フォルダ | 帯 | 分類 |
| --- | --- | --- | --- |
| 1 | `phase1_上流設計/` | 00番台 | 要件・非機能要件・方式・構成・基本設計・詳細設計 |
| 2 | `phase2_データ管理/` | 10番台 | データ管理 |
| 3 | `phase3_ML固有/` | 20番台 | モデルカード・データセットカード・再現性・評価基準・リスク |
| 4 | `phase4_テスト品質保証/` | 30番台 | テスト・品質保証 |
| 5 | `phase5_運用/` | 40番台 | 運用 |
| 6 | `phase6_セキュリティガバナンス/` | 50番台 | セキュリティ・ガバナンス |
| 7 | `phase7_チーム開発標準/` | 60番台 | チーム開発標準 |
| 8 | 未作成 | 70番台 | プロジェクト管理 |

1本目の文書を作るときに、そのフェーズのフォルダも作る。空のフォルダは置かない。

この37本との整合を確認する。

未着手の文書を参照している箇所には、その旨を書いてある。存在しない文書へのリンクは張らず、
フォルダの決まっていない文書はファイル名だけで参照する。

## 4. `_archive/` の扱い

`_archive/` の資料は更新しない。ADR 10本は意思決定の記録として、runbook 9本は実機で確認した手順として、
書かれた時点の内容のまま残す。新しい体系資料は、判断の経緯や具体的な操作手順を写し取らず、
`_archive/` の該当箇所へリンクする。

| 種別 | 本数 | 参照のされ方 |
| --- | --- | --- |
| `_archive/adr/` | 10 | 「なぜその方式を選んだか」の根拠。03・61・50・51 から参照する |
| `_archive/runbooks/` | 9 | 「どう操作するか」の手順。40〜44・22・50〜54・57 から参照する |
| `_archive/security/001_20260908_threat_model.md` | 1 | データ分類と信頼境界。02 と 50・53・54・57・58 から参照する |

移設に伴い、コード・設定・CI 内のパス参照（13ファイル）も `docs/_archive/` へ書き換えてある。
`x-plan-改訂/` 配下は履歴として凍結する取り決めのため、旧パスのまま残してある。

## 5. ここに置かないもの

ここに置くのは、別の人が同じことを再現できるかを基準にした資料に限る。
