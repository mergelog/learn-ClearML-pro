# Runbook: データ品質・lineage・drift

学習に使ってよいDatasetかどうかを、学習を始める前に判断するための手順。

## 2種類の検証がある

同じ「Datasetの検証」でも、見ているものが違う。

| 検証 | 実装 | 見るもの | 失敗したら |
| --- | --- | --- | --- |
| 学習入力の検証 | `ml/semiconductor_quality/dataset.py` | 列が揃っているか、値が数値か、ラベルが契約内か | 学習できないので停止 |
| データ品質の検証 | `ml/data_quality/` | 値が物理的にありうる範囲か、未知のカテゴリが無いか、ラベルが偏りすぎていないか | 学習できてしまうので停止 |

後者が必要なのは、「学習できる」と「学習してよい」が別だからである。
センサが上限に張り付いたDatasetも、不良がほとんど無いDatasetも、
前者の検証は通る。通ったうえで、使い物にならないモデルを作る。

Pipelineの `validate` ステップは**品質の検証を先に**行う。品質の検証は
生のテキストのまま測るためで、先に厳密な読み込みを通すと、欠損は
「拒否された」あとなので数えられなくなる。

## 合格条件

`config/data_quality.yaml` に書く。編集すれば次の実行から効く。

```yaml
numeric:
  temperature:
    minimum: 0      # 物理的にありうる下限。いまのデータの下限ではない
    maximum: 1000
categorical:
  equipment_id:
    allowed: [EQ-01, EQ-02, EQ-03, EQ-04]
    maximum_unknown_share: 0.0   # 未知の装置は1件も許さない
labels:
  minimum_share: 0.05            # どのラベルもこれを下回らない
identifiers:
  maximum_duplicate_share: 0.0
```

範囲は「その値が物理的にありうるか」で決める。いまのDatasetが収まっている
範囲まで狭めると、正常な製造条件の変化で学習が止まる。

列の一覧は `ml/semiconductor_quality/domain.py` と一致していなければならない。
食い違うと読み込み時に拒否される。コードに列を足してファイルに足し忘れると
無検査で通ってしまうため、その状態を作らせない。

## 1. Datasetに何が入っているか見る

```bash
corepack pnpm ml:data profile -- --dataset-version 1.0.0
```

判断は何もしない。列ごとの範囲・平均・広がり・欠損数、カテゴリの内訳、
ラベルの数、重複した `sample_id` の数が出る。

登録前のCSVも見られる。

```bash
corepack pnpm ml:data profile -- --csv path/to/semiconductor_quality.csv
```

## 2. 使ってよいか判断する

```bash
corepack pnpm ml:data check -- --dataset-version 1.0.0
```

満たしていれば終了コード0、満たしていなければ1で、理由が全部出る。

```text
the dataset does not meet the data quality contract:
- temperature: expected no value above 1000.0, but found a value of 5000.0
- equipment_id: expected only the declared values: EQ-01, EQ-02, EQ-03, EQ-04,
  but found EQ-99 (5.00% of the rows)
- result: expected at least 5.00% 'fail', but found 20 rows (1.67%)
```

理由は1つ目で止めずに全部出す。1回直して1回試す、を繰り返さないためである。

## 3. 前のバージョンから何が変わったか見る

```bash
corepack pnpm ml:data drift -- --dataset-version 2.0.0 --against 1.0.0
```

2つの測り方を使う。

- **数値列**: 平均が「前のバージョンの広がりの何倍」動いたか。
  単位ではなく広がりで測るので、温度でも正規化済みセンサでも同じ閾値が使える
- **カテゴリ列とラベル**: 分布を一致させるためにどれだけ動かす必要があるか。
  同じなら0、全く共通しなければ1

閾値は `--numeric-threshold` `--categorical-threshold` `--label-threshold` で
変えられる。既定は 0.5 / 0.2 / 0.1 である。

## 4. Pipelineの中で自動的に判断させる

`validate` ステップが毎回行う。追加の指定は要らない。

比較したいときだけ、前のバージョンを渡す。

```bash
corepack pnpm ml:pipeline -- --dataset-version 2.0.0 --drift-reference-version 1.0.0
```

`validate` Taskに残るもの。

| Artifact | 内容 |
| --- | --- |
| `data_profile` | 測った結果 |
| `data_quality` | 合否と、満たさなかった理由 |
| `data_drift` | 比較した場合のみ。列ごとの移動量と閾値 |
| `lineage` | このDatasetがどのバージョンの上に作られたか |
| `validation_report` | 学習入力としての検証結果 |

**品質を満たさない場合、ステップは失敗し、後続は起動しない。**
モデルは1つも作られない。

**driftが閾値を超えた場合、ステップは失敗しない。** 動いたデータも使える
データではあり、止めるべきかどうかは人が決める。代わりに次を残す。

- Taskのログに、どの列がどれだけ動いたか
- Taskに `data-drift` タグ（一覧から絞り込める唯一の手段）

## 5. どこから来たDatasetか追う

`lineage` アーティファクトが、そのDatasetが何の上に作られたかを持つ。

```json
{
  "links": [
    {"stage": "raw", "identifier": "<親のDataset ID>", "..." : "..."},
    {"stage": "training", "identifier": "<このDataset ID>",
     "sources": ["<親のDataset ID>"], "row_count": 1200}
  ]
}
```

段階は `raw` -> `curated` -> `training` の3つを想定しているが、
このプロジェクトでは生成スクリプトが training Dataset を直接作るため、
実際に現れるのは `raw`（親バージョン）と `training` だけである。
中間の curation を挟むようになったら、そこに `curated` が入る。

## 6. 検証失敗時の扱い

| 状況 | すること |
| --- | --- |
| 範囲外の値が少数 | 上流の計測を疑う。Datasetを直して新しいバージョンとして登録する。既存バージョンは書き換えない |
| 未知の装置が入った | 装置を増設したなら `config/data_quality.yaml` の `allowed` に追加し、なぜ追加したかをコミットに残す |
| ラベルが偏った | 期間を変えて取り直す。基準を下げて通すのは、モデルが何を学べないかを隠すだけである |
| 想定内の分布変化 | `minimum` / `maximum` を広げる。ただし「物理的にありうるか」で判断する |
| driftが出た | 止まってはいないので、まず比較結果を読む。再学習するか、そのまま使うかを決めて記録する |

**基準を緩めて通すときは、必ず理由をコミットメッセージに残すこと。**
`config/data_quality.yaml` の履歴が、いつ何を諦めたかの唯一の記録になる。

## トラブルシュート

| 症状 | 原因と対処 |
| --- | --- |
| `no longer matches the data contract` | コードの列とYAMLの列が食い違っている。両方を揃える |
| `at least one allowed value is required` | カテゴリ列の `allowed` が空 |
| `values that vary between rows` | その列が全行同じ値。センサの固着か、生成の不具合 |
| `--against-csv only makes sense together with --csv` | 登録済みバージョンとローカルCSVは比較できない。どちらかに揃える |
| driftが常に出る | 閾値が厳しすぎる。`--numeric-threshold` を上げるか、比較対象を見直す |
