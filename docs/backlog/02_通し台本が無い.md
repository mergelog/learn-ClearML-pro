## 何が起きているか

runbook 9本は部品ごとに独立している。1本ずつは異常系まで書かれているが、
それらを一続きに演じる筋書きが無い。

想定する筋書きは次のとおりである。

```text
新しいデータが来た
  → 品質判定（005）
  → 学習（002）
  → 探索（008）
  → 昇格（003）
  → 配備（004）
  → ドリフト検知（006）
  → rollback（003）
  → postmortem（006）
```

各段の観測点として台帳（BL-01）を挟むと、いま何を見ているのかが一本の線になる。

## 解決とみなす状態

新規の文書が1本あり、既存9本へのリンクと、各段の合否の判定と観測点だけを書いてあること。
手順そのものは書き写さない。二重管理になれば必ずずれる。

机上で書いて置くのは趣旨に反する。一度は実機で通す。

## 着手の条件

通しで実機を動かせる日を確保できること。BL-01 を先に済ませてあること。

ドリフトと rollback まで演じるなら、故意に条件を作る手間が加わる。
