# BL-02: runbook 9本を貫く通し台本が無い

| 項目 | 内容 |

## 何が起きているか

runbook 9本は部品ごとに独立している。1本ずつは異常系まで書かれているが、
それらを一続きに演じる筋書きが無い。

想定する筋書きは次のとおりである。

```text
新しいデータが来た
  → 品質判定（005）
  → 学習（002）
  → 探索（008）
  → 昇格（003）
  → 配備（004）
  → ドリフト検知（006）
  → rollback（003）
  → postmortem（006）
```

各段の観測点として台帳（BL-01）を挟むと、いま何を見ているのかが一本の線になる。

## 解決とみなす状態

新規の文書が1本あり、既存9本へのリンクと、各段の合否の判定と観測点だけを書いてあること。
手順そのものは書き写さない。二重管理になれば必ずずれる。

机上で書いて置くのは趣旨に反する。一度は実機で通す。

## 着手の条件

通しで実機を動かせる日を確保できること。BL-01 を先に済ませてあること。

## 2026-09-13 に作ったもの

`../phase5_運用/45_通し台本.md` を新しく置いた。既存の runbook は書き換えていない。

* 8段の並びと、各段が指す runbook へのリンク
* 各段の「次へ進んでよい条件」と観測点。手順そのものは写していない
* 台帳を観測点に持つ段（1・5・6）の明示
* §5.1 に、同じ日に実機で通した記録

実機では、品質判定から rollback までの8段のうち、段 9（postmortem）以外を通した。
段 9 は障害が起きていないため演じていない。演じていない段を演じたことにはしていない。

通して分かったことは 45 §5.1 に3つ書いた。昇格だけでは配備が切り替わらないこと、
Dataset 版が違う production とは退行を比較できなかったこと、
モデルの入れ替えで同じ入力の判定が変わったことである。

## 着手の条件が満たされていなかった点

BL-01（台帳が運用手順に現れない）を先に済ませる条件は満たしていない。
45 §4.3 に、どの段で台帳を見るかだけを先に置き、runbook 側への組み込みは BL-01 に残した。
