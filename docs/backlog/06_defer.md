# BL-06: `@defer` の導入

## 何をしないと決めたか

自作 feature の内側に `@defer` を入れて、初期バンドルを削ること。

## なぜしないか

入れても下がらないためである。2026-09-12 の実測は次のとおりである。

| 測ったもの | 値 | 予算 |
| --- | --- | --- |
| 初期バンドル（raw / 転送見積） | 3.10 MB / 796.21 kB | 警告 3.15 MB・失敗 3.30 MB |
| `data-catalog` の初期バンドルへの寄与 | 0（`loadChildren` で完全に遅延） | — |
| `data-catalog` の遅延 chunk | 4つ・計 約38 kB（最大 12.9 kB） | 警告 560 kB |

`@defer` が削れるのは自作 feature の内側だけで、そこは初期バンドルに1バイトも乗っていない。

## 残っている問題

初期バンドルの余裕は 0.05 MB（1.6%）しかない。これは凍結領域が積み上げたもので、
自作分を削っても届かない。削る対象は凍結領域であり、それは凍結方針（ADR 003）と衝突する。

## 再検討する条件

ビルドの警告が実際に出たとき。そのときに、凍結を一部やめるか、予算を上げるかを判断する。
