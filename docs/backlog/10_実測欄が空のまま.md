## 何が起きているか

20（モデルカード）と 22（再現性検証書）には、実行しなければ埋まらない欄がある。
文書作成時に学習を実行していないため、次が空のままである。

| 文書 | 空の欄 |
| --- | --- |
| 20 §4.1 | ClearML Task ID、Model ID |
| 20 §4.7 | train / validation / test の accuracy・precision・recall・f1・混同行列 |
| 22 §4.6 | 再実行の元 Task と再実行結果の対応表、差異 |

推定値では埋めない。埋めれば、測っていない数値が測ったものとして残る。

## 解決とみなす状態

学習を1回通し、Task の指標をそのまま転記してあること。
22 については、同じ条件でもう一度実行し、両者の差異を記録してあること。

## 着手の条件

学習を1回通せる日があること。併存プロジェクトを先に停止する必要がある。

BL-02（通し台本）と同じ実機作業で片付く。順序としては、通し台本を演じる過程で
この2文書の欄も埋まる。

## 2026-09-13 に埋めたもの

`pnpm ml:train -- --dataset-version 2.0.0` を2回実行し、次を転記した。

| 文書 | 埋めたもの |
| --- | --- |
| 20 §4.1 | Task ID `e8a30d92eb3344989337291c8dc8dde9`、Model ID `36382cf96bb441f38edb8f7ebc4f2971` |
| 20 §4.7 | validation と test の accuracy・precision・recall・f1・混同行列、および実行時の条件 |
| 22 §4.6 | 元の Task と再実行の対応表。差異は全項目で 0 |

train の指標は埋めていない。学習に使った行で測った値は判断に使えないため、
`ml/semiconductor_quality` はそもそも報告していない。上の表の「train」は、
測れるのに測らなかったのではなく、測らないと決めてある欄である。20 §4.7 にその旨を書いた。

2回の実行は混同行列の各マスまで一致した。乱数種が分割と推定器の両方へ渡り、
学習に外部の状態が入らないためである。

作業ツリーは両方の実行で `dirty` である。同じ日に文書と検査スクリプトを変更しながら
実行したためで、22 §4.7 の1行目に当たる。記録したコミットからは、この2回が走ったコードを
取り出せない。この制約は 20 §4.7 と 22 §4.6 の両方に書いてある。
