# BL-12: 文書と実装の乖離を検出する手段が無い

| 項目 | 内容 |
| --- | --- |
| 種別 | 実装 |
| 状態 | 一部着手（2026-09-13） |
| 起票日 | 2026-09-12 |

## 何が起きているか

`docs/**` はどの検査の対象でもない。`test-pyramid.json`・`eslint-baseline`・
`web-boundaries`・`ci:parity` のいずれも Markdown を見ない。

そのため、実装を変えて文書を直し忘れても、すべてのゲートが緑のままになる。
文書の正しさは、受け入れ時の人の判断だけが支えている（32 §4.9）。

この体系整備でも同じ性質が現れている。`docs/_archive/` への移設に伴って
13ファイルのパス参照を書き換えたが、どの検査もその食い違いを指摘しなかった。

## 解決とみなす状態

次のうち少なくとも1つが自動で検出されること。

| 検出したいもの | 検出の仕方（案） |
| --- | --- |
| 存在しないファイルへのリンク | `docs/**/*.md` のリンク先を実在確認する |
| 実装が指す文書のパスが実在しないこと | コード内の `docs/...` 文字列を実在確認する |
| 参照している設定値が実際の値と違うこと | 案なし。値の対応表が必要になる |

3つ目は難しい。文書が書き写している数値（しきい値・上限・ポート）を、
出所の設定ファイルと突き合わせる仕組みが要る。

## 着手の条件

文書の本数が増えたとき。現在11本だが、計画上は48本になる。
リンクの数が人手で追える量を超えた時点で、1つ目だけでも入れる価値が出る。

この条件は満たされた。`docs/**` の Markdown は89本（うち `_archive/` が22本）である。

## 2026-09-13 に入れたもの

上の表の1つ目だけを実装した。

* `scripts/docs-links.mjs`。`docs/**/*.md` の相対リンクを読み、先が実在しなければ失敗する
* `pnpm docs:links` として `verify` の先頭に置いた。CI では `docs` ジョブが呼ぶ
* `scripts/tests/docs-links.test.mjs`。取り出しの範囲を両側から固定する9件
* `_archive/` を対象に含めた。理由は 64 §4.11 にある
* 71 の R-19 の検知方法を、この検査の名前に書き換えた

着手時点の89本に対して、確かめている相対リンクは71本である。
外部 URL と、同一文書内の `#見出し` への11本は対象にしていない。

## なお残るもの

上の表の2つ目と3つ目は入れていない。

2つ目（コード内の `docs/...` 文字列の実在確認）は、1つ目が実際に何かを止めてから判断する。
3つ目（書き写した数値と設定ファイルの突き合わせ）は、値の対応表を作る案が無い。

リンクが繋がっていることは、書いてある内容が正しいことを意味しない。
20 §17 の「文書と実装に重大な矛盾がない」は、この検査だけでは満たされない。
