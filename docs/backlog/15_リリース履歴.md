## 何が起きているか

`x-plan-改訂/20_ドキュメント作成プラン.md` §11 は `77_リリース履歴.md` を挙げている。
しかしリリースの実績が1件も無い。git のタグは0件であり、モデルを production へ昇格した記録も、
推論サービスと画面を配備した記録も無い。

いま作れるのは記入欄の様式だけである。様式の中身（何を確認して出すか、どの単位で出すか）は
33（リリース判定基準）が既に持っており、様式だけを別の文書へ写すと二重管理になる。

履歴は、出来事が起きたときに1行ずつ増える台帳である。出来事が0件の台帳は、
読む人に対して「出していない」以上のことを伝えない。その事実は 33 §3 に既に書いてある。

## 解決とみなす状態

最初のリリース（33 が定める R1・R2・R3 のいずれか）を実施した時点で、
`docs/phase8_プロジェクト管理/77_リリース履歴.md` に次を持つ1行があること。

* 日付、種別（R1 / R2 / R3）、対象の版（モデルの版とタグ、またはイメージのタグ）
* 33 の確認項目のうち、実際に実行したものと、実行しなかったもの
* 併せて動いた Dataset の版と Task ID（R1 の場合）
* 既知の未解決課題（72 のうち、その時点で残っていたもの）

## 着手の条件

最初のリリースを行うとき。R1 は学習を1回通す必要があり、BL-10（実測欄）と同じ実機作業に乗る。
