# BL-16: 退行（regression）の判定基準が定まらない

| 項目 | 内容 |
| --- | --- |
| 種別 | 実機確認＋文書 |
| 状態 | 完了（2026-09-13） |
| 起票日 | 2026-09-12 |

## 何が起きているか

23（モデル評価基準）§4.7 は退行の判定を扱うが、比較対象と許容する低下幅の両方が未定である。
`x-plan-改訂/20_ドキュメント作成プラン.md` §6.4 の「Regression 判定基準」が未チェックのまま残っているのはこのためである。

決められない理由は、比較する相手が無いことにある。学習を1回も実行しておらず、
production のモデルも、過去の評価値の系列も存在しない。
現在 23 が持つ基準値（0.55 / 0.65）は不良率から計算した値であり、実測ではない。

許容幅を先に決めることはできる。ただし、測定のばらつきがどれだけあるかを知らずに幅を決めると、
ばらつきを退行と呼ぶか、退行をばらつきと呼ぶかのどちらかになる。

## 解決とみなす状態

23 §4.7 に次が書いてあること。

* 比較対象（直前の production か、固定した baseline か）
* 許容する低下幅と、その根拠になった測定のばらつき
* 退行と判定したときの扱い（昇格を止めるか、記録して進めるか）

## 着手の条件

同じ条件での学習を複数回実行し、指標のばらつきを測れること。
BL-10（実測欄）で1回通した後、同じ条件で数回繰り返す必要がある。

## 2026-09-13 に測ったものと、決めたこと

Dataset 2.0.0 で既定の設定の学習を12回実行した。同じ乱数種で2回、種だけを 1〜10 に変えて10回である。

| 測定 | 結果 |
| --- | --- |
| 同じ種の2回 | 混同行列の各マスまで完全一致。振れ幅は 0 |
| 種を変えた10回（validation の recall） | 平均 0.6968、標準偏差 0.0287、幅 0.0948 |
| 種を変えた10回（validation の f1） | 平均 0.7630、標準偏差 0.0249、幅 0.0645 |

この測定を根拠に、23 §4.7 へ次を書いた。

* 比較対象は直前に `production` にあった Model。§4.3 の baseline は下限の確認に留める
* 許容する低下幅は、同じ種で測り直した場合 0.02、記録値と比べる場合は recall 0.06 / f1 0.05（標準偏差の2倍）
* 退行と判定したら昇格を止める。低下幅の中に収まっていても、下がった事実は記録に残す

基準値 0.55 / 0.65 は変えなかった。実測はこれを 0.11 以上上回っているが、下限は
「達成できる値」ではなく「これを下回るモデルを候補にしない」線であり、引き上げると
種の違いによる振れが下限に触れるためである。理由は 23 §4.7 に書いた。

## なお残るもの

相対比較を機械が確かめる実装は無い。`ml/model_lifecycle` は絶対値の下限しか見ないため、
上の判定は昇格を要求する人が行う。23 §6 に未決事項として残した。
