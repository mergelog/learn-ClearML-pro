## 1. 目的

この文書は、この環境が持つデータを区分ごとに並べ、個人情報と機密情報が
どこに在るかを記録する。

該当が無い場合も、無いという判断と、その判断が変わる条件を残す。
「無いから書かない」と「無いことを確かめた」を区別するためである。

## 2. 適用範囲

対象は、Dataset・学習の記録・モデル・監視の数字・各種の資格情報である。
区分の定義は `../_archive/security/001_20260908_threat_model.md` §1 に従い、
ここでは定義し直さず、個々のデータをその区分へ割り当てる。

法令・規制の適用判定は `../phase6_セキュリティガバナンス/58_規制・コンプライアンス適用判定.md` が行う。

## 3. 前提

Dataset は合成データであり、実在の製造工程から採ったものではない
（10 §3）。実行環境は単一マシンで、データを読める者は開発者1名である。

## 4. 定義

### 4.1 個人情報の有無

現 Dataset に個人情報は含まれない。

11ある列は、検体の識別子、装置、工程、測定値、判定結果だけである（10 §4.2）。
作業者・担当者・顧客を指す列は無く、行を人と結び付ける経路も無い。
`equipment_id` は装置を指すもので、その装置を誰が動かしたかは記録していない。

この判断が変わるのは、次のいずれかが列として入ったときである。

| 入りうる列 | 個人情報になる理由 |
| --- | --- |
| 作業者 ID・担当者名 | 人を直接指す |
| 検体と作業記録を結ぶキー | 単体では人を指さないが、作業記録と突き合わせると人が特定できる |
| ロット番号など顧客を特定できる識別子 | 個人情報ではないが、契約上の秘密になりうる |

実データを受け入れるときは、列ごとにこの判定を行い、この表を更新してから流す。

### 4.2 台帳

| データ | 区分 | 個人情報 | 保存場所 | 利用目的 | 読める者 | 外部提供 | 保存時暗号化 | 削除条件 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Dataset の CSV | 内部 | 無し | fileserver（`clearml-files`）、`.generated/semiconductor/datasets/` | 学習と評価 | 開発者 | 無し | 無し | 12 §4.2 |
| Task の記録（Parameter・指標・コンソール出力） | 内部 | 無し | MongoDB、Elasticsearch | 再現と比較 | 開発者 | 無し | 無し | 12 §4.2 |
| モデルの重み | 機密 | 無し | fileserver | 推論 | 開発者、推論サービス | 無し | 無し | 12 §4.3 |
| 監視の時系列 | 内部 | 無し | `prometheus-data` | 障害の検知 | 開発者、Grafana の閲覧者 | 無し | 無し | 7日で自動削除 |
| ClearML の資格情報 | 秘密 | 無し | `clearml.conf`（git 追跡外） | SDK と Agent の接続 | 開発者 | 無し | 無し | 再発行時に置き換え |
| ブラウザへ配る ClearML 資格情報 | 秘密 | 無し | `apps/web/src/credentials.json` と build 生成物（いずれも git 追跡外） | Web アプリの実行時設定 | ブラウザを開ける者 | ブラウザへ配られる | 無し | §4.5 |
| サービスの呼び出しトークン | 秘密 | 無し | `.generated/security/clients.env`（git 追跡外） | 推論 API と ops-exporter の認可 | 開発者、呼び手 | 呼び手へ配る | 無し | 更新時に置き換え |
| トークンの指紋 | 内部 | 無し | 各サービスのメモリ（環境変数から読む） | 照合 | サービス | 無し | — | プロセス終了時 |

### 4.3 機密にあたるもの

区分が機密なのはモデルの重みだけである。学習した内容がそのまま入っており、
配ると学習データの性質が推測されうる。ただし現在の学習データは合成データであり、
推測されて困る実データは含まれていない。

実データで学習した時点で、重みの扱いは「持ち出しを記録する」側へ移る
（`../_archive/security/001_20260908_threat_model.md` §1）。記録の仕組みは無い（§6）。

### 4.4 秘密にあたるもの

秘密は平文で保存しない、が原則である。しかし現状は、いずれも平文のファイルに置いてある。

| 秘密 | 現状 | 補っているもの |
| --- | --- | --- |
| ClearML の資格情報 | `clearml.conf` に平文 | git 追跡外。ホストの外へ出ていない |
| サービスのトークン | `.generated/security/clients.env` に平文 | git 追跡外。サービス側はトークンを保存せず SHA-256 の指紋だけを持つ |

指紋だけを持つ設計により、サービス側の記録や設定が漏れても、そこからトークンは戻らない
（`ml/security/credentials.py`）。漏れうるのは配布元のファイルだけである。

git への混入は、コミット前の検査で見る。`pnpm sec:scan` が追跡対象を、
`pnpm sec:scan:paths` が生成物を、`pnpm sec:scan:clearml` が Task の記録を検査する。
除外は `config/security.yaml` に理由つきで書く。理由の無い除外は読み込みで拒否される。

### 4.5 ブラウザへ配られる資格情報

`apps/web/src/credentials.json` は、持ち込んだ ClearML Web アプリが実行時に読むファイルで、
ビルド生成物にそのまま写る。つまりブラウザへ配るものに資格情報が含まれる。

これは受け入れているリスクであり、成立している条件は「待ち受けがループバックである」ことだけである
（`../_archive/security/001_20260908_threat_model.md` §5）。ホストの外へ公開する場合、
この構造のままでは配れない。

### 4.6 マスキングと匿名化

マスキングも匿名化も実装していない。対象となる個人情報が無いためである。

実データを受け入れる場合、`../_archive/security/001_20260908_threat_model.md` §4 は
検証環境に「匿名化した実データ」を置くとしている。匿名化の方法は決めていない（§6）。

### 4.7 アクセス可能者

| 経路 | 誰が | 何を読めるか |
| --- | --- | --- |
| ClearML Web（:8080） | 同一 LAN のブラウザ | Dataset・Task・Model の全て |
| ClearML API（:8008） | 資格情報を持つ者 | 同上 |
| 推論 API | トークンを持つ呼び手 | 判定結果のみ |
| Grafana（:3000） | ホストの誰でも（匿名 Viewer） | 監視の数字 |

待ち受けアドレスは一様ではない。推論 API と監視はループバックである（`BIND_ADDRESS` の既定値）。
ClearML の3ポート（8008 / 8080 / 8081）は待ち受けアドレスを指定せずに公開しており、同一 LAN から
到達できる。これは意図した例外である（`../_archive/security/001_20260908_threat_model.md` §5、
`../phase6_セキュリティガバナンス/50_セキュリティ設計書.md` §4.4）。

ホストに入れる者と読める者が一致しており、この環境では利用者が1名であるため区別していない。
権限の分離は `../phase6_セキュリティガバナンス/52_権限マトリクス.md` が扱う。

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 個人情報は無いと判断し、その根拠と変わる条件を残す | 無いことの確認と、確認していないことを区別するため |
| サービス側にトークンを保存せず指紋だけを持つ | サービスの設定や記録が漏れても、そこから呼び出しに使える値が戻らないため |
| 秘密の混入検査を、追跡対象・生成物・Task の記録の3経路で行う | 秘密が漏れる経路が git だけではないため。Task の Parameter やログにも同じ値が載る |

## 6. 未決事項

* 実データを受け入れるときの匿名化の方法と、その検証。
* モデルの重みを持ち出したときの記録。仕組みが無い。
* 秘密の保存方法。現在は平文のファイルで、git 追跡外であることだけが担保である。
  secret manager の利用は検証環境からの前提とされている（脅威モデル §4）が、導入していない。
* ブラウザへ配る資格情報の扱い。ホストの外へ公開する前に決める必要がある。
