## 1. 目的

この文書は、本プロジェクトが作るモデルが何のためのもので、どこまで信じてよいかを記す。

評価結果と ClearML の ID は、実際に学習を実行して初めて埋まる。
本文書の作成時点でその実行は行っておらず、該当欄は空のままにしてある。
推定値で埋めることはしない（§4.7）。

## 2. 適用範囲

対象は `semiconductor-quality-classifier` という名前で登録されるモデルである。
名前はコード側のデータ契約が持ち、学習側とモデルライフサイクル側の両方が同じ名前を指す。

`tools/semiconductor_seed` が作る実験用の比較モデル（logistic / tree / forest の各設定）は、
題材の生成物であり、このカードの対象外とする。

## 3. 前提

学習データは合成である（10 §3）。したがって、このモデルの性能は実在の製造工程に対する性能ではない。

## 4. 定義

### 4.1 基本情報

| 項目 | 内容 |
| --- | --- |
| Model 名 | `semiconductor-quality-classifier` |
| Version | 段階（`candidate` / `staging` / `production`）で表す。連番の版は振らない |
| 目的 | 製造工程の測定値から、その製品が不良（`fail`）になるかを判定する |
| 出力 | ラベル（`pass` / `fail`）と確信度 |
| ClearML Project | `Semiconductor Quality Prediction/Training` |
| ClearML Task ID | `e8a30d92eb3344989337291c8dc8dde9`（2026-09-13 の実行） |
| ClearML Model ID | `36382cf96bb441f38edb8f7ebc4f2971` |

### 4.2 想定用途と非推奨用途

想定する用途は、本プロジェクトの学習・評価・昇格・配備・監視の流れを通して確かめることである。
推論サービスを通じて、測定値の並びに対して判定を返す。

次の用途には使えない。

* 実在の製造工程の良否判定。学習データが合成であり、実工程の分布を再現していない。
* 装置の異常検知。`EQ-04` で不良が出やすいという関係は生成器が入れたものであり、実機の性質ではない。
* 人に関わる判断。この Dataset は人間の属性を含まないが、含まないことと、含むデータへ転用してよいことは別である。

### 4.3 アルゴリズムと学習条件

既定は RandomForest である。採用理由は ADR 001 が持つ。
`logistic-regression` と `hist-gradient-boosting` も選べるが、既定は変えていない。

| 項目 | 既定値 | 出所 |
| --- | --- | --- |
| アルゴリズム | `random-forest` | `ml/semiconductor_quality/config.py` |
| `n_estimators` | 300 | 同上 |
| `max_depth` | 無制限 | 同上 |
| `min_samples_leaf` | 4 | 同上 |
| `class_weight` | 重み付けなし | 同上 |
| `decision_threshold` | 指定なし（0.5） | 同上 |
| 乱数の種 | 20260906 | 同上 |
| 分割比率 | train 0.6 / validation 0.2 / test 0.2 | 同上 |
| 分割の方法 | 目的変数で層化し、ラベルごとに行を割り当てる | `ml/semiconductor_quality/preprocess.py` |

`decision_threshold` は探索の対象に含めない。閾値はそれが切るモデルの隣でしか意味を持たないためである。
探索が閾値を動かすのは、各候補を判定するときの内側の分割に限られる。

### 4.4 学習 Dataset

| 項目 | 内容 |
| --- | --- |
| Dataset | `semiconductor-quality-data` |
| 版 | 実行時に指定する。既定は無く、指定しないと実行できない |
| 特徴量 | 数値7列（`temperature`, `pressure`, `process_time`, `gas_flow`, `sensor_1`, `sensor_2`, `inspection_value`）とカテゴリ2列（`equipment_id`, `process_step`） |
| ラベル | `result`（`pass` / `fail`）。正例は `fail` |
| 前処理 | 数値列とカテゴリ列を列ごとに変換する。数値列を先に並べ、学習済みパイプラインが同じ列番号で同じ特徴量を指し続けるようにする |

列の意味と値域は 10 が持つ。

### 4.5 評価指標

| 指標 | 何のために見るか |
| --- | --- |
| recall | 実際の不良のうち、どれだけを不良と判定できたか。見逃しの少なさ |
| precision | 不良と判定したもののうち、実際に不良だった割合。過検出の少なさ |
| f1 | 上の2つの釣り合い。recall だけを上げて何でも不良と言うモデルを通さないために併せて見る |
| accuracy | 参考。基準には使わない |
| 混同行列 | 4つの区分の件数。ラベルの順序はデータ契約に従う |

accuracy を基準にしないのは、不良が一部しかないデータでは「全部良品」と答えるモデルが
高い accuracy を得るためである。

指標を測るのは validation と test の2つである。validation は設定を確かめるため、test は最終評価のために
一度だけ使う。選定に test を使うと、独立した評価が残らなくなる。
train に対する指標は報告しない（`ml/semiconductor_quality/domain.py` の `TrainingEvaluation`）。

### 4.6 採用基準

候補モデルとして登録してよい最低条件は、validation に対して次を満たすことである。

| 指標 | 最低値 |
| --- | --- |
| recall | 0.55 |
| f1 | 0.65 |

基準は `config/model_gate.yaml` にある。編集すれば次の Pipeline 実行から適用され、
コードの変更も配備も要らない。基準を変えたときは、なぜ変えたかをコミットメッセージに残す。

この基準値自体の根拠は、学習環境として置いた値であり、利用側と合意したものではない。

### 4.7 評価結果

2026-09-13 に `pnpm ml:train -- --dataset-version 2.0.0` を実行した結果である。
Task `e8a30d92eb3344989337291c8dc8dde9` の値をそのまま写した。

| 分割 | accuracy | precision | recall | f1 | 混同行列 |
| --- | --- | --- | --- | --- | --- |
| validation | 0.8280 | 0.8421 | 0.6737 | 0.7485 | pass: 286 / 24、fail: 62 / 128 |
| test | 0.8240 | 0.8148 | 0.6947 | 0.7500 | pass: 280 / 30、fail: 58 / 132 |

混同行列は「実際のラベル: 予測が pass / 予測が fail」の順である。
`fail` を正例として precision・recall・f1 を計算している。

train の指標は測っていない。学習に使った行で測った値は、
その設定を採るかどうかの判断に使えないためである。

実行時の条件は次のとおりである。

| 項目 | 値 |
| --- | --- |
| Dataset | `semiconductor-quality-data` 2.0.0（`57407833e0904c5c8af31f18d3a79152`）、2500行、pass 1550 / fail 950 |
| 分割 | train 1500 / validation 500 / test 500（0.6 / 0.2 / 0.2） |
| 推定器 | random-forest、`n_estimators=300`、`min_samples_leaf=4`、深さ無制限、`class_weight=none` |
| 乱数種 | 20260906 |
| 実行場所 | 手元のプロセス（Queue へ投げていない）。Python 3.10.12 |
| Git | `b5a6e748492a9059790d6c960204d44948e8aa58`、作業ツリーは `dirty` |

作業ツリーが `dirty` であることは、この実行を厳密には再現できないことを意味する（22 §4.7）。
同じ日に文書と検査スクリプトを変更しながら実行したためである。

上の値は §4.6 の採用基準（validation の recall 0.55、f1 0.65）を満たす。
ただし基準との差は、種を変えたときの振れ幅より大きい。振れ幅は 23 §4.7 にある。

### 4.8 制約と既知の弱点

| 事項 | 内容 |
| --- | --- |
| データが合成である | 実工程の分布を再現していない。性能の数値は題材の中でしか意味を持たない |
| 特徴量に従属がある | `sensor_1` は温度から、`sensor_2` は圧力から導かれている。重要度をそのまま独立な寄与として読めない |
| 未知の装置を扱えない | 宣言していない `equipment_id` が含まれる Dataset は、学習の前に拒否される |
| ラベルの偏りに弱い | どちらかのラベルが 5% を下回る Dataset は拒否される。それを上回る範囲の偏りには、重み付けを既定で適用していない |
| 閾値が固定である | 既定の学習は 0.5 で切る。閾値を動かすのは探索のときだけで、その値は勝った設定と一緒に引き渡される |
| 版をまたいだ比較 | 1.0.0 と 2.0.0 は雑音の大きさが違う。異なる版で測った指標を直接比べられない |

### 4.9 利用上のリスク

| リスク | いまの手当て |
| --- | --- |
| 基準を満たさないモデルが配備される | 評価ゲートが validation の recall と f1 で止める |
| どのモデルが動いているか分からなくなる | 推論の応答が必ずモデルを名乗る。段階は tag と metadata の両方に書く |
| 段階を飛ばして昇格する | 宣言された遷移だけを許す |
| 学習時と違う分布のデータで使い続ける | 予測ラベルの分布を監視し、30分継続で `PredictionDistributionShifted` を上げる。Dataset 側は `ml:data drift` で比較する |
| 再現できない | 来歴（コミット・イメージ・実行者・環境）を Task に記録する。詳細は 22 |

これらのうち、実機で確かめたのは runbook に記録のある範囲に限られる。
