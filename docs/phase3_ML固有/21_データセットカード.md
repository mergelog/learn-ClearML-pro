## 1. 目的

この文書は、Dataset `semiconductor-quality-data` がどこから来て、どう作られ、何に使ってよいかを記す。

列の意味・型・値域は 10（データディクショナリ）が持ち、段階ごとの扱いは 11（データライフサイクル）が持つ。
このカードは、その2つが答えない問い、すなわち「このデータは何のために存在し、どこまで一般化できるか」に答える。

## 2. 適用範囲

対象は ClearML Project `Semiconductor Quality Prediction` に登録される Dataset
`semiconductor-quality-data` の版 1.0.0 と 2.0.0 である。

`tools/semiconductor_seed` が同時に作る実験用の Task 群と、そこで比較されるモデルは対象外とする。

## 3. 前提

このデータは合成である。実在の製造ラインから取得した測定値ではない。
したがって、このデータで測った性能は、実工程に対する性能を意味しない。

## 4. 定義

### 4.1 目的

半導体の製造工程で測った値から、その製品が不良（`fail`）になるかを判定するモデルを学習させるためのデータである。

実データを使わない理由は2つある。実データは入手できない。そして、このプロジェクトの主題は
Dataset の版管理・来歴・品質判定・再現性であり、それらは合成データでも同じ形で確かめられる。

### 4.2 取得元と作成方法

取得元は生成器 `tools/semiconductor_seed/generator.py` だけである。外部から受け取ったデータは無い。

生成は乱数の種から決まる。同じ種と同じ版定義を与えれば、同じ CSV が再び得られる。
種は `--random-seed` で与え、版ごとに固定の値（`random_seed_offset`）を足して使う。
2つの版が同じ種から別々の行を得るのは、この足し込みによる。

生成の流れは次のとおりである。

1. 装置 ID と工程を、それぞれ4種と3種から一様に選ぶ。
2. 温度・圧力・処理時間・ガス流量・検査値を、列ごとに定めた正規分布から引く。
3. センサ2列を、温度と圧力からそれぞれ線形に導き、雑音を足す。
4. 5つの危険度（温度の逸脱、圧力と時間の交互作用、`EQ-04` であること、センサ1の逸脱、検査値の超過）を足し、雑音を加える。
5. 危険度が上位38%に入る行を `fail`、残りを `pass` とする。

各分布の母数は 10 §4.4 にある。

### 4.3 ラベルの定義

ラベルは `result` の1列で、`pass` と `fail` の2値である。正例は `fail` とする。

`fail` は「危険度が上位38%に入ったこと」を意味する。実際の検査で不良と判定されたことではない。
危険度の閾値は生成時に分位点で決めるので、不良の割合は版によらずおよそ38%になる。

### 4.4 特徴量

9列を特徴量として使う。数値7列（`temperature`, `pressure`, `process_time`, `gas_flow`,
`sensor_1`, `sensor_2`, `inspection_value`）とカテゴリ2列（`equipment_id`, `process_step`）である。

`sample_id` は識別子であり、特徴量に含めない。

数値列は標準化し、カテゴリ列は one-hot に展開する。数値列を先に並べるのは、学習済みパイプラインが
同じ列番号で同じ特徴量を指し続けるようにするためである（`ml/semiconductor_quality/preprocess.py`）。

### 4.5 版

| 版 | 行数 | 種の増分 | 雑音の標準偏差 | 親 |
| --- | --- | --- | --- | --- |
| 1.0.0 | 1,200 | 0 | 0.72 | 無し |
| 2.0.0 | 2,500 | 1,000 | 0.62 | 1.0.0 |

2.0.0 は 1.0.0 を親として登録する。ClearML の Dataset は親子で連なり、版の並びが後から辿れる。

版の違いは、行数と危険度に足す雑音の大きさである。2.0.0 のほうが雑音が小さく、
危険度とラベルの対応がはっきりしている。同じ設定のモデルでも 2.0.0 のほうが高い指標を出しやすい。
異なる版で測った指標を直接比べられないのは、このためである。

### 4.6 train / validation / test の分割

分割は学習の実行時に行い、Dataset には保存しない。既定は train 0.6 / validation 0.2 / test 0.2 である
（`ml/semiconductor_quality/config.py`）。比率は実行時に変えられるが、合計が 1.0 でなければ拒否される。

分割は `result` で層化する。ラベルごとに行を割り当てるので、3つの部分の不良率はもとの Dataset とほぼ等しい。
層化しないと、不良が一部しかないデータでは validation に不良がほとんど入らない引きが起こりうる。

3つの部分の役割は重ならない。

| 部分 | 使う場面 | 使わない場面 |
| --- | --- | --- |
| train | モデルの当てはめ。探索も、この部分をさらに5分割して使う | 指標の報告 |
| validation | 設定の確認と、候補モデルとして登録してよいかの判定（評価ゲート） | 探索の採点 |
| test | 選び終えたモデルの最終評価。1回だけ予測する | 設定の選定 |

探索が train の内側だけを見る理由は ADR 004 が持つ。

### 4.7 更新履歴

| 版 | 生成日 | 変更 |
| --- | --- | --- |
| 1.0.0 | 未記録 | 初版 |
| 2.0.0 | 未記録 | 行数を 2,500 に増やし、雑音を 0.62 に下げた |

生成日を記録していないのは、版定義がコードにあり、いつ実行しても同じ内容が得られるためである。
ClearML へ登録した日時は Dataset 側に残る。実際の登録日は、登録を実行して初めて確定する。

### 4.8 品質上の制約

| 事項 | 内容 |
| --- | --- |
| 合成である | 実工程の分布を再現していない。列の相関も、装置と不良の関係も、生成器が入れたものである |
| 特徴量に従属がある | `sensor_1` は温度から、`sensor_2` は圧力から導かれている。独立した測定値ではない |
| 時間の軸が無い | 行に時刻を持たない。工程の順序、装置の経時変化、季節性は表現できない |
| 装置が4種に固定されている | 宣言していない `equipment_id` を含む Dataset は、品質判定が拒否する |
| 欠損が無い | 欠損値を含む行を生成しない。欠損の扱いを学習側で確かめる材料にはならない |
| 不良率が高い | およそ38%が `fail` である。実工程の不良率はこれよりはるかに低いのが普通で、不均衡データでの挙動を確かめる材料にはならない |

品質判定の合否条件は 14 が持つ。上の表は、条件を満たしていてもなお残る制約である。

### 4.9 利用制限

| 用途 | 可否 |
| --- | --- |
| 本プロジェクトの学習・評価・昇格・監視の確認 | 可 |
| 実在の製造工程の良否判定モデルの学習 | 不可。分布が実工程と対応していない |
| 装置の性能比較 | 不可。`EQ-04` の不良率は生成器が与えた値である |
| 外部への提供 | 制限しない。個人情報も機密情報も含まない（13） |

このデータには人間の属性を含まない。ただし、含まないことと、人間の属性を含むデータへ
同じ手順を転用してよいことは別である。

## 5. 判断事項

| 判断 | 記録 |
| --- | --- |
| 合成データを使う | 実データを入手できず、主題が Dataset 管理と再現性であるため |
| 版を親子で連ねる | 版の並びを後から辿れるようにするため（`tools/semiconductor_seed/dataset_seeding.py`） |
| 分割を Dataset に保存せず実行時に行う | 比率を実行ごとに変えられるようにし、Dataset を分割の形から独立させるため |
| 分割を `result` で層化する | 層化しないと validation に不良がほとんど入らない引きが起こりうるため |
| 探索を train の内側だけで行う | `../_archive/adr/004_20260909_experiment_settings_and_search.md` |

## 6. 未決事項

* 版 1.0.0 と 2.0.0 の生成日・ClearML Dataset ID。登録を実行して初めて確定する。
* 3つ目の版を作る条件。いまは決めていない。
* 実データを受け入れる場合の収集方法・同意・提供元との取り決め。
* 不均衡データを扱う版の要否。現在の不良率38%では、不均衡への手当てを確かめられない。
