## 1. 目的

この文書は、一度行った学習を後から同じ条件で再実行するために何が要るかを示し、
それぞれがどこに記録されるかを対応づける。

再実行を実際に行った結果は §4.6 に書く。この文書の作成時点では実施しておらず、空欄である。

## 2. 適用範囲

対象は `ml/semiconductor_quality`（単発の学習）と `ml/pipeline`（Pipeline としての学習）である。
ハイパーパラメータ探索（`ml/experiment`）は、勝った設定を学習として引き渡した後は同じ扱いになる。

推論サービスの応答の再現は対象外とする。応答はモデルと入力から決まり、
どのモデルが答えたかは応答自身が名乗る。

## 3. 前提

再実行が同じ結果を返すのは、次の3つが同じときに限る。同じ Dataset 版、同じ設定と種、同じ依存関係。
このうち依存関係だけは、記録があっても自動では復元されない（§4.5）。

## 4. 定義

### 4.1 再現に要る情報と、その記録先

学習 Task には、実行を再現するための情報が2種類記録される。
何を測ったかを示す Parameter・指標と、どこから来たかを示す来歴である。

| 情報 | 記録される名前 | 記録する場所 |
| --- | --- | --- |
| Dataset の Project / 名前 / 版 | 実行契約の Parameter | `ml/semiconductor_quality/config.py` が組み立て、`clearml_tracking` が書く |
| Dataset の CSV パス・別名 | 同上 | 同上 |
| 分割比率（train / validation / test） | 同上 | 同上 |
| アルゴリズムと推定器の設定 | 同上 | 同上 |
| 乱数の種 | 同上 | 同上 |
| Git コミット | `git_commit` | `ml/semiconductor_quality/provenance.py` |
| Git ブランチ | `git_branch` | 同上 |
| Git リモート | `git_remote` | 同上 |
| 作業ツリーの状態 | `git_working_tree`（`clean` / `dirty`） | 同上 |
| 実行イメージ | `image_reference` | 同上（環境変数 `SEMICONDUCTOR_TRAINING_IMAGE`） |
| イメージの digest | `image_digest` | 同上（`SEMICONDUCTOR_TRAINING_IMAGE_DIGEST`） |
| Python の版 | `python_version` | 同上 |
| ホスト名 | `hostname` | 同上 |
| 実行を依頼した者 | `executed_by` | 同上 |
| 実行された Queue | `queue`（その場の実行は `local`） | 同上 |
| ClearML Task ID | Task 自身 | ClearML |
| Model ID・Artifact | Output Model、Artifact | ClearML |

作業ツリーの状態をコミットの隣に書くのは、汚れた作業ツリーではコミットだけでは
何を実行したか特定できないためである。

値が取れなかったときは、空文字ではなく `unknown` と記録する。
空文字だと「記録し忘れ」と見分けが付かない。来歴の欠落で実行を止めることはしない。
不完全な来歴でも、実行を拒否するよりは残したほうがよいという判断である。

### 4.2 コンテナが自分のイメージを名乗る理由

コンテナは、自分がどのイメージから起動したかを内側から読めない。
そのため Compose 側から環境変数として渡している。

digest はレジストリへ push して初めて決まるので、ローカルビルドでは
`docker image inspect --format '{{.Id}}'` の値を `.env` に入れる。
入れない場合は `unknown` が記録される。

### 4.3 Dataset の特定

Dataset は名前と版で指定する。ClearML が版ごとに内容を固定するため、
同じ版を指定すれば同じ行が得られる。

版を指定せずに実行することはできない。既定の版を持たせていないのは、
「最新」を指したつもりの実行が、後から別の内容を指すようになるのを避けるためである。

### 4.4 乱数の種

種は1つで、分割と推定器の両方に渡る（既定 20260906）。
分割は目的変数で層化し、ラベルごとに行を割り当てるため、同じ Dataset 版と同じ種であれば
常に同じ3つの部分になる。

### 4.5 依存関係

依存は `requirements/*.in` から `piptools` で固定し、`requirements/*.txt` として残す。

| 用途 | 固定ファイル |
| --- | --- |
| 学習 | `requirements/training.txt` |
| 推論 | `requirements/serving.txt` |
| 探索 | `requirements/optimization.txt` |
| 開発・検査 | `requirements/dev.txt` |

Python は 3.10 系である（`.python-version` は 3.10.12、`pyproject.toml` は 3.10 を指定）。

固定ファイルは git が版を持つので、コミットが分かれば当時の依存も分かる。
ただし、その復元は自動では行われない。過去の実行を再現するには、
そのコミットを取り出して `pnpm py:setup` をやり直す必要がある。

Agent 上で実行した場合は、Agent のイメージが依存を持つ。この場合の再現は
イメージの digest で特定する。

### 4.6 再実行の手順

以下は、記録から再実行を組み立てる手順である。2026-09-13 に1回実施した。結果は表の下にある。

1. Task を開き、§4.1 の Parameter と来歴を控える。
2. `git_commit` のコミットを取り出す。`git_working_tree` が `dirty` であれば、
   その時点の作業ツリーは復元できない。この場合、完全な再現は成立しない。
3. `pnpm py:setup` で、そのコミットの `requirements/*.txt` から環境を作る。
   Agent 上の実行を再現する場合は、`image_digest` のイメージを使う。
4. 控えた Dataset の版・分割比率・推定器の設定・種を引数として学習を実行する。
   実行方法と引数は `../_archive/runbooks/002_20260908_training_pipeline.md` にある。
5. 新しい Task の指標を、元の Task の指標と突き合わせる。

| 項目 | 元の実行 | 再実行 | 差異 |
| --- | --- | --- | --- |
| Task ID | `e8a30d92eb3344989337291c8dc8dde9` | `d137875ca8c44e348dfc0056d13cb2dd` | 別の Task |
| Dataset 版 | 2.0.0（`57407833e0904c5c8af31f18d3a79152`） | 同じ | 無し |
| Git コミット | `b5a6e748`（`dirty`） | `b5a6e748`（`dirty`） | 無し |
| 乱数種 | 20260906 | 20260906 | 無し |
| validation の recall | 0.6737 | 0.6737 | 0.0000 |
| validation の f1 | 0.7485 | 0.7485 | 0.0000 |
| test の f1 | 0.7500 | 0.7500 | 0.0000 |

2回の実行は、混同行列の各マスまで一致した（validation は pass 286 / 24、fail 62 / 128）。
指標だけでなく、どの行をどちらへ分類したかまで同じである。

一致したのは、乱数種が分割と推定器の両方へ渡っており、学習に外部の状態が入らないためである。
同じ種で実行する限り、この一致は設定の再現性を示すが、環境の再現性までは示さない。
2回とも同じ作業ツリー・同じ依存・同じ Python で実行しており、§4.5 が挙げる復元の手順は踏んでいない。

作業ツリーは両方とも `dirty` である。同じ日に文書と検査スクリプトを変更しながら実行したためで、
§4.7 の1行目に当たる。記録されたコミットからは、この2回が走ったコードを取り出せない。
違いが出なかったことは、この制約を打ち消さない。

種を変えれば結果は動く。10回の振れ幅は 23 §4.7 にある。

### 4.7 再現が成立しない条件

次のいずれかに当たる場合、同じ結果は得られない。

| 条件 | なぜ成立しないか |
| --- | --- |
| `git_working_tree` が `dirty` | 記録されたコミットは、実行されたコードと一致しない |
| Dataset の版を指定せずに実行した | 実行できないため、この条件は起こらない |
| 依存を作り直さずに現在の環境で実行した | scikit-learn の版が変われば、同じ設定でも結果が動きうる |
| 来歴が `unknown` を含む | 特定できない項目の分だけ、再現の範囲が狭くなる |
| 異なる Dataset 版で比べた | 1.0.0 と 2.0.0 は雑音の大きさが違う（10 §4.1） |

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 来歴の欠落で実行を止めない | 不完全な来歴でも、実行を拒否するより残したほうが後から役に立つ |
| 欠落を `unknown` と書く | 空文字では記録し忘れと区別できない |
| イメージ情報を環境変数で外から渡す | コンテナは自分の出自を内側から読めない |
| 依存を lock ファイルとして git に置く | コミットが決まれば当時の依存も決まる |

## 6. 未決事項
