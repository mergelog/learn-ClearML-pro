## 1. 目的

この文書は、本プロジェクトのモデルに公平性評価が要るかを判断し、その判断と根拠を残す。

結論は「人間の属性に対する公平性評価は対象外」である。以下はその根拠と、
対象外としたあとも残る偏りの扱いである。判断が変わる条件も併せて定める（§4.5）。

## 2. 適用範囲

対象は `semiconductor-quality-classifier` と、その学習に使う Dataset `semiconductor-quality-data` である。

## 3. 前提

このモデルは製品を判定する。人を判定しない。
Dataset は合成であり、生成器が作る列だけを持つ（21 §4.2）。

## 4. 定義

### 4.1 人間属性に対する公平性評価を行わない理由

公平性評価は、保護対象となる属性の間で判定の質が偏っていないかを測るものである。
本プロジェクトにはその属性が無い。

Dataset の11列は、識別子1列、装置と工程の2列、測定値7列、判定結果1列である（10 §4.2）。
このうち人に対応する列は無い。作業者 ID も、班や勤務帯を示す列も持たない。

判定の対象は製品であり、判定の結果として不利益を受ける人がいない。
したがって、人間属性に対する公平性指標（属性ごとの真陽性率の差、均等オッズ、人口統計的パリティなど）は設定しない。

この判断は、指標を設定しないことの記録であって、偏りが無いことの証明ではない。
§4.2 で扱うとおり、人に関わらない偏りは存在する。

### 4.2 対象外としたあとも残る偏り

人間属性に関わらなくても、群ごとに判定の質が違うことはある。

| 群 | 偏りの内容 |
| --- | --- |
| `equipment_id` | `EQ-04` は不良が出やすいように生成されている。危険度に固定値 0.9 が加わる |
| `process_step` | 3種を一様に選ぶだけで、工程ごとの危険度の差は与えていない |
| 版 | 2.0.0 は雑音が小さく、危険度とラベルの対応がはっきりしている |

`EQ-04` の偏りは生成器が入れたものであり、実機の性質ではない。
装置ごとの不良率の差をそのまま装置の性能の差として読むことはできない（21 §4.9）。

装置ごとに recall や precision が違いうるかどうかは測っていない。
評価は Dataset 全体でしか行っておらず、群ごとに分けた指標を出す実装が無い。

### 4.3 データの作られ方に由来する偏り

学習データそのものの偏りは、公平性とは別の問題として 21 §4.8 と 24 が扱う。
ここでは、公平性の観点から見て特に関係する2点だけを挙げる。

装置は4種から一様に選ばれる。実工程では装置ごとの処理量が違うのが普通で、
少数の装置の行が少なければ、その装置での判定の質は測りにくくなる。この Dataset ではその状況が起きない。

宣言していない装置が混ざった Dataset は、品質判定が1件でも拒否する（14）。
つまり、一度も見たことのない装置で判定する事態は、Dataset の側で止まる。
逆に言えば、装置を増設したときは宣言を先に行わないと学習が進まない。

### 4.4 いま行っている確認

群ごとの公平性指標は測っていない。関連して行っているのは次の2つである。

| 確認 | 内容 |
| --- | --- |
| 未知カテゴリの拒否 | 宣言していない装置・工程を含む Dataset を学習前に止める（14） |
| カテゴリ分布の比較 | 版の間でカテゴリの分布がどれだけ動いたかを測る。閾値は 0.2（`ml/data_quality/drift.py`） |

どちらも入力側の確認であり、判定の質が群ごとに違うかは見ていない。

### 4.5 判断を見直す条件

次のいずれかが起きたら、この文書の結論を見直す。

| 条件 | 見直す内容 |
| --- | --- |
| 人に対応する列（作業者、班、勤務帯など）を Dataset に加える | 人間属性に対する公平性評価の要否を改めて判断する |
| 判定の結果が人の評価や処遇に使われる | 同上。用途が変われば、人の列が無くても間接的な代理変数が問題になる |
| 装置ごとの判定の質を運用上の根拠に使う | 装置ごとに recall と precision を測る実装を加える |
| 実データへ移行する | 装置ごとの行数の偏りが生じるため、少数の装置での判定の質を測る必要が出る |
| 規制の適用対象になる | `../phase6_セキュリティガバナンス/58_規制・コンプライアンス適用判定.md` §4.7 の見直し条件と結論に従う |

見直しの契機を条件として書くのは、「対象外」という判断が一度下されたまま残り続けるのを避けるためである。

## 5. 判断事項

| 判断 | 根拠 |
| --- | --- |
| 人間属性に対する公平性評価を対象外とする | Dataset に人に対応する列が無く、判定の対象が製品であるため（§4.1） |
| 公平性指標を設定しない | 測る対象となる保護属性が無いため。指標だけを置いても意味を持たない |
| 装置ごとの指標を現時点で測らない | 装置と不良の関係が生成器の与えたものであり、測っても実機の性質を表さないため |
| 見直しの条件を明記する | 判断を固定せず、前提が変わったときに再判断できるようにするため（§4.5） |

## 6. 未決事項

* 装置ごとの recall・precision を測る実装。§4.5 の条件に当たったときに必要になる。
* 実データにおける装置ごとの行数の偏りと、その扱い。
* 実データへ移行し、判定の対象が人に関わるものへ変わった場合の再判断。規制の適用可否そのものは `../phase6_セキュリティガバナンス/58_規制・コンプライアンス適用判定.md` が判定し、現時点ではいずれも適用されないとしている。
