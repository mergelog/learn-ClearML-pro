## 1. 目的

この文書は、個々のテストケースについて、前提・入力・操作・期待結果と、実行した結果を記録する。
どの層で何を確かめるかは 30 が持ち、何をもって合格とするかは 32 が持つ。

## 2. 適用範囲

書き下す対象を、32 が合否条件として名前を挙げている判断に限る。
具体的には Dataset の品質判定、評価ゲート、段階の遷移、認可、供給網ゲート、秘密検査、
および E2E である。

全1590ケースを1件ずつ表に写すことはしない。写した表は実装から切り離されるため、
更新されないまま実装だけが変わる（禁止事項の「コードを大量に設計書へコピーする」に当たる）。
書き下していない層の読み方を §4.10 に置く。

## 3. 前提

ケース名は英文の平叙文で書かれている。テスト関数名がそのままケースの主張であり、
この文書の「期待結果」列は関数名を日本語へ移したものである。

実行結果は 2026-09-12 に手元（WSL2・Python 3.10.x の `.venv`・Node 24 系）で取得した。
CI での結果は GitHub Actions の実行履歴にあり、この文書には写さない。

## 4. 定義

### 4.1 Test ID の付け方

`TC-<領域>-<連番>` とする。領域は次の7つである。

| 領域 | 意味 | 実装の場所 |
| --- | --- | --- |
| DQ | Dataset の品質判定 | `ml/tests/data_quality/test_checks.py` |
| GATE | 評価ゲート | `ml/tests/model_lifecycle/test_gate.py` |
| STG | 段階の遷移と昇格の要求 | `ml/tests/model_lifecycle/test_domain.py` |
| AUTH | 認可と断り方 | `services/tests/security/test_authorization.py` |
| SC | 供給網ゲート | `tools/tests/test_supply_chain.py` |
| SEC | 秘密検査 | `ml/tests/security/test_secrets.py` |
| E2E | 画面の通し確認 | `apps/web/e2e/*.spec.ts` |

ID はこの文書だけで使う。テスト側にはID を書かない。両方に書くと、
片方だけを直したときに対応が崩れる。

### 4.9 書き下していない層の読み方

上の7領域以外のケースは、この文書に表を持たない。読むときは次の順で辿る。

まず `test-pyramid.json` で層と置き場所を確認する。次にその場所のテスト関数名を読む。
関数名は「何がどうなるか」を述べた平叙文で書かれているため、
一覧を出せばそのままケース一覧になる。

```bash
# 例: 学習・評価の単体層のケース一覧
grep -rn "def test_" ml/tests | sed 's/.*def test_//;s/(self.*//'
```

この方法で読めることを前提にしているため、テスト関数名は実装の言い換えではなく、
確かめている判断を述べた文にする（62 レビュー基準、未着手）。
