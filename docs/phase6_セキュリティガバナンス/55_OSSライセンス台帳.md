## 1. 目的

この文書は、このリポジトリが使っている OSS のライセンスと、そこから生じる義務を記録する。

台帳であり、依存が変わったときに更新する。ただし現時点で全件を列挙できておらず、この文書が
いま果たしている役割は、確認できた範囲の記録と、全件を列挙する手段が無いことの記録である
（§4.2）。

## 2. 適用範囲

対象は3種類あり、確認の難しさが異なる。

| 対象 | 件数 | 状態 |
| --- | --- | --- |
| 取り込んだ ClearML Web（fork） | 1 | 確認済み（§4.3） |
| Python の依存（lock が決めているもの） | 未集計 | 未確認（§4.2） |
| Node の依存（`pnpm-lock.yaml` が決めているもの） | 未集計 | 未確認（§4.2） |
| Angular アプリに同梱されている第三者ライブラリ | 未集計 | 未確認（§4.4） |

対象外は、コンテナのベースイメージに含まれる OS パッケージのライセンスである。イメージを
再配布していないため、現時点で義務が生じない。再配布する場合は対象に入る（§6）。

## 3. 前提

このリポジトリは学習用であり、成果物を外部へ配布していない。公開している配布物が無いため、
多くの OSS ライセンスが課す義務（著作権表示の同梱、ライセンス文の添付、変更点の告知）は、
まだ履行の対象になっていない。

この前提が変わるのは、次のいずれかが起きたときである。

* コンテナイメージを他者へ渡す
* Angular のビルド生成物を他者へ配る
* このリポジトリ自体を公開する

## 4. 定義

### 4.1 台帳の形

依存1件あたりに記録する項目を次のように定める。現時点で埋まっているのは §4.3 の1行だけである。

| 項目 | 意味 |
| --- | --- |
| 名前・版数 | SBOM のコンポーネントと対応する |
| 生態系 | PyPI / npm / fork したソース |
| ライセンス | SPDX の識別子 |
| 入手元 | PyPI、npm registry、fork 元のリポジトリ |
| 直接／推移 | 自分で宣言したか、他の依存が引いたか |
| 配布の有無 | その依存を含むものを外部へ渡しているか |
| 義務 | 表示、ライセンス文の同梱、変更の告知、ソースの開示のいずれが生じるか |
| 確認日 | 誰がいつ確認したか |

### 4.2 全件を列挙できない理由

SBOM はライセンス欄を持たない（`tools/supply_chain/sbom.py`。56 §4.3）。したがって、
lock が決めている依存のライセンスを、いまある道具で機械的に集められない。
`../phase4_テスト品質保証/33_リリース判定基準.md` が項目18「License を確認した」を対象外に
している理由もこれである。

手作業で集めることは可能だが、`requirements/*.txt` の5ファイルと `pnpm-lock.yaml`（7637行）が
対象であり、依存が変わるたびに繰り返すことになる。1回の写しは、次の更新で古くなる。

機械的に集めるときの注意点が1つある。Python のパッケージは、ライセンスを2つの異なる項目で
宣言する。古い形式は `License:`、新しい形式は `License-Expression:` である。
手元の仮想環境で確認したところ、`fastapi`・`uvicorn`・`scikit-learn`・`pydantic`・
`prometheus_client` は `License:` が空で `License-Expression:` を持ち、`clearml` と `numpy` は
`License:` を持つ。片方だけを読む実装は、半数を「ライセンス不明」として報告する。

### 4.3 確認できているもの

| 対象 | ライセンス | 根拠 | 生じる義務 |
| --- | --- | --- | --- |
| ClearML Web（``。fork して取り込み） | Apache License 2.0 | `LICENSE` | 再配布時に、ライセンス文と著作権表示の同梱、変更したファイルの告知 |
| ClearML SDK（`clearml`） | Apache License 2.0 | パッケージの metadata | 同上 |

`package.json` の `license` は空文字列である。fork 元のライセンスは `LICENSE`
に残っているため、ライセンスが不明なわけではない。ただし、パッケージの宣言としては空であり、
機械的に読む道具はここを見る。

リポジトリのルートには `LICENSE` が無く、ルートの `package.json` は `private: true` である。
このリポジトリ自体のライセンスを決めていない（§6）。

### 4.4 Angular アプリに同梱されている第三者ライブラリ

`**/assets/**` には、plotly と ace-builds を含む第三者ライブラリが、ファイルとして
置かれている。これらは lock に現れないため、SBOM にも入らない。秘密検査ではこの範囲を
理由付きで除外しており（`config/security.yaml`）、除外の理由に「持ち込んだ第三者ライブラリ」と
書いてある。つまり、第三者のものであることは把握されているが、ライセンスは確認していない。

ブラウザへ配る生成物にこれらが含まれるため、配布を始めた時点で表示の義務が生じる可能性が高い。

### 4.5 台帳を埋める順序

全件を一度に埋めない。次の順で進める。

1. SBOM にライセンス欄を足す（56 §6）。Python は `License-Expression:` と `License:` の両方を、
   npm は `package.json` の `license` を読む
2. 生成された一覧から、SPDX 識別子が取れなかったものだけを手で確認する
3. 配布を始める対象（イメージ、ブラウザへの生成物）に含まれるものを先に確認する
4. `**/assets/**` の同梱ライブラリを、ファイル単位で確認する

この順序の理由は、3 が義務の生じる範囲であり、1 と 2 はその範囲を特定するための作業であること
による。

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 台帳を空のまま作る | 何が確認できていないかを、文書の不在ではなく文書の中で示す |
| 手作業での全件列挙をしない | 依存が変わるたびに古くなる写しになる |
| 配布物に含まれるものを優先する | 義務が生じるのは配布したときであり、そこが先に要る |
| ルートのライセンスを未定のまま残す | 公開する予定を決めていない。決める前に選ぶと、選び直すことになる |

## 6. 未決事項

* SBOM のライセンス欄（56 §6 と同じ項目）
* このリポジトリ自体のライセンス。ClearML Web を fork して含むため、Apache License 2.0 との
  両立を確認してから決める
* `package.json` の `license` を埋めるかどうか
* `**/assets/**` に同梱されている第三者ライブラリの一覧とライセンス
* コンテナイメージを配布する場合の、OS パッケージのライセンスの扱い
* 禁止するライセンスの一覧（copyleft の扱い）。配布の方針が決まるまで定めない
