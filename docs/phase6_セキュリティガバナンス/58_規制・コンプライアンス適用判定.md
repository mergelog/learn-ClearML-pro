## 1. 目的

この文書は、どの規制・契約上の制限がこのプロジェクトに適用されるかを判断し、その判断と根拠を残す。

結論は、現時点でいずれも適用されない、である。以下はその根拠と、判断が変わる条件である。
12・13・25 の各文書が「規制の判定は 58 で行う」として先送りした判断を、ここで確定させる。

この文書は法的な助言ではない。判断したのは開発者本人であり、法務の確認を受けていない（§5）。

## 2. 適用範囲

対象は、このリポジトリが扱うデータと、そのデータで作るモデル、およびソフトウェアの配布である。

判定する規制と制限は次の6つである。対象を選んだのは、扱うデータの種類（測定データ）、
作るもの（機械学習モデル）、および配布の有無から、適用が問題になりうる範囲だからである。

| # | 規制・制限 | 判定 |
| --- | --- | --- |
| 1 | 個人情報保護法（日本） | 適用されない（§4.1） |
| 2 | GDPR | 適用されない（§4.2） |
| 3 | EU AI Act | 適用されない（§4.3） |
| 4 | 契約上の制限（顧客データ・秘密保持） | 適用されない（§4.4） |
| 5 | OSS ライセンスの義務 | 現時点で義務は生じない（§4.5） |
| 6 | 輸出管理・その他 | 適用されない（§4.6） |

## 3. 前提

判定の根拠になっている事実は3つで、いずれも他の文書が確認したものである。

| 事実 | 根拠 |
| --- | --- |
| 現 Dataset に個人情報は含まれない | `../phase2_データ管理/13_PII・機密データ台帳.md` §4.1 |
| モデルは製品を判定し、人を判定しない | `../phase3_ML固有/25_公平性・バイアス評価.md` §3 |
| 成果物を外部へ配布していない | `55_OSSライセンス台帳.md` §3 |

この3つのいずれかが変わると、判定は変わる。変わる条件は各節に書く。

## 4. 定義

### 4.1 個人情報保護法（日本）

適用されない。取り扱う個人情報が無いためである。

Dataset の11列は、検体の識別子、装置、工程、測定値、判定結果だけであり、行を人と結び付ける
経路が無い（`../phase2_データ管理/10_データディクショナリ.md` §4.2、
`../phase2_データ管理/13_PII・機密データ台帳.md` §4.1）。`equipment_id` は装置を指すもので、
その装置を誰が動かしたかを記録していない。

判定が変わる条件は、13 §4.1 が挙げる列が入ったときである。作業者 ID、検体と作業記録を結ぶキー、
顧客を特定できる識別子のいずれかが列として入ると、取り扱いが生じる。そのときは列ごとに判定を
行い、13 の表を更新してから流す。

### 4.2 GDPR

適用されない。理由は2つあり、どちらか一方でも成立すれば適用されない。

第一に、個人データを扱っていない（§4.1）。第二に、EU に所在する者へ商品やサービスを提供して
おらず、EU 域内の者の行動を監視していない。このリポジトリは単一の開発端末で動く学習用のもので、
外部から到達できる経路を持たない。

判定が変わる条件は、個人データが入ること、または EU 域内の利用者へ提供を始めることである。

### 4.3 EU AI Act

適用されない。理由は、提供者・利用者としての行為が成立していないことによる。

EU AI Act が義務を課すのは、AI システムを EU 市場へ提供する者と、EU 域内で利用する者である。
このプロジェクトはモデルを外部へ提供しておらず、EU 域内での利用も無い。

仮に提供を始めた場合の分類についても、現時点では高リスクに該当しない見込みである。判定の対象は
製品の品質判定であり、同法が高リスクとして挙げる領域（生体認証、重要インフラ、教育、雇用、
公共サービス、法執行など）に含まれない。ただしこれは見込みであり、提供を始める時点で、
そのときの条文と製品の位置づけに照らして判定し直す必要がある。同法には汎用 AI モデルに対する
別系統の義務もあるが、このプロジェクトが作るのは特定の判定に使う分類器であり、そこには当たらない。

判定が変わる条件は、モデルを EU 域内へ提供すること、または判定の対象が人に関わるものへ変わる
ことである。後者が起きた場合、公平性評価の対象外判断も併せて見直す
（`../phase3_ML固有/25_公平性・バイアス評価.md` §4.5）。

### 4.4 契約上の制限

適用されない。顧客から受領したデータを扱っておらず、秘密保持の対象となるデータも無い。

学習に使っているのは生成器が作る合成データである（`../phase3_ML固有/21_データセットカード.md`）。
外部から受領したものは、持ち込んだ ClearML Web と ClearML SDK であり、これは契約ではなく
OSS ライセンスの範囲である（§4.5）。

判定が変わる条件は、実データを受け入れることである。そのとき、ロット番号など顧客を特定できる
識別子は、個人情報ではないが契約上の秘密になりうる（`../phase2_データ管理/13_PII・機密データ台帳.md` §4.1）。
受入時に、データの出所と利用範囲の合意を確認する。

### 4.5 OSS ライセンスの義務

現時点で履行すべき義務は生じない。配布物が無いためである。

含んでいる OSS のうち、ライセンスを確認できているのは ClearML Web と ClearML SDK の
Apache License 2.0 である。依存全体のライセンスは未確認であり、確認できない理由は
`55_OSSライセンス台帳.md` §4.2 にある。

判定が変わる条件は、配布を始めることである。コンテナイメージを渡す、ブラウザへの生成物を配る、
リポジトリを公開する、のいずれかが起きた時点で、表示とライセンス文の同梱の義務が生じる。
その順序は 55 §4.5 にある。

### 4.6 輸出管理・その他

適用されない。暗号の実装を含んでおらず（TLS は実行環境の機能を使う形だけがある）、
軍事・デュアルユースに該当する技術を扱っていない。判定の対象は製品の品質であり、
規制品目ではない。

医療・金融・自動車など、業種ごとの規制も対象外である。いずれの業種向けにも提供していない。

### 4.7 判定を見直す条件

次のいずれかが起きたとき、この文書を見直す。どの節を見直すかを併記する。

| 条件 | 見直す節 |
| --- | --- |
| 実データを受け入れる | §4.1、§4.4 |
| 人に関する列が Dataset に入る | §4.1、§4.2、§4.3 |
| 判定の対象が人に関わるものへ変わる | §4.3（および 25 §4.5） |
| 成果物を外部へ配布する | §4.5 |
| EU 域内へ提供する | §4.2、§4.3 |
| 業種を限定した提供を始める | §4.6 |

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 適用されない規制も節を立てて残す | 「検討していない」と「検討して適用外と判断した」を区別する。項目を消すと、判断したこと自体が残らない |
| 判定の根拠を他の文書へのリンクで示す | 事実は 10・13・21・25 が持つ。ここで写すと、事実が2か所に分かれて食い違う |
| EU AI Act の高リスク分類を「見込み」に留める | 提供していないため分類を確定させる必要が無く、確定させると条文の改定で古くなる |
| 法務の確認を受けていないことを明記する | 判断したのは開発者本人であり、確認を受けたと読める形にはできない |
| 「対応済み」と書かない | 義務が生じていない状態を、義務を履行した状態として記録しない |
