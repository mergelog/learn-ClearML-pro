## 1. 目的

この文書は、本プロジェクトの成果に関わる相手を並べ、それぞれとの関係が何に依存しているかを示す。

誰がどの作業に責任を持つかは 73 が持つ。ここで扱うのは、作業の外にいて、
しかしこちらの判断や成果に影響する相手である。

## 2. 適用範囲

対象は、実在する相手に限る。

顧客・発注者・利用部門・承認者は存在しない。本プロジェクトは学習を目的とした単独開発であり、
成果物を受け取る第三者がいない。要求の出どころは 01 が定める学習目的そのものである。

## 3. 前提

`Angular Web` は ClearML Web の fork である。`ml` / `services` / `tools` は自作であり、
ClearML の SDK と Server に依存する。この依存関係が、外部との関係のほぼすべてを決めている。

## 4. 定義

### 4.1 一覧

| # | 相手 | 立場 | こちらへの影響 | こちらからの働きかけ |
| --- | --- | --- | --- | --- |
| S-01 | 本リポジトリの開発者 | 唯一の作業者。要求・実装・判定のすべてを担う | 全作業 | — |
| S-02 | ClearML（開発元） | 基盤と Web の提供元 | Server・SDK・Web の仕様変更が実装に直接及ぶ（R-01・R-02・R-05） | 無し。更新を追う側であり、要望を出していない |
| S-03 | 依存 OSS の提供者 | Angular・NgRx・scikit-learn ほか | 版上げの破壊的変更と脆弱性（R-03・R-04・R-16） | 無し |
| S-04 | ライセンス上の義務の相手 | 依存 OSS のライセンス保持者 | 再配布時の表示義務。現在は配布していない | 55 の台帳で義務を把握する |
| S-05 | 想定する利用者（水銀電池製造の工程担当） | 01 が置く仮想の利用者 | 要求の前提。実在しない | 無し |
| S-06 | 将来の参画者 | まだいない | 文書の書き方を規定する。読んで再現できるかが基準 | `docs/**` を通じてのみ |

S-01 以外に、こちらの判断を承認する相手はいない。
S-05 は 01 が利用シナリオを立てるために置いた仮想の相手であり、実在の関係者ではない。

### 4.2 ClearML との関係

S-02 との関係は一方向である。こちらが upstream を追う立場にあり、
こちらの変更が upstream へ戻ることはない。

fork した時点の版から upstream がどれだけ進んだかは、`pnpm upstream:status` が見る。
最後に確認した commit は `upstream.json` にあり、そこから進むとこの検査が失敗する（03 §4.15）。

`Angular Web` の自作分を feature 単位で分けてあるのは、この関係を前提にした配置である（61 §4.1）。
既存ファイルを書き換えずに済む範囲であれば、upstream の更新を取り込むときの競合が自作分に限られる。

### 4.3 将来の参画者

S-06 は現在いない。それでも一覧に置くのは、この相手が文書の合否条件になっているためである。

`docs/README.md` は、置くものを「別の人が同じことを再現できるかを基準にした資料」に限ると宣言している。
再現できるかを判断する相手が S-06 である。机上で書いた手順を置かないという制約も、
この相手を想定した結果である（`x-plan-改訂/将来的展望/02_20260912_将来TODO.md` §2）。

### 4.4 存在しない相手

以下は、一般的なプロジェクトでは置かれるが、本プロジェクトには存在しない。

| 相手 | 存在しない理由 | 生じたときに影響する文書 |
| --- | --- | --- |
| 発注者・顧客 | 受け取る第三者がいない | 01、32、33 |
| 運用担当（開発者以外） | 単独作業である | 40、42、73 §4.4 |
| データ提供者 | Dataset を自分で生成している（21） | 10、14、21 |
| 監査人・規制当局 | 適用される規制が無いと判定した（58） | 53、58 |

これらが生じた時点で、対応する文書の前提が変わる。
とくにデータ提供者が現れた場合、10 と 14 は生成器ではなく提供元の仕様に従うことになる。

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 実在しない相手を一覧の本体へ入れない | 顧客や承認者を置くと、要求や承認が実在するかのように読める |
| 存在しない相手を §4.4 に明示した | 空欄では「検討していない」と「存在しない」を区別できない |
| 将来の参画者を一覧に残した | 文書の合否条件がこの相手の再現可否で決まっているため |
