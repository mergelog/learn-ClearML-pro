## 1. 目的

この台帳は、いったん決めたことを後から変えた記録を残す。

なぜそう決めたかは ADR が、いまどうなっているかは各設計書が持つ。
この台帳が持つのは、決めた内容が変わった事実と、その変更が他の何に及んだかである。

## 2. 適用範囲

記録するのは、他へ波及する変更に限る。次のいずれかに当たるものを対象とする。

| 種別 | 例 |
| --- | --- |
| 決定の変更 | ADR の決定を覆す。方式・境界・依存方向を変える |
| 構成の変更 | ディレクトリ構成、文書の置き場所、成果物の単位を変える |
| 契約の変更 | API の形、Dataset のスキーマ、パイプラインの入出力を変える |
| 基準の変更 | 品質の合否条件、評価の採用基準、リリースの判定項目を変える |

通常の実装・文書の更新は対象外とする。git の履歴と各文書の更新履歴が持つ。
両方へ書くと、どちらが最新か判断できなくなる。

## 3. 前提

変更の実体は git のコミットである。この台帳は履歴を置き換えず、
「どのコミットで何の決定が変わったか」を人が読める形で指す。

現在、リポジトリのコミットは3件、タグは0件である。体系文書の整備は1日（2026-09-12）に行われており、
その内部の順序は、コミット単位では追えない。

### 4.3 ADR との関係

決定そのものは ADR が持ち、書き換えない。決定を変えるときは新しい ADR を書き、
古い ADR の状態を「置き換えられた」にする（64 §4.7）。

この台帳は、その置き換えが起きた事実と波及先を1行で指す。ADR を読まなければ経緯が分からない状態を、
台帳の側で埋めない。経緯を写すと、写した先と写し元のどちらが正しいか判断できなくなる。

### 4.4 記録する時機

変更を取り込んだ時点で書く。まとめて後から書かない。
後から書くと、波及先（どのファイルを併せて直したか）が思い出せる範囲に縮む。

C-01 の「13ファイルのパス参照」は、移設と同時に直したために数えられている。

### 4.5 契約の変更の扱い

API・Dataset・パイプラインの契約を変えるときは、変更前に影響範囲を確かめる手段がある。

| 契約 | 確かめる手段 |
| --- | --- |
| パイプラインの入出力 | `pnpm web:contract` |
| 公開している画面の外向き面 | `data-catalog.surface.published.json` との差分（ADR 006） |
| Dataset の列と型 | `ml/**/domain.py` と `pnpm ml:data check` |
| 推論 API の形 | `pnpm serving:openapi:update` の差分 |

これらが差分を出したときは、台帳へ記録する変更に当たる。差分が出ないなら、契約は変わっていない。

## 5. 判断事項

| 判断 | 理由 |
| --- | --- |
| 通常の更新を対象外にした | git の履歴と各文書の更新履歴で足りる。二重に書くと最新が定まらない |
| ADR の経緯を写さない | 写した先と写し元で食い違う |
| 契約の変更を機械の差分で定義した | 「変えたつもりが無い」変更を人の申告だけに任せない |
