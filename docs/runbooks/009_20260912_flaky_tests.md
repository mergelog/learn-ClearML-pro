# Runbook: 振れるテスト（flaky）

同じコードで、走らせるたびに結果が変わるテストの扱い。

## 方針

**隔離しない。retryもしない。**

skipやquarantineへ移すと赤が消える。赤が消えると直す理由も消え、
「そのうち見る」まま残る。retryを入れると振れたテストは緑になり、
**検知そのものが無くなる**。このシステムは失敗を一度で確定させる設計で
（W12-4）、テストも同じ扱いにする。Playwrightの `retries` は 0 のままにする。

代わりに置くのは「**同じものを繰り返して、振れるかどうかを数える**」道具だけ
である。

## 1. 疑いが出たら数える

```bash
corepack pnpm test:flaky                # E2Eを5回
corepack pnpm test:flaky --times 10
```

判定の単位はテスト1件である（Playwrightが書くJUnit XMLを読む）。

| 出方 | 意味 |
| --- | --- |
| 緑と赤が混ざる | **振れている**。これを探している |
| ずっと赤 | 壊れている。flakyではない。普通に直す |
| 走行ごとに実行された集合が違う | 名前が変わったか、途中で落ちて残りが走っていない |

CIでは走らせない。同じ試験を5回走らせる分だけ遅くなる。疑いが出たときに
手元で回す。

## 2. 原因を4つに分けて読む

振れる理由はだいたいこの4つで、直し方が違う。

| 分類 | 見分け方 | 直し方 |
| --- | --- | --- |
| 時間 | `waitForTimeout` や固定待ちの近くで落ちる | 時間ではなく**状態**を待つ（`expect.poll` / `toBeVisible`） |
| 順序・並行 | 単独では通り、まとめて走らせると落ちる | テスト間で共有している状態を切る（`page` は既にテストごと） |
| 外部 | fixtureの外へ出ている（実ネットワーク・時計・乱数） | 差し替える。E2EのAPI応答は `e2e/fixtures` が持つ |
| 実装の非決定性 | テストではなく製品側が振れている | **テストを直さない**。製品を直す |

4つ目が一番多く、そして一番見落とされる。振れているのがテストだと決めつける
前に、製品側が同じ入力で同じ結果を返しているかを見る。

## 3. 直したら記録する

直した理由を残さないと、同じ形が何度でも戻ってくる。下の台帳へ1行足す。

| 日付 | テスト | 分類 | 原因 | 直し方 | 再発防止 |
| --- | --- | --- | --- | --- | --- |
| － | （まだ無い） | － | － | － | － |

2026-09-12 時点で、E2E 27件を4回繰り返して振れたものは無い。
**台帳が空であることと、振れるテストが無いことは同じではない。**
数えていない期間に振れていたかどうかは分からないので、疑いが出たら数える。

## トラブルシュート

| 症状 | 原因と対処 |
| --- | --- |
| `playwright.xml が書かれなかった` | 走行そのものが立ち上がっていない。`pnpm web:e2e` を単独で走らせて原因を見る |
| 毎回ぴったり同じテストが落ちる | flakyではない。壊れているので普通に直す |
| 手元では振れないがCIでだけ落ちる | CIはdev serverを毎回立てる。`playwright.config.ts` の `webServer.timeout` を疑う（待ち不足は「E2Eが失敗した」と読める形で出る） |
