# 02-05 選択状態の四系統

「選択されている実験」を表す状態が 4 つ並存している。
役割が違い、更新するタイミングも保存先も異なる。

| 名前 | Selector / 実体 | 何を指すか | 更新のきっかけ |
| --- | --- | --- | --- |
| `selectedExperiment` | `selectSelectedExperiment`（info feature） | 右ペインに表示中の実験の詳細 | URL の `:experimentId` → `getExperiment` の応答 |
| `selectedTableExperiment` | `selectSelectedTableExperiment`（view feature） | 一覧行として選ばれている実験 | `setSelectedExperiment`（URL とリストの突き合わせ結果） |
| `selectedExperiments` | `selectSelectedExperiments` | チェックボックスで選んだ複数件 | `setSelectedExperiments` |
| `highlited` | コンポーネント内 `signal` | 行クリックの一時ハイライト | `experimentSelectionChanged`（`origin: 'row'`） |

## 図1: 4 つが同時に動く場面

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant InfoEff as InfoEffects

    User->>ExpTable: 行 A をクリック
    ExpTable->>EC: experimentSelectionChanged({experiment: A, origin: 'row'})
    EC->>EC: selectionState().highlited.set(A)
    Note right of EC: この時点で動くのは highlited だけ

    User->>ExpTable: 行 B のチェックボックス
    ExpTable->>EC: experimentsSelectionChanged([B])
    EC->>Store: setSelectedExperiments({experiments: [B]})
    Store->>ViewEff: 活性判定を計算 → setSelectedExperimentsDisableAvailable

    User->>ExpTable: 行 A をダブルクリック
    EC->>Store: experimentSelectionChanged({experiment: A})
    Store->>ViewEff: router.navigate(.../tasks/A) + setTableMode('info')
    Store-->>EC: selectRouterParams.experimentId = A
    EC->>Store: setSelectedExperiment({experiment: A})
    Note right of Store: selectedTableExperiment = A
    Store->>InfoEff: getExperimentInfo → getExperiment
    InfoEff->>Store: setExperiment({experiment}) ／ setExperimentInfoData
    Note right of Store: selectedExperiment = A の詳細（項目数が多い版）
```

## 図2: highlited が signal である理由

```mermaid
sequenceDiagram
    autonumber
    participant Store
    participant EC as ExperimentsComponent

    Store-->>EC: selectSelectedTableExperiment（distinctUntilChanged で id 比較）
    EC->>EC: selectedTableExperiment = toSignal(...)
    EC->>EC: previousTableExperiment = computedPrevious(selectedTableExperiment)
    EC->>EC: selectionState = computed(() => ({<br/>prevExperiment: previousTableExperiment(),<br/>highlited: signal(selectedTableExperiment() ?? previousTableExperiment())}))
    Note right of EC: selectedTableExperiment が変わるたびに<br/>computed が新しい signal を作り直す<br/>＝ Store 側の選択が変わるとハイライトが張り替わる
    EC->>EC: highlited = computed(() => tableMode() === 'compare' ? null : selectionState().highlited())
    EC-->>EC: 比較モードでは常に null
```

`highlited` はテーブル行の枠線表示にしか使われず、URL にも Store にも保存されない。
一方 `selectedTableExperiment` は Store にあり、自動更新のたびに
「詳細を取り直すべきか」の判断材料として使われる（04-04）。

## 図3: 比較モードでの選択の取り直し

```mermaid
sequenceDiagram
    autonumber
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant TasksApi

    EC->>Store: dispatch getSelectedExperiments({ids: URL の ids})
    Store->>ViewEff: getSelectedExperiments effect
    ViewEff->>Store: selectSelectedExperiments / selectExperimentsList を読む
    alt すでに選択済みがある
        ViewEff->>Store: setSelectedExperiments(既存を先頭100件)
    else 一覧の中に ids が全部ある
        ViewEff->>Store: setSelectedExperiments(一覧から抽出、先頭100件)
    else 足りない
        ViewEff->>TasksApi: tasksGetAllEx({id: ids})
        TasksApi-->>ViewEff: {tasks}
        ViewEff->>Store: setSelectedExperiments({experiments: tasks})
    end
```
