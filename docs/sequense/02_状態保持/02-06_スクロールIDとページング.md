# 02-06 スクロール ID とページング

一覧は `tasks.get_all_ex` の `scroll_id` によるカーソル方式で読み進める。
`scroll_id` はサーバ側のセッションに紐づくため、
「同じ ID が返ってきたか」が状態遷移の分岐条件になっている。

Store に持つのは `scrollId`（`selectCurrentScrollId`）と
`refreshList`（`selectTableRefreshSessionList`、再取得が必要かのフラグ）の 2 つ。

## 図1: 初回取得 → 追い読み

```mermaid
sequenceDiagram
    autonumber
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant Server

    EC->>Store: dispatch getExperiments()
    Store->>ViewEff: reFetchExperiment effect
    ViewEff->>Server: tasks.get_all_ex {scroll_id: null, refresh_scroll: true, size: 30}
    Note right of ViewEff: null を渡すと新規スクロールを作る<br/>（undefined だと作られない）
    Server-->>ViewEff: {tasks: [...30], scroll_id: 'S1'}
    ViewEff->>Store: setNoMoreExperiments({hasMore: tasks.length が 30 未満か})
    ViewEff->>Store: setExperiments({experiments})
    ViewEff->>Store: setCurrentScrollId({scrollId: 'S1'})

    Note over EC,Server: 一覧を末尾までスクロール
    EC->>Store: dispatch getNextExperiments()
    Store->>ViewEff: getNextExperiments effect
    ViewEff->>Server: tasks.get_all_ex {scroll_id: 'S1', refresh_scroll: false}
    Server-->>ViewEff: {tasks: [次の30件], scroll_id: 'S1'}
    ViewEff->>Store: addExperiments({experiments})（既存リストへ追記）
    ViewEff->>Store: setCurrentScrollId({scrollId: 'S1'})
```

## 図2: スクロールセッションが切れた場合

```mermaid
sequenceDiagram
    autonumber
    participant Store
    participant ViewEff as ViewEffects
    participant Server
    participant User

    Note over ViewEff: 自動更新または追い読みの途中
    ViewEff->>Server: tasks.get_all_ex {scroll_id: 'S1'}
    Server-->>ViewEff: {tasks, scroll_id: 'S2'}
    ViewEff->>ViewEff: res.scroll_id !== currentScrollId
    ViewEff->>Store: setCurrentScrollId({scrollId: 'S2'})
    ViewEff->>Store: setNoMoreExperiments({hasMore})
    alt 手動更新（autoRefresh: false）
        ViewEff->>Store: addMessage(WARN, 'Session expired')
        ViewEff->>Store: setTableRefreshSessionPending({refresh: true})
        Note right of Store: refreshList フラグが立つ
        User->>Store: 次に更新するとき
        ViewEff->>Store: getExperimentsWithPageSize({pageSize: 表示中の件数})
        ViewEff->>Store: setTableRefreshSessionPending({refresh: false})
        Note right of ViewEff: 読み込み済み件数ぶんを 1 回で取り直し、<br/>スクロール位置を保ったまま作り直す
    else 自動更新
        Note right of ViewEff: 通知を出さずに setExperiments で差し替え
    end
```

## 図3: 「もう無い」の判定

```mermaid
sequenceDiagram
    autonumber
    participant ViewEff as ViewEffects
    participant Store
    participant SmTable as sm-table

    ViewEff->>ViewEff: res.tasks.length が EXPERIMENTS_PAGE_SIZE 未満か判定
    ViewEff->>Store: setNoMoreExperiments({hasMore: 上の真偽値})
    Store-->>SmTable: [noMoreData]=noMoreExperiments()
    Note over SmTable: [autoLoadMore]=true のため、<br/>noMoreData が false の間だけ<br/>末尾到達で loadMoreClicked を出す
```

`setNoMoreExperiments` のプロパティ名は `hasMore` だが、渡している値は
`res.tasks.length < EXPERIMENTS_PAGE_SIZE`、つまり「もう無い」である。
reducer も `noMoreExperiment: action.hasMore` と、そのまま名前を反転して格納している
（[experiments-view.reducer.ts:175](/home/mtrysd/work_2026/000-learn-ClearML-pro/src/app/webapp-common/experiments/reducers/experiments-view.reducer.ts:175)）。
プロパティ名だけを見ると意味が逆になる。
