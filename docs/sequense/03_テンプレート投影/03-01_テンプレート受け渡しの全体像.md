# 03-01 テンプレート受け渡しの全体像

この画面では `ng-template` が 3 つの方向に渡っている。

1. 親 → 子（`input` で `TemplateRef` を渡し、子が `ngTemplateOutlet` で描く）
2. 子 → 孫（`sm-experiments-table` が `sm-table` にコンテンツとして渡し、`contentChildren` で拾われる）
3. 兄弟間（ヘッダーが自分のテンプレートを設定オブジェクトに埋めて孫に渡す）

`ng-content` は `sm-table-card` の組み立てにだけ使われている。

## 図: どのテンプレートがどこで実体化するか

```mermaid

    Note over EC: addButton テンプレートを宣言
    EC->>Header: [addButtonTemplate]="addButton"
    Header->>Header: ngTemplateOutlet で addButtonTemplate() を描画<br/>context に smallScreen を渡す
    Note right of Header: NEW TASK ボタンはヘッダー内に描かれるが<br/>クリックハンドラは EC のもの

    Note over Header: metricsTemplate と hyperParamsTemplate を宣言
    Header->>ColsMenu: [sections]="[{name, options, template: metricsTemplate}, ...]"
    ColsMenu->>ColsMenu: ngTemplateOutlet で sections()[0].template を描画<br/>context の $implicit は sections()[0]

    Note over EC: contextMenuExtendedTemplate を宣言
    EC->>ExpTable: contextMenuTemplate に contextMenuExtendedTemplate を渡す
    ExpTable->>ExpTable: ngTemplateOutlet で描画（テンプレート先頭行）
    Note right of ExpTable: 描画位置は ExpTable の中、<br/>宣言ビューは EC（03-03）

    Note over ExpTable: ng-template pTemplate="body" や "card" などを宣言
    ExpTable->>SmTable: コンテンツとして投影
    SmTable->>SmTable: contentChildren(PrimeTemplate) → ngAfterContentInit で振り分け
    SmTable->>SmTable: ngTemplateOutlet で bodyTemplate を描画<br/>context は $implicit=col, rowData

    Note over ExpTable: pTemplate="card" の中で sm-table-card に子要素を書く
    SmTable->>Card: card テンプレートを描画
    Card->>Card: ng-content select="mat-checkbox" などで slot 分配（03-04）

    Note over ExpTable: noDataTemplate を宣言
    ExpTable->>SmTable: noDataTemplate 入力に渡す
    SmTable->>SmTable: emptymessage 内で ngTemplateOutlet
```

## 一覧

| テンプレート | 宣言元 | 渡し方 | 描画元 | context |
| --- | --- | --- | --- | --- |
| `#addButton` | `ExperimentsComponent` | `input` | `sm-experiment-header` | `{smallScreen}` |
| `#contextMenuExtendedTemplate` | `ExperimentsComponent` | `input` | `sm-experiments-table` | `{$implicit: contextExperiment()}` |
| `#metricsTemplate` / `#hyperParamsTemplate` | `sm-experiment-header` | `sections[].template` | `sm-custom-cols-menu` | `{$implicit: section}` |
| `pTemplate="body"` ほか 6 種 | `sm-experiments-table` | コンテンツ投影 | `sm-table` | 種類ごとに異なる |
| `#noDataTemplate` | `sm-experiments-table` | `input` | `sm-table` | `{noDataTop, minimizedView}` |
| `#tagList` / `#compactCol` | `sm-experiments-table`（card テンプレート内） | `input` | `sm-table-card` | なし |

## テンプレートを渡す利点

子コンポーネントは「どこに何を置くか」だけを決め、中身の描き方と依存は親に残る。
`sm-table` は `ExperimentsTableComponent` も `ModelsTableComponent` も同じ実装で扱えて、
セルの描画だけが呼び出し側で差し替わる。

一方で、バインディングの評価文脈は宣言元のコンポーネントのままである。
`#contextMenuExtendedTemplate` の中に書かれた `checkedExperiments` や `selectedExperiment$` は
`sm-experiments-table` ではなく `ExperimentsComponent` のプロパティを参照している。
