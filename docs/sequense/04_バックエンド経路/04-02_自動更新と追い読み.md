# 04-02 自動更新と追い読み

一覧を更新する経路は 3 つある。どれも同じ `fetchExperiments$` を通るが、
渡す `scroll_id` と結果の扱いが違う。

| 経路 | 起点 | `scroll_id` | 結果の反映 |
| --- | --- | --- | --- |
| 初回・条件変更 | `getExperiments` ほか | `null`（新規作成） | `setExperiments`（全差し替え） |
| 自動更新・手動更新 | `refreshExperiments` | 現在の ID・`refresh_scroll: true` | `setExperimentInPlace` または `setExperiments` |
| 追い読み | `getNextExperiments` | 現在の ID・`refresh_scroll: false` | `addExperiments`（追記） |

## 図1: 自動更新のタイマーから反映まで

```mermaid
sequenceDiagram

    participant Timer as RefreshService
    participant Store
    participant Base as BaseEntityPageComponent
    participant EC as ExperimentsComponent
    participant ViewEff as ViewEffects
    participant Server

    Timer->>Timer: interval(AUTO_REFRESH_INTERVAL)
    Timer->>Store: selectAutoRefresh / selectAppVisible を確認
    Note right of Timer: 自動更新が off、またはタブが非表示なら発火しない
    Timer->>Base: tick.next(null)
    Base->>Store: selectEditMode / showAllSelectedIsActive を確認
    Note right of Base: 編集中や「選択中のみ表示」中はスキップ
    Base->>EC: refreshList(auto)
    EC->>Store: dispatch refreshExperiments({hideLoader: auto, autoRefresh: auto})

    Store->>ViewEff: refreshExperiments effect
    ViewEff->>ViewEff: lockRefresh が立っていれば無視
    ViewEff->>Store: currentScrollId / selectedExperiment / experiments / refreshList を読む
    ViewEff->>Server: tasks.get_all_ex {scroll_id, refresh_scroll: true}
    Server-->>ViewEff: {tasks, scroll_id}

    alt 選択中があり、ID 集合が前回と一致
        ViewEff->>Store: setExperimentInPlace({experiments})
        Note right of Store: 行の並びを保ったまま値だけ更新<br/>＝スクロール位置と選択が動かない
    else 件数や並びが変わった
        ViewEff->>Store: setExperiments({experiments, noPreferences: true})
        Note right of Store: noPreferences により<br/>ユーザープリファレンスへの保存は走らない
    end

    opt 選択中の実験がある
        alt 自動更新
            ViewEff->>Store: autoRefreshExperimentInfo({id})
        else 手動更新
            ViewEff->>Store: getExperimentInfo({id, autoRefresh: null})
        end
        Note right of Store: 右ペインの詳細も追従する（04-04）
    end
```

## 図2: 末尾スクロールでの追い読み

```mermaid

    participant ViewEff as ViewEffects

    User->>SmTable: 一覧を末尾までスクロール
    SmTable->>SmTable: autoLoadMore かつ noMoreData が false
    SmTable->>ExpTable: loadMoreClicked.emit()
    ExpTable->>EC: loadMoreExperiments.emit()
    EC->>ViewEff: dispatch getNextExperiments()
    ViewEff->>Server: tasks.get_all_ex {scroll_id, refresh_scroll: false}
    Server-->>ViewEff: {tasks, scroll_id}

        ViewEff->>ViewEff: getExperimentsWithPageSize({pageSize: 表示中の件数})で作り直し

        ViewEff->>ViewEff: addExperiments({experiments})
    end
```

## `lockRefresh` の役割

`refreshExperiments` の Effect はインスタンス変数 `lockRefresh` を持つ。
手動更新（`autoRefresh: false`）が始まると true になり、応答が返るかエラーになるまで
後続の `refreshExperiments` を弾く。

自動更新のタイマーは止まらないため、手動更新の最中にタイマーが発火して
2 重にリクエストが飛ぶのを防いでいる。

`getMetricsToDisplay()` から出る `getCustomMetrics({hideLoader: true})` などがここで落ちる
（[common-experiments-view.effects.ts:97](/home/mtrysd/work_2026/000-learn-ClearML-pro/src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts:97)）。
