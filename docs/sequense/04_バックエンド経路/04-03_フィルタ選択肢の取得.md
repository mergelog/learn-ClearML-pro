# 04-03 フィルタ選択肢の取得

列ヘッダのフィルタに出す選択肢は、一覧データとは別のエンドポイントから取る。
一覧に読み込まれている 30 件からではなく、プロジェクト全体から集める必要があるためである。

| 選択肢 | Action | エンドポイント | 取得のきっかけ |
| --- | --- | --- | --- |
| タグ | `getTags` | `projects.get_task_tags` | 起動時／タグメニューを開いたとき |
| タイプ | `getProjectTypes` | `tasks.get_types` | 起動時／タイプメニューを開いたとき |
| 親タスク | `getParents` | `projects.get_task_parents` | 起動時／検索文字列の入力時 |
| プロジェクト | `getTablesFilterProjectsOptions` | `projects.get_all_ex` | プロジェクト列のメニューを開いたとき |
| ユーザー | `getProjectUsers` | `projects.get_user_names` | 起動時（`ProjectsEffects` が担当） |
| カスタム列（メトリクス） | `getCustomMetrics` | `projects.get_unique_metric_variants` | 列カスタマイズメニューを開いたとき |
| カスタム列（ハイパーパラメータ名） | `getCustomHyperParams` | `projects.get_hyper_parameters` | 同上 |
| ハイパーパラメータの値 | `hyperParamSelectedExperiments` | `projects.get_hyperparam_values` | 該当列のフィルタメニューを開いたとき |

## 図1: メニューを開いた時点で取りに行くもの

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant ProjApi as ApiProjectsService

    User->>ExpTable: タグ列のフィルタを開く
    ExpTable->>ExpTable: columnFilterOpened(col)
    ExpTable->>ExpTable: sortByFilterValues.set(filtersValues())
    Note right of ExpTable: 開いた瞬間の選択値を固定し、<br/>選択中の項目を先頭に並べたまま操作できるようにする
    alt 選択肢がまだ空
        ExpTable->>EC: tagsMenuOpened.emit()
        EC->>Store: dispatch getTags({})
        Store->>ViewEff: getTagsEffect
        ViewEff->>ProjApi: projectsGetTaskTags({projects: [projectId]})
        ProjApi-->>ViewEff: {tags}
        ViewEff->>Store: setTags({tags: tags.concat(null)})
        Note right of Store: 末尾の null は「(No tags)」の選択肢になる
    end
    Store-->>ExpTable: [tags] → filtersOptions() が再計算される
```

## 図2: 親タスクの絞り込み検索

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant ViewEff as ViewEffects
    participant ProjApi as ApiProjectsService
    participant TasksApi as ApiTasksService

    User->>ExpTable: 親タスクフィルタで文字を入力
    ExpTable->>EC: filterSearchChanged.emit({colId: 'parent.name', value})
    EC->>EC: super.filterSearchChanged()（project 列用の分岐）
    EC->>ViewEff: dispatch resetTablesFilterParentsOptions() + getParents({searchValue})
    ViewEff->>ViewEff: debounceTime(300)
    ViewEff->>ProjApi: projectsGetTaskParents({projects, tasks_state, task_name: '(?i)...'})
    ProjApi-->>ViewEff: {parents}

    ViewEff->>ViewEff: 現在フィルタ中の親 ID が parents に含まれるか確認
    opt 含まれない ID がある
        ViewEff->>TasksApi: tasksGetAllEx({id: missingIds, only_fields: ['name','project.name']})
        TasksApi-->>ViewEff: {tasks}
        ViewEff->>ViewEff: setActiveParentsFilter({parents: tasks})
    end
    ViewEff->>ViewEff: setParents({parents})
    Note over ViewEff,ExpTable: 検索で候補から外れても、<br/>選択済みの親はチェックが付いたまま表示される
```

## 図3: ハイパーパラメータ値のページング

```mermaid
sequenceDiagram
    autonumber
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant ProjApi as ApiProjectsService

    Note over ExpTable: hyperparams. で始まる列のメニューを開く
    ExpTable->>Store: dispatch hyperParamSelectedInfoExperiments({col, values: []})
    ExpTable->>Store: dispatch setHyperParamsFiltersPage({page: 0})
    ExpTable->>Store: dispatch hyperParamSelectedExperiments({col, searchValue: ''})

    Store->>ViewEff: hyperParameterMenuClicked effect
    ViewEff->>ViewEff: debounce(searchValue ? 300ms : 0)
    ViewEff->>ViewEff: decodeHyperParam(col) → {section, name}
    ViewEff->>ProjApi: projectsGetHyperparamValues({section, name, page, page_size, pattern})
    ProjApi-->>ViewEff: {values}
    ViewEff->>Store: hyperParamSelectedInfoExperiments({col, values, loadMore: page > 0})

    Note over ExpTable,EC: さらにスクロールしたとき
    ExpTable->>EC: filterSearchChanged({colId, value: {loadMore: true}})
    EC->>Store: dispatch hyperParamSelectedExperiments（page は据え置き）
```

ハイパーパラメータの値だけはサーバ側ページングがある。
一方、親タスクの候補にはページングが無く、`loadMore` が来たときは
`setParents({parents: [...this.parents]})` と同じ配列を入れ直して
「これ以上は無い」と判定させている。
