# 04-04 詳細パネルの二段取得

右ペインの詳細は、`tasks.get_by_id_ex` を 2 回呼ぶ。
1 回目は `last_change` だけを取り、2 回目で本体を取る。
自動更新のたびに本体を取り直さないための作りである。

## 図1: 差分確認 → 本体取得

```mermaid
sequenceDiagram
    autonumber
    participant Store
    participant InfoEff as InfoEffects
    participant TasksApi as ApiTasksService
    participant Reverter as ExperimentReverterService
    participant Output as ExperimentOutputComponent

    Store->>InfoEff: getExperimentInfo / autoRefreshExperimentInfo /<br/>experimentUpdatedSuccessfully
    InfoEff->>Store: selectedTableExperiment / selectedExperiment /<br/>selectedFromTable / experimentInfoData / appVisible を読む

    alt 詳細データが無い、選択が無い、タブが非表示
        InfoEff->>InfoEff: 取得せず終了（ローダーだけ落とす）
    else 一覧に同じ行のデータが載っている
        InfoEff->>InfoEff: その行の last_change を使う（リクエストなし）
    else それ以外
        InfoEff->>TasksApi: tasksGetByIdEx({id: [selected.id], only_fields: ['last_change']})
        TasksApi-->>InfoEff: {tasks: [{last_change}]}
    end

    alt last_change が前回より新しい、または更新完了直後
        InfoEff->>Store: dispatch getExperiment({experimentId, autoRefresh})
        InfoEff->>Store: dispatch getExperimentUncommittedChanges({experimentId})
    else 変わっていない
        InfoEff->>Store: dispatch deactivateLoader のみ
        Note right of Store: 本体は取りに行かない
    end

    Store->>InfoEff: fetchExperiment$ effect
    InfoEff->>TasksApi: tasksGetByIdEx({id, only_fields: 詳細画面用の一式})
    TasksApi-->>InfoEff: {tasks: [task]}
    InfoEff->>Reverter: CommonExperimentReverterService.revertReadOnly()
    InfoEff->>Reverter: ExperimentReverterService.revertExperiment()
    Note right of Reverter: API のデータ形式を画面用のモデルへ変換
    InfoEff->>Store: setExperimentInfoData({experiment})（表示用）
    InfoEff->>Store: setExperiment({experiment})（生データ寄り）
    InfoEff->>Store: updateExperiment({id, changes})（一覧側の行も更新）
    InfoEff->>Store: deactivateLoader / setBackdrop(false) / deactivateEdit()
    Store-->>Output: Selector 経由で各タブに配られる
```

## 図2: 一覧更新から詳細更新への連鎖

```mermaid
sequenceDiagram
    autonumber
    participant ViewEff as ViewEffects
    participant Store
    participant InfoEff as InfoEffects
    participant Refresh as RefreshService

    Note over ViewEff: 04-02 の refreshExperiments の末尾
    ViewEff->>Store: setExperimentInPlace / setExperiments
    alt 自動更新
        ViewEff->>Store: autoRefreshExperimentInfo({id: selectedExperiment.id})
        Store->>InfoEff: getExperimentInfo$ effect
        InfoEff->>Refresh: refreshService.trigger(true)
        Note right of Refresh: スカラーやログなど、<br/>詳細タブ側の購読にも更新を伝える
    else 手動更新
        ViewEff->>Store: getExperimentInfo({id, autoRefresh: null})
    end
```

一覧の `setExperiments` は詳細取得より先に発行される。
`getExperimentInfo$` が `selectSelectedTableExperiment` を読んで
`last_change` の比較に使うため、順序が入れ替わると古い値で比較してしまう。
Effect のコメントにも `SetExperiments must be before GetExperimentInfo!` と書かれている。
