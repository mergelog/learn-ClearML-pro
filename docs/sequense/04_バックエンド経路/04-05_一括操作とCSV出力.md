# 04-05 一括操作と CSV 出力

一覧画面から出る、取得以外のリクエストをまとめる。
どれもフッターまたはコンテキストメニューが起点で、
成功したら一覧を取り直す形で画面を合わせる。

| 操作 | エンドポイント | 成功後 |
| --- | --- | --- |
| アーカイブ | `tasks.archive_many` | `removeExperiments` + `getExperiments` + Undo 付き通知 |
| アーカイブ解除 | `tasks.unarchive_many` | 同上 |
| 削除 | `tasks.delete_many` | 一覧から除去して取り直し |
| リセット | `tasks.reset_many` | 一覧を取り直し |
| Enqueue / Dequeue | `tasks.enqueue_many` / `tasks.dequeue_many` | 一覧を取り直し |
| 停止 | `tasks.stop_many` | 一覧を取り直し |
| 公開 | `tasks.publish_many` | 一覧を取り直し |
| プロジェクト移動 | `tasks.move` | 一覧を取り直し |
| タグ追加・削除 | `tasks.update_tags` | Store の該当行を更新 |
| クローン | `tasks.clone` | 複製されたタスクへ遷移 |

削除とリセットだけは `CommonExperimentsMenuEffects` ではなく、
確認ダイアログ側の Effect（[base-delete-dialog.effects.ts:100](/home/mtrysd/work_2026/000-learn-ClearML-pro/src/app/webapp-common/shared/entity-page/entity-delete/base-delete-dialog.effects.ts:100)）が呼ぶ。
どちらも同じダイアログを使い、`resetMode` フラグでエンドポイントを切り替えている。
| 新規作成 | `tasks.create` | 成功通知 + `refreshExperiments`（キュー指定時は `tasks.enqueue`） |
| 全件 CSV | `organization.prepare_download_for_get_all` | `downloadForGetAll` でダウンロード開始 |
| 表示中 CSV | なし（クライアント側で生成） | - |

## 図1: アーカイブと Undo

```mermaid
sequenceDiagram
    autonumber
    participant Menu as sm-experiment-menu-extended
    participant Store
    participant MenuEff as MenuEffects
    participant TasksApi as ApiTasksService
    participant ViewEff as ViewEffects

    Menu->>Store: dispatch archiveSelectedExperiments({selectedEntities})
    Store->>MenuEff: archiveExperiments effect
    MenuEff->>TasksApi: tasksArchiveMany({ids, include_pipeline_steps})
    TasksApi-->>MenuEff: {failed: [...]}

    MenuEff->>Store: setSelectedExperiments({experiments: []})
    MenuEff->>Store: addMessage(通知, [{name: 'Undo',<br/>actions: [setSelectedExperiments, restoreSelectedExperiments]}])
    Note right of Store: Undo は「元の選択を復元してから解除を実行」の 2 手
    MenuEff->>Store: removeExperiments({experiments: 成功した ID})
    MenuEff->>Store: getExperiments()
    Store->>ViewEff: 04-01 の取得経路へ

    opt 選択中の実験がアーカイブ対象に含まれる、または比較モード
        MenuEff->>Store: selectNextExperiment()
        Note right of Store: 右ペインを次の行へ移すか、比較を空にする
    end
```

`removeExperiments` で先に画面から消してから `getExperiments()` を出している。
サーバの応答を待たずに一覧が更新されるため、操作直後の見た目が遅れない。

## 図2: 全件 CSV ダウンロード

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Header as sm-experiment-header
    participant EC as ExperimentsComponent
    participant Store
    participant ViewEff as ViewEffects
    participant OrgApi as ApiOrganizationService

    User->>Header: 「Download first N items」
    Header->>EC: downloadFullTableAsCSV.emit()
    EC->>Store: dispatch prepareTableForDownload({entityType: 'task'})
    Store->>ViewEff: prepareTableForDownload effect
    ViewEff->>ViewEff: 一覧取得と同じ 14 個の状態を集める
    ViewEff->>ViewEff: getGetAllQuery({...}) + prepareColsForDownload(cols)
    Note right of ViewEff: 画面の列構成を CSV の列マッピングに変換
    ViewEff->>OrgApi: organizationPrepareDownloadForGetAll({entity_type, field_mappings, ...query})
    OrgApi-->>ViewEff: {prepare_id}
    ViewEff->>Store: dispatch downloadForGetAll({prepareId})
    Note right of Store: 以降は共通のダウンロード処理が prepare_id で取りに行く
```

表示中の行だけの CSV は API を使わない。
`ExperimentsComponent` が `viewChild` で掴んだ `sm-table` の
`downloadTableAsCSV()` を直接呼び、読み込み済みの行から生成する。

## 図3: 新規タスク作成

```mermaid
sequenceDiagram
    autonumber
    participant EC as ExperimentsComponent
    participant Dialog as CreateExperimentDialogComponent
    participant Store
    participant ViewEff as ViewEffects
    participant TasksApi as ApiTasksService

    EC->>Dialog: dialog.open()
    Dialog-->>EC: afterClosed() → data（リポジトリ、引数、Docker 設定ほか）
    EC->>Store: dispatch createExperiment({data})
    Store->>ViewEff: createExperiment effect
    ViewEff->>ViewEff: data を TasksCreateRequest に組み替え
    Note right of ViewEff: Docker の arguments 文字列に<br/>CLEARML_AGENT_* の環境変数を連結する
    ViewEff->>TasksApi: tasksCreate(request)
    TasksApi-->>ViewEff: {id}
    ViewEff->>Store: createExperimentSuccess({data: {...data, id}, project})

    par 成功後に 3 つの effect が反応
        ViewEff->>Store: addMessage(成功通知, [{name: 'open task', actions: [openExperiment]}])
    and
        ViewEff->>Store: refreshExperiments({autoRefresh: false, hideLoader: false})
    and
        opt キューが指定されている
            ViewEff->>TasksApi: tasksEnqueue({queue, task, verify_watched_queue: true})
            TasksApi-->>ViewEff: {queue_watched}
            opt queue_watched === false
                ViewEff->>Store: openEmptyQueueMessage({queue, entityName})
            end
        end
    end
```
