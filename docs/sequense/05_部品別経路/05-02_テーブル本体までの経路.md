# 05-02 テーブル本体までの経路

行が並ぶ本体まで。ここは3枚重ねになっていて、それぞれ役割が違う。

| 層 | 役割 |
| --- | --- |
| `sm-experiments-table` | Task 固有の知識（列 ID、フィルタ選択肢、選択ロジック）。基底は `BaseTableView` |
| `sm-table` | PrimeNG のラッパ。列幅・スクロール・テンプレート振り分け・キーボード操作 |
| `p-table` | 実際の table 要素を描く PrimeNG 本体 |

**Task という言葉を知っているのは一番上の層だけ**。下2層は `{id: string}` を持つ何かとしてしか扱わない。
だから同じ `sm-table` がモデル一覧や比較画面でも使われている。

## 図1: 3層の生成と input の流れ

```mermaid
sequenceDiagram
    autonumber
    participant EC as ExperimentsComponent
    participant Split as as-split-area（左）
    participant ExpTable as sm-experiments-table
    participant BaseTable as BaseTableView（基底）
    participant SmTable as sm-table
    participant PTable as p-table

    EC->>Split: [size]=100-splitSize()（Store）
    Split->>ExpTable: 左ペインに1個だけ配置
    EC->>ExpTable: [experiments] [tableCols] [colsOrder] [tableFilters]<br/>[checkedExperiments] [selectedExperiment]=highlited() ...
    Note right of EC: 中身はすべて Store の select。<br/>experiments$ だけ archived の絞り込みを通す

    ExpTable->>BaseTable: super()（selectionChecked の用意、table() 待ち effect）
    ExpTable->>SmTable: [tableData]=experiments() [columns]=tableCols()<br/>[columnsOrder]=colsOrder() [selection]=selectedExperiment()<br/>[checkedItems]=checkedExperiments() [sortFields] [lazyLoading]=true
    ExpTable->>SmTable: ng-template pTemplate="body/card/sort-filter/checkbox/cardFilter"<br/>（コンテンツとして渡す）

    SmTable->>SmTable: visibleColumns = columns().filter(col => !col.hidden)
    SmTable->>SmTable: effect: colsOrder が来たら orderColumns() で並べ替え
    SmTable->>PTable: [value]=tableData() [columns]=visibleColumns()<br/>[selectionMode] [scrollable] [virtualScroll]
    PTable-->>SmTable: viewChild(Table) で掴める
    SmTable-->>BaseTable: viewChild(TableComponent) = table()
```

`sm-table` が `p-table` に渡す `[columns]` は `visibleColumns()`。
`hidden: true` の列は**そもそも描かれない**。表示/非表示の切替はヘッダーのメニューから
`toggleColHidden` で Store と URL を書き換え、ここまで降りてくる。

## 図2: テーブルが立ち上がった後の初期処理

```mermaid
sequenceDiagram
    autonumber
    participant BaseTable as BaseTableView
    participant SmTable as sm-table
    participant PTable as p-table

    SmTable->>SmTable: effect: table() が生えたら active=true, gotTable()
    SmTable->>SmTable: gotTable() でスクロールコンテナを掴む
    SmTable->>SmTable: effect: columns() が入ったら orderColumns() + resize()
    SmTable->>PTable: calcResize() で列幅を復元（restoreColumnWidths）

    BaseTable->>BaseTable: effect: table() が生えたら1度だけ
    BaseTable->>SmTable: focusSelected()（選択行に DOM フォーカス）
    BaseTable->>SmTable: afterTableInit() → scrollToElement(選択行)
    Note over BaseTable,SmTable: この effect は自分で destroy() して二度と走らない
```

列幅の復元は `p-table` の内部 API（`columnWidthsState` / `restoreColumnWidths`）を
直接叩いている。PrimeNG の localStorage 保存機能は使わず、**幅の原本はサーバ側の
ユーザープリファレンス**にある（05-15）。
