# 05-16 追い読み

一覧は最初の 1 ページ分しか持っていない。下端まで来たら続きを読む。

ページ番号ではなく **サーバが返す `scroll_id` を持ち回る方式**。
そのため「何ページ目」という状態は存在せず、「次」しか要求できない。

## 図1: 下端の3点まで到達して追い読みするまで

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Dots as sm-dots-load-more
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as ViewEffects
    participant Api as tasks.get_all_ex

    Note over SmTable,Dots: 最終行の後ろに1行だけ置かれる<br/>lazyLoading && autoLoadMore && !noMoreData のとき表示
    User->>Dots: スクロールして到達（mouseenter でも発火）
    Dots->>SmTable: (loadMore)
    SmTable->>SmTable: loadMore() → tableSate().loading.set(true)
    SmTable->>ExpTable: autoLoadMore なので即 (loadMoreClicked)
    ExpTable->>EC: onLoadMoreClicked() → (loadMoreExperiments)
    EC->>Store: dispatch getNextExperiments

    Store->>ViewEff: getNextExperiments effect
    ViewEff->>ViewEff: 現在の scrollId を取り出す
    ViewEff->>Api: scroll_id 付きで問い合わせ
    Api-->>ViewEff: 次の 30 件（EXPERIMENTS_PAGE_SIZE）+ scroll_id
    ViewEff->>Store: setNoMoreExperiments({hasMore: 件数 < 30})<br/>※ hasMore は「まだ有る」ではない（下記）
    ViewEff->>Store: addExperiments({experiments})（既存に追加）
    ViewEff->>Store: setCurrentScrollId({scrollId})
    Store-->>SmTable: tableData() が伸びる → 3点は次の最終行の後ろへ
```

`(mouseenter)` でも読み込むのが実装上のポイント。3 点の上にカーソルが乗るだけで
読み始めるので、スクロール位置の計算をしていない。

`setNoMoreExperiments({hasMore})` の引数名は**意味が逆**なので注意。
reducer は `noMoreExperiment: action.hasMore` と入れているだけで、渡ってくる値は
`res.tasks.length < 30`、つまり「ページが埋まらなかった＝もう無い」。
これが `noMoreExperiments()` → sm-table の `[noMoreData]` まで素通しで届く。
**`hasMore` が true のとき 3 点は消える**。

`autoLoadMore` が false の経路（他画面のテーブル）では `throttleTime(1500)` の
Subject を通すので、連打しても 1.5 秒に 1 回しか飛ばない。

## 図2: セッション切れ

`scroll_id` はサーバ側で期限切れになる。

```mermaid
sequenceDiagram
    autonumber
    participant ViewEff as ViewEffects
    participant Api as tasks.get_all_ex
    participant Store as NgRx Store
    participant SmTable as sm-table

    ViewEff->>Api: scroll_id 付きで問い合わせ
    Api-->>ViewEff: 別の scroll_id が返る（= 期限切れ）
    ViewEff->>Store: setTableRefreshSessionPending({refresh: true})
    ViewEff->>Store: addMessage('Session expired')
    Note over Store,SmTable: 次の更新時に getExperimentsWithPageSize で<br/>今の件数ぶんを丸ごと取り直す
    Store-->>SmTable: [hasExperimentUpdate] が true
    SmTable->>SmTable: 3点のスピナーを止め、REFRESH LIST 表記に切り替える
```

## 図3: 読み込み中の表示

```mermaid
sequenceDiagram
    autonumber
    participant SmTable as sm-table
    participant Dots as sm-dots-load-more

    SmTable->>SmTable: tableSate = computed(() => ({table: tableData(), loading: signal(!tableData())}))
    Note right of SmTable: computed の中で signal を作るので、<br/>tableData が入れ替わるたびに loading も作り直される
    SmTable->>SmTable: loadMore() で loading.set(true)
    SmTable->>Dots: [loading]=tableSate().loading() && !hasExperimentUpdate()
    Note over SmTable,Dots: 新しいデータが届くと tableSate が作り直され、<br/>loading は自動的に初期値へ戻る（明示的な false が無い）
```

「読み込み終わったら loading を false にする」コードがどこにも無いのが最初は不気味だが、
**`computed` ごと作り直されることが解除の合図**になっている。
