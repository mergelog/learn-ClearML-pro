# 05-20 CSVダウンロード

ヘッダーのダウンロードメニューには2項目あり、**経路が全く別**。

| 項目 | 範囲 | 作る場所 |
| --- | --- | --- |
| Download on screen items | 今テーブルに読み込んである行だけ | ブラウザ（JS で文字列を組む） |
| Download first N items | サーバ側の全件（上限あり） | サーバ |

## 図1: 画面上の行だけ（ブラウザで生成）

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Header as sm-experiment-header
    participant EC as ExperimentsComponent
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table
    participant Browser as ブラウザ

    User->>Header: Download on screen items
    Header->>EC: (downloadTableAsCSV)
    EC->>ExpTable: this.table()（viewChild: ExperimentsTableComponent）
    ExpTable->>SmTable: .table()（viewChild: TableComponent）
    EC->>SmTable: downloadTableAsCSV('ClearML <プロジェクト名> Experiments')
    Note over EC,SmTable: Store も Action も通さない。<br/>viewChild を2段辿って孫のメソッドを直接呼ぶ

    SmTable->>SmTable: colsOrder → columns() を並べ替え → prepareColsForDownload()
    SmTable->>SmTable: preProcessRows()<br/>lodash get で値を取り、配列は文字列化、文字列は sanitizeCSVCell
    SmTable->>Browser: export-to-csv の generateCsv + download
```

`sanitizeCSVCell` は `= + - @ \r \t` のいずれかで始まるセルの**先頭に `'` を足す**処理。
表計算ソフトが数式として解釈するのを防ぐ（CSV インジェクション対策）。セル内の改行は別途除去している。

なぜ Store を通らないかというと、**出力対象が「今 p-table が持っている列と順序」であって
アプリの状態ではない**から。列の並びは `columnsOrder` と `columns()` を突き合わせて
その場で組み立てている。

## 図2: 全件（サーバで生成）

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Header as sm-experiment-header
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as ViewEffects
    participant OrgApi as organization.prepare_download_for_get_all
    participant ProjEff as ProjectsEffects
    participant Browser as ブラウザ

    User->>Header: Download first N items
    Header->>EC: (downloadFullTableAsCSV)
    EC->>Store: dispatch prepareTableForDownload({entityType: 'task'})

    Store->>ViewEff: prepareTableForDownload effect
    ViewEff->>ViewEff: 14 本の selector を concatLatestFrom で集める<br/>（プロジェクト、アーカイブ、検索語、並び、フィルタ、選択、列 ...）
    Note right of ViewEff: 「選択のみ表示」が有効なら selectedIds を付ける<br/>completed フィルタには closed も足す
    ViewEff->>OrgApi: field_mappings + 一覧取得と同じ条件で依頼
    OrgApi-->>ViewEff: prepare_id
    ViewEff->>Store: dispatch downloadForGetAll({prepareId})

    Store->>ProjEff: downloadForGetAll effect
    ProjEff->>Browser: a 要素を作って organization.download_for_get_all?prepare_id=... を開く
```

**画面に出ている条件をそのままサーバに渡し直している**のがこの経路の要点。
一覧取得と同じ `getGetAllQuery()` を使うので、フィルタとソートが一致する。

件数上限はヘッダーのラベルに出ている `maxDownloadItems$`（サーバの設定値）。
