# 05-03 セルまでの経路

1個のセル（「名前」「状態」「タグ」など）の中身まで。

経路が素直でないのはここ。**セルを描く指示を出すのは `p-table` だが、中身を書いているのは
`sm-experiments-table`**。間の `sm-table` はテンプレートを受け取って仕分けるだけ。

## 図1: テンプレートが下に渡り、描画で戻ってくる

```mermaid
sequenceDiagram
    autonumber
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table
    participant PTable as p-table
    participant Cell as セルの中身（sm-tag-list など）

    Note over ExpTable,SmTable: ① コンテンツとして渡す（描画前）
    ExpTable->>SmTable: ng-template pTemplate="body" を子要素として置く
    SmTable->>SmTable: contentChildren(PrimeTemplate) で集める
    SmTable->>SmTable: ngAfterContentInit で getType() を見て振り分け<br/>body → bodyTemplate, card → cardTemplate, ...

    Note over SmTable,PTable: ② 行を描く（描画時）
    SmTable->>PTable: ng-template #body（p-table の行テンプレート）
    PTable->>SmTable: 行ごとに rowData と columns を渡して呼び戻す
    SmTable->>SmTable: 列ごとに td を作る
    SmTable->>ExpTable: ngTemplateOutlet bodyTemplate<br/>context: 列 col, rowData, rowIndex

    Note over ExpTable,Cell: ③ 中身を決める
    ExpTable->>ExpTable: @switch (col.id)
    ExpTable->>Cell: 列に応じた部品を生成
```

`bodyTemplate` が無い場合は `{{ getBodyData(rowData, col) }}`（lodash の `get`）で
素のテキストを出すフォールバックがある。experiments-table は必ず渡すのでここは通らない。

## 図2: 列 ID ごとの行き先

```mermaid
sequenceDiagram
    autonumber
    participant Tpl as pTemplate="body"
    participant Type as sm-experiment-type-icon-label
    participant Tags as sm-tag-list
    participant Status as sm-status-icon-label
    participant Check as mat-checkbox
    participant Metric as sm-hyper-param-metric-column

    Tpl->>Tpl: col.id で分岐
    Tpl->>Type: type 列
    Tpl->>Tags: tags 列（[tags] と [sysTags] を分けて渡す）
    Tpl->>Status: status 列（progress でスピナー表示）
    Tpl->>Check: selected 列（チェックボックス → 05-12）
    Tpl->>Metric: @default = メトリクス列 / ハイパーパラメータ列
    Note over Tpl,Metric: name / id / user / project / started などは<br/>div + ellipsis + smShowTooltipIfEllipsis で直接描く
```

`@default` に落ちるのがユーザーが後から足した列（`last_metrics.*` と `hyperparams.*`）。
列 ID が固定でないので `switch` に書けず、値の取り出しは `col.getter` に任せている。

## 状態の要点

- 行データ `experiments` は Store → EC → experiments-table の input signal → p-table の `[value]`。
  **セルは値を受け取るだけで、Store を見ない**。
- メトリクス値の丸め判定（`roundedMetricValues`）は experiments-table の `computed`。
  行×列を全部なめるので、experiments か tableCols が変わったときだけ再計算される。
- チェック状態は `checkedExperiments() | isRowSelected:experiment` というパイプ。
  配列を毎回なめるが、パイプなので参照が変わらない限り再評価されない。
