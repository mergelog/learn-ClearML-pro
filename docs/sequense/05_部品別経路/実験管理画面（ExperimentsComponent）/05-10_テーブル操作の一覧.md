# 05-10 テーブル操作の一覧

ここから 05-20 まではテーブルの操作単位。まず全体の形と一覧を置く。

## 操作の共通形

ほとんどの操作が次の形をとる。**3層を下から上に登り、EC で初めて Action になる**。

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Part as 列ヘッダー / セル / カード
    participant PTable as p-table
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table<br/>（+ BaseTableView）
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    User->>Part: 操作
    Part->>PTable: DOM イベント（またはテンプレート内で直接ハンドラ）
    PTable->>SmTable: PrimeNG のイベント
    SmTable->>SmTable: 正規化（型を整える・二重クリック判定など）
    SmTable->>ExpTable: output
    ExpTable->>ExpTable: Task 固有の判断（範囲選択・列 ID 別の分岐）
    ExpTable->>EC: output
    EC->>Store: dispatch
    Note over EC,Store: ここで初めて「アプリの状態」になる。<br/>下の3層は誰も Store に書かない
```

例外が3つある。覚えておくと迷わない。

| 例外 | 何が違うか |
| --- | --- |
| 全選択メニュー（05-12） | experiments-table が自分で `store.dispatch()` する |
| フィルタメニューを開く（05-14） | 同じく experiments-table が dispatch する |
| ハイライト行（05-11） | EC がローカル signal に持ち、Store に出さない |

前2つは `BaseTableView` が `inject(Store)` を持っているため。表示部品としては例外的だが、
「メニューを開いた瞬間に選択肢を取りに行く」だけの用途に限られている。

## URL を経由する操作に注意

ソート・フィルタ・列構成は **Store を直接書き換えない**。
`dispatch` → effect が `setURLParams` → Router がクエリパラメータを書き換え →
EC がそれを購読して改めて `setTableSort` などを dispatch、という一周をする。

```mermaid
sequenceDiagram
    autonumber
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as CommonExperimentsViewEffects
    participant RouterEff as RouterEffects
    participant Router as Angular Router

    EC->>Store: dispatch tableSortChanged / tableFilterChanged
    Store->>ViewEff: 受け取り、現在値と合成
    ViewEff->>Store: dispatch setURLParams({orders, filters, update: true})
    Store->>RouterEff: 受け取り
    RouterEff->>Router: router.navigate([], {queryParams, queryParamsHandling: merge})
    Router-->>EC: route.queryParams が発火
    EC->>Store: dispatch setTableSort / setTableFilters（ここで Store が変わる）
    Store->>ViewEff: reFetchExperiment が再取得
    Note over EC,ViewEff: リロードしても同じ表になる代わりに、<br/>1操作で2周ぶんのログが出る
```

この一周があるので、**Store の値を直接書き換えるデバッグは効かない**。URL を見るのが早い。
EC 側の受け口は [experiments.component.ts:284](../../../../src/app/webapp-common/experiments/experiments.component.ts#L284) の `distinctParamsUntilChanged$` の購読。
