# 05-11 行クリックとダブルクリック

同じ「行を押す」操作が、表示モードで3通りに分かれる。

| 状況 | 結果 | 状態の行き先 |
| --- | --- | --- |
| テーブル表示（広い状態）で1回クリック | 行がハイライトされるだけ | EC のローカル signal |
| 縮小表示（情報パネルが開いている）でクリック | 選択が切り替わりパネルが更新 | URL |
| ダブルクリック | 情報パネルが開く | URL |
| チェック済みの行をクリック | コンテキストメニューが開く（05-17） | - |

## 図1: シングルとダブルの判定

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Tr as tr（p-table の行）
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table

    User->>Tr: click
    Tr->>SmTable: checkClick({e, data})
    SmTable->>SmTable: waitForClick に 250ms タイマーを仕掛ける

    alt 250ms 以内に2回目が来た
        User->>Tr: dblclick（または2回目の click）
        Tr->>SmTable: checkClick
        SmTable->>SmTable: タイマーを破棄
        SmTable->>ExpTable: (rowDoubleClicked)
    else 来なかった
        SmTable->>ExpTable: (rowClicked)
    end
    Note over SmTable,ExpTable: 縮小表示のときは tr の click 自体を無効化<br/>（!minimizedView() && checkClick）
```

シングルクリックが必ず 250ms 遅れる。**ハイライトの反応が一瞬遅いのは仕様**で、
ダブルクリックのときにパネルを開く前に一度ハイライトさせないための作り。

## 図2: rowClicked のあと

```mermaid
sequenceDiagram
    autonumber
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    ExpTable->>ExpTable: tableRowClicked({e, data})
    ExpTable->>EC: selectionMode が single なら<br/>(experimentSelectionChanged) {experiment, origin: 'row'}
    Note right of ExpTable: チェック済みの行なら、続けて<br/>openContextMenu(backdrop: true) も呼ぶ

    EC->>EC: getTableModeFromURL() が compare なら何もしない
    EC->>EC: experimentSelectionChanged()

    alt minimizedView() または openInfo
        EC->>Store: dispatch experimentSelectionChanged
        Note right of Store: ViewEffects が router.navigate<br/>→ URL に experimentId が載る
    else origin === 'row'
        EC->>EC: selectionState().highlited.update(...)
        Note right of EC: Store に出さないローカル signal。<br/>同じ行をもう一度押すと null に戻る（トグル）
    end
```

`highlited` は `computed` の中で `signal()` を作るという珍しい書き方をしている。

```
selectionState = computed(() => ({
  prevExperiment: this.previousTableExperiment(),
  highlited: signal(this.selectedTableExperiment() ?? this.previousTableExperiment())
}));
highlited = computed(() => this.tableMode() === 'compare' ? null : this.selectionState().highlited());
```

`selectedTableExperiment`（Store 由来）が変わるたびに **signal ごと作り直される**ので、
「Store から来た選択を初期値にして、以降はローカルで上書きできる値」になる。
比較モードではハイライトを出さないので `null` を返す。

## 図3: p-table 自身の選択（rowSelectionChanged）

行には `pSelectableRow` も付いているので、PrimeNG 側の選択イベントも同時に流れる。

```mermaid
sequenceDiagram
    autonumber
    participant Tr as tr（pSelectableRow）
    participant PTable as p-table
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent

    Tr->>PTable: 選択
    PTable->>SmTable: (onRowSelect)
    SmTable->>SmTable: onRowSelected() で同じ行なら data: null にして返す（選択解除）
    SmTable->>ExpTable: (rowSelectionChanged)
    ExpTable->>EC: (experimentSelectionChanged) {origin: 'table'}
    Note over SmTable,EC: origin が 'table' なので EC はハイライト更新をせず、<br/>縮小表示のときだけパネルを切り替える
```

`origin` が `'row'`（人が行をクリック）と `'table'`（p-table の選択機構やキーボード操作）を
区別しているのがポイント。同じ output を2つの経路が共有しているため、EC 側で振り分けている。
