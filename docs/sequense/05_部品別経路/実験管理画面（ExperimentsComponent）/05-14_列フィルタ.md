# 05-14 列フィルタ

漏斗アイコンのメニュー。ソート（05-13）と同じく URL を一周するが、
**「選択肢を取ってくる」という別の流れが手前にある**のが違い。

## 図1: メニューを開く（選択肢の用意）

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant FilterSort as sm-table-filter-sort
    participant ExpTable as sm-experiments-table
    participant Store as NgRx Store
    participant EC as ExperimentsComponent

    User->>FilterSort: 漏斗をクリック
    FilterSort->>FilterSort: onMenuOpen() → pinnedValues.set(value())
    Note right of FilterSort: 開いた瞬間の選択値を固定。<br/>チェックを外しても並びが飛ばない
    FilterSort->>ExpTable: (menuOpened)
    opt 手元の options() が空
        FilterSort->>FilterSort: searchChanged(searchValue()) を自分で呼ぶ
        FilterSort->>ExpTable: (searchValueChanged) → 図3 の検索経路へ
    end
    ExpTable->>ExpTable: columnFilterOpened(col)<br/>sortByFilterValues.set(filtersValues())

    alt tags 列
        ExpTable->>EC: 選択肢が空なら (tagsMenuOpened)
        EC->>Store: dispatch getTags
    else hyperparams.* 列
        ExpTable->>Store: dispatch hyperParamSelectedInfoExperiments<br/>+ setHyperParamsFiltersPage + hyperParamSelectedExperiments
        Note right of ExpTable: ここも表示部品から直接 dispatch
    else project.name 列
        ExpTable->>EC: 選択肢が空なら (filterSearchChanged) {colId, value: {value: ''}}
        EC->>Store: dispatch getTablesFilterProjectsOptions
    end

    Store-->>ExpTable: 選択肢が届く
    ExpTable->>FilterSort: [options]=filtersOptions()[col.id]
    FilterSort->>FilterSort: effect: options() が来たら loading/searching を false に
```

status / type のように選択肢が固定の列は何も取りに行かない。
`filtersOptions()` は固定リストと Store 由来のリストを混ぜた 1 個の `computed`。

選択肢を取りに行く入口が2つある点に注意。experiments-table の `columnFilterOpened()` と、
FilterSort 自身の `onMenuOpen()`（手元が空のときだけ）で、**列によっては両方走る**。

## 図2: 値をチェックして絞り込むまで

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant List as sm-checkbox-three-state-list
    participant FilterSort as sm-table-filter-sort
    participant BaseTable as BaseTableView
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as ViewEffects

    User->>List: 値をチェック（3状態: 含む / 除外 / なし）
    List->>FilterSort: (filterChanged) 新しい値の配列
    FilterSort->>FilterSort: emitFilterChanged() で andFilter を添える
    FilterSort->>BaseTable: (filterChanged) {value, andFilter}
    BaseTable->>BaseTable: tableFilterChanged(col, event) → scrollTableToTop()
    BaseTable->>EC: (filterChanged) {col, value, andFilter}
    EC->>Store: dispatch tableFilterChanged({filters: [{col, value, filterMatchMode}], projectId})

    Store->>ViewEff: tableFilterChange → 既存フィルタとマージ
    ViewEff->>Store: dispatch setURLParams({filters, update: true})
    Note over ViewEff,Store: 以降 URL → EC → setTableFilters → 再取得（05-10 図参照）
    Store->>ViewEff: reFetchExperiment は tableFilterChanged 自体も購読していて、<br/>URL の一周を待たずに取得が始まる
```

タグ列の Any / All 切替（`andFilter`）は `model()` なので、押した瞬間にコンポーネント内の値が
変わり、同時に `filterChanged` も飛ぶ。`filterMatchMode: 'AND'` として Store に載る。

## 図3: 選択肢の検索とページング

選択肢が多い列（親タスク、プロジェクト、ハイパーパラメータ値）はサーバ検索になる。

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant FilterSort as sm-table-filter-sort
    participant BaseTable as BaseTableView
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    User->>FilterSort: 検索欄に入力
    FilterSort->>FilterSort: searchChanged() → pageNumber=1, searching=true
    FilterSort->>BaseTable: (searchValueChanged) {value}
    BaseTable->>BaseTable: searchValues[colId] = value（ただのオブジェクト）
    BaseTable->>EC: col.asyncFilter のときだけ (filterSearchChanged)
    EC->>EC: override filterSearchChanged()
    alt parent.name
        EC->>Store: dispatch resetTablesFilterParentsOptions + getParents({searchValue})
    else hyperparams.*
        EC->>Store: dispatch setHyperParamsFiltersPage({page: 0}) + hyperParamSelectedExperiments
    else project.name
        EC->>Store: 基底の実装 → getTablesFilterProjectsOptions
    end

    User->>FilterSort: 3点（もっと読む）
    FilterSort->>FilterSort: loadMore()
    FilterSort->>FilterSort: loading() か noMoreOptions() なら即 return
    alt asyncFilter でない
        FilterSort->>FilterSort: pageNumber++ だけ（手元の配列を多く見せる）
    else asyncFilter
        FilterSort->>FilterSort: lengthBeforeLoad を記録し pageNumber++ して loading=true
        FilterSort->>EC: (searchValueChanged) {value, loadMore: true}
        Note right of FilterSort: 返ってきた件数が増えていなければ<br/>noMoreOptions() が true になり 3点が消える
    end
```

`searchValues` が signal ではなく素の `Record<string, string>` である点が引っかかりやすい。
OnPush でも動くのは、**値を書き換えるのが必ずイベントハンドラの中**で、
その場でそのビューの変更検知が走るため。

## 図4: フィルタを消す

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Src as ヘッダーの Clear / メニューの Clear all / 0件表示のリンク
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    User->>Src: クリック
    Src->>EC: (clearTableFilters) または (clearTableFiltersAndSearch)
    EC->>EC: clearTableFiltersHandler(tableFilters, others?)
    EC->>Store: dispatch setTableFilters({filters: []})
    EC->>Store: dispatch tableFilterChanged({filters: 全列を空配列, others})
    Note over EC,Store: setTableFilters で即座に画面を空に、<br/>tableFilterChanged で URL の filter を消す
```

0 件のときに出る「Clear filters」は `#noDataTemplate` の中のリンク。
このテンプレートは experiments-table が宣言し、`[noDataTemplate]` として sm-table に渡され、
p-table の `#emptymessage` から呼び戻される（セルと同じ投影の形）。
検索語も一緒に消すのが `clearTableFiltersAndSearch`（`others: {q: null}`）。
