05-12 チェックボックス選択と全選択

一括操作の対象（checkedExperiments）を決める操作。ハイライト（05-11）とは別系統で、 こちらは Store に入る。

図1: 行のチェックボックス

sequenceDiagram
    autonumber
    participant User
    participant Cb as mat-checkbox（selected 列）
    participant ExpTable as sm-experiments-table
    participant BaseTable as BaseTableView
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    User->>Cb: クリック
    Note right of Cb: smClickStopPropagation で<br/>行クリックまで伝わらないようにする
    Cb->>ExpTable: rowSelectedChanged({value: cb.checked, event}, experiment)

    alt チェックを付けた
        ExpTable->>BaseTable: getSelectionRange(change, experiment)
        BaseTable-->>ExpTable: Shift 押下なら prevSelected から今の行までの配列
        ExpTable->>EC: (experimentsSelectionChanged) 既存 + 追加分
    else チェックを外した
        ExpTable->>BaseTable: getDeselectionRange(change, experiment)
        ExpTable->>EC: (experimentsSelectionChanged) 除外後の配列
    end

    EC->>Store: dispatch setSelectedExperiments({experiments})
    Store->>Store: reducer が selectedExperiments を置き換え
    Note over EC,Store: effect が選択内容から「どのボタンが押せるか」を<br/>計算して setSelectedExperimentsDisableAvailable を返す

cb.checked を読んでいるのは (click) で拾っているため。(change) ではなく (click) なのは event.shiftKey が必要だから。Shift 範囲選択のために、チェックボックスの標準イベントを使っていない。

範囲の起点 prevSelected / prevDeselect は BaseTableView のただのプロパティ。 再描画や再取得で消えるが、Shift 選択の起点としてはそれで十分という判断。

図2: ヘッダーのチェックボックス

sequenceDiagram
    autonumber
    participant Store as NgRx Store
    participant BaseTable as BaseTableView
    participant Cb as mat-checkbox（ヘッダー）
    participant User
    participant EC as ExperimentsComponent

    Store-->>BaseTable: experiments() と checkedExperiments()
    BaseTable->>BaseTable: selectionState = All / Partial / None を computed
    BaseTable->>Cb: effect → selectionChecked.setValue(state !== 'None')
    BaseTable->>Cb: [indeterminate]=selectionIndeterminate()（Partial のとき）

    User->>Cb: クリック
    Cb->>BaseTable: headerCheckboxClicked()
    BaseTable->>BaseTable: None だった → unionBy(表示中の全件, 既存選択, 'id')<br/>それ以外 → 空配列
    BaseTable->>EC: emitSelection() → (experimentsSelectionChanged)
    EC->>Store: dispatch setSelectedExperiments

selectionState が this[this.entitiesKey]() という文字列アクセスで書かれている。 BaseTableView は Task を知らないので、派生クラスが

override entitiesKey = 'experiments';
override selectedEntitiesKey = 'checkedExperiments';

と名前を教える。基底クラスが input signal をキー名で引くため型が効かない箇所で、 読むときは必ずこの2行を先に見る。

図3: ドロップダウンの All / None / All matching filter

ここだけ EC を経由しない。

sequenceDiagram
    autonumber
    participant User
    participant Menu as mat-menu（チェックボックス横の矢印）
    participant ExpTable as sm-experiments-table
    participant Store as NgRx Store
    participant ViewEff as CommonExperimentsViewEffects
    participant Api as tasks.get_all_ex

    User->>Menu: All または All matching filter
    Menu->>ExpTable: selectAll(filtered?)
    ExpTable->>Store: dispatch selectAllExperiments({filtered})
    Note right of ExpTable: BaseTableView が inject(Store) を持つので<br/>表示部品から直接投げている

    Store->>ViewEff: selectAll effect
    ViewEff->>Api: 1ページ 5000 件で問い合わせ<br/>filtered なら現在のフィルタを適用
    Api-->>ViewEff: tasks + scroll_id
    ViewEff->>Api: expand() で 5000 件ちょうどなら次ページも取る
    ViewEff->>Store: reduce で全部繋げて setSelectedExperiments

    User->>Menu: None
    Menu->>ExpTable: emitSelection([])
    ExpTable->>Store: EC 経由で setSelectedExperiments({experiments: []})

only_fields を name / parent / status / type などに絞って投げている。 一括操作の可否判定に必要な項目だけなので、画面に出ていない行も選択できる。

選択上限は selectionReachedLimit input（getSelectedExperiments effect 側では 100 件に スライスしている箇所もある）。上限に達すると未チェックの行のチェックボックスが disabled になる。
