05-13 列ソート

列名の左の矢印を押したときの流れ。

PrimeNG のソート機能は使っていない。並べ替えはサーバ側で行い、 クライアントは「どの列をどの向きで」を URL に書くだけ。

図1: 列ヘッダーから一周して再取得まで

sequenceDiagram
    autonumber
    participant User
    participant FilterSort as sm-table-filter-sort
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as ViewEffects
    participant Router as Router
    participant Api as tasks.get_all_ex

    User->>FilterSort: ソートボタン（または列名）をクリック
    FilterSort->>FilterSort: switchSortOrder($event)
    FilterSort->>ExpTable: (sortOrderChanged) = $event.shiftKey
    ExpTable->>ExpTable: onSortChanged(isShift, col.id)
    ExpTable->>ExpTable: scrollTableToTop()（table().table().scrollTo({top: 0})）
    ExpTable->>EC: (sortedChanged) {isShift, colId}
    EC->>Store: dispatch tableSortChanged

    Store->>ViewEff: tableSortChange
    ViewEff->>ViewEff: addMultipleSortColumns(現在の並び, colId, isShift)
    ViewEff->>Store: dispatch setURLParams({orders, update: true})
    Store->>Router: RouterEffects が queryParams.order を書き換え
    Router-->>EC: route.queryParams 発火
    EC->>Store: dispatch setTableSort({orders, projectId})
    Store->>ViewEff: reFetchExperiment（setTableSort を購読）
    ViewEff->>Api: order_by 付きで再取得
    Api-->>Store: setExperiments で差し替え

ソート矢印の見た目は Store の tableSortFields から tableSortFieldsObject() で 列 ID 別に引いた値。押した瞬間には変わらず、URL が書き換わって Store に戻ってきてから変わる。

図2: Shift クリックの多段ソート

sequenceDiagram
    autonumber
    participant User
    participant FilterSort as sm-table-filter-sort
    participant ViewEff as ViewEffects

    User->>FilterSort: 列 A をクリック
    FilterSort->>ViewEff: isShift = false
    ViewEff->>ViewEff: 既存を捨てて [A 昇順] に

    User->>FilterSort: 列 A をもう一度
    ViewEff->>ViewEff: [A 降順]（向きだけ反転）

    User->>FilterSort: Shift + 列 B
    FilterSort->>ViewEff: isShift = true
    ViewEff->>ViewEff: [A 降順, B 昇順] と積む
    Note over FilterSort,ViewEff: 矢印の横に出る番号が orders 配列の index

判定は全部 addMultipleSortColumns の中。コンポーネント側は shiftKey の真偽を そのまま渡すだけで、何列目かの管理はしていない。

図3: カード表示のソート

縮小表示では列ヘッダーが無いので、ヘッダー帯のメニューから同じ経路に入る。

sequenceDiagram
    autonumber
    participant User
    participant Menu as sm-menu "SORTED BY"
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table

    SmTable->>SmTable: sortableCols = (initialColumns() ?? visibleColumns()).filter(col => col.sortable)
    User->>Menu: 項目をクリック
    Menu->>SmTable: sortItemClick($event, col.id)
    SmTable->>ExpTable: (sortChanged) {isShift: $event.event.shiftKey, field: colId}
    ExpTable->>ExpTable: onSortChanged($event.isShift, $event.field)
    Note over SmTable,ExpTable: 以降は図1と同じ

sortableCols が initialColumns() から作られている点に注意。 表示中の列ではなく列定義の全部なので、隠している列でもソートできる。 initialColumns を渡していないテーブルだけ visibleColumns() に落ちる（experiments-table は渡すので落ちない）。

状態の要点

  • 原本は URL の order（encodeOrder でエンコード）。リロードしても復元される。
  • Store の tableSortFields は URL の写し。初期値は INITIAL_EXPERIMENT_COLS_ORDER。
  • サーバ設定にも保存される（setUserPreferences effect が setTableSort を購読）ので、 次回この画面を URL 無しで開くと前回の並びが復元される。
