05-15 列の並べ替えと幅変更

th に付いた2つのディレクティブが入口。似た操作だが保存先が違う。

操作 保存先
列の移動 URL の columns ＋ サーバのユーザープリファレンス
列幅の変更 サーバのユーザープリファレンスのみ（URL に出ない）

図1: 列をドラッグして移動

sequenceDiagram

    participant User
    participant Th as th（pReorderableColumn）
    participant PTable as p-table
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store as NgRx Store
    participant ViewEff as ViewEffects

    User->>Th: ヘッダーをドラッグして落とす
    Note right of Th: col.disableDrag の列は pReorderableColumnDisabled
    Th->>PTable: 並べ替え
    PTable->>SmTable: (onColReorder) 並び替え後の columns
    SmTable->>SmTable: onColReorder() → 列 ID の配列にして resize()
    SmTable->>ExpTable: (colReordered) string[]
    ExpTable->>EC: (columnsReordered) そのまま素通し
    EC->>Store: dispatch setColsOrderForProject({cols: Array.from(new Set([...cols, 'project.name'])), projectId})
    EC->>Store: dispatch updateUrlParams

    Store->>ViewEff: setUserPreferences（setColsOrderForProject を購読）
    ViewEff->>ViewEff: userPreferences.setPreferences(パス, 値)
    Store->>ViewEff: setURLParams（updateUrlParams を購読）
    ViewEff->>Store: encodeColumns() した結果を URL へ
    Store-->>SmTable: colsOrder() が更新 → effect が orderColumns()

'project.name' を必ず末尾に足しているのは、プロジェクト列が条件次第で表示/非表示に なるため（全プロジェクト表示や deep モードのときだけ出る）。 並び順の配列に居ないと、出てきたときに位置が決まらない。 new Set を噛ませているのは、すでに並びに居るときに二重登録しないため。

orderColumns() は visibleColumns() の配列を sort() で破壊的に並べ替えている。 computed の戻り値を直接ソートしているので、ここは素直な書き方ではない。

図2: 列幅をドラッグして変える

    User->>Th: 境界をドラッグ
    Th->>PTable: ResizableColumn の処理（PrimeNG 継承）
    PTable->>SmTable: (onColResize) {delta, element}
    SmTable->>SmTable: colResize() → data-col-id 属性から列 ID を逆引き
    SmTable->>ExpTable: (columnResized) {columnId, widthPx}
    ExpTable->>EC: そのまま素通し
    EC->>Store: dispatch setColumnWidth({columnId, widthPx, projectId})
    Store->>Store: setUserPreferences effect がサーバに保存
    Note over EC,Store: URL には出ないので、リンクを共有しても幅は伝わらない

列 ID を DOM の data-col-id 属性から引いているのは、PrimeNG が渡してくるのが HTMLElement だけだから。列オブジェクトを辿れないので DOM に埋めた ID を読む、という回避。

図4: メトリクス列の展開ボタン

メトリクスのセルにある展開アイコンは、幅を「押し広げる」独自経路を通る。

sequenceDiagram
    autonumber
    participant User
    participant Metric as sm-hyper-param-metric-column
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table
    participant EC as ExperimentsComponent

    User->>Metric: 展開クリック
    Metric->>ExpTable: (expandClicked) {columnId, width}
    ExpTable->>ExpTable: columnsWidthChanged() で tableCols() から差分を計算
    ExpTable->>SmTable: table().updateColumnsWidth(columnId, width, delta)
    SmTable->>SmTable: 受け取った delta は使わず visibleColumns() から計算し直す
    SmTable->>SmTable: 当該列を広げ、隣の列を同じ分だけ縮める（最小 30px）
    SmTable->>ExpTable: 全列ぶん (columnResized) を emit
    ExpTable->>EC: 全列ぶん columnResized
    EC->>EC: 列ごとに dispatch setColumnWidth
    Note over SmTable,EC: 1回の操作で列数ぶんの Action が出る

updateColumnsWidth は先頭で delta = width - parseInt(columns[colIndex].style?.width, 10) と 引数の delta を上書きする。呼び出し側が計算した値は捨てられるので、 columnsWidthChanged() の差分計算を追っても幅の結果は説明できない。見るなら updateColumnsWidth の中。
