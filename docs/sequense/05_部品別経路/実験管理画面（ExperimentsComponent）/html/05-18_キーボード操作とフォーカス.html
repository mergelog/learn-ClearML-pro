05-18 キーボード操作とフォーカス

上下キーでの行移動と、選択行を見える位置に保つ処理。 この2つは同じ「フォーカス」という仕組みに乗っているので一緒に扱う。

図1: 上下キーで行を移動

sequenceDiagram
    autonumber
    participant User
    participant SmTable as sm-table
    participant ExpTable as sm-experiments-table
    participant EC as ExperimentsComponent
    participant Store as NgRx Store

    User->>SmTable: ArrowDown / ArrowUp
    SmTable->>SmTable: @HostListener('keydown')<br/>keyboardControl() が false なら何もしない
    SmTable->>SmTable: preventDefault() → incrementIndex(±1)
    SmTable->>SmTable: getCurrentIndex()（selection() の id で探す）

    alt 残り3件未満で、まだ続きがある
        SmTable->>SmTable: loadMore()（05-16）
    end

    SmTable->>ExpTable: (rowSelectionChanged) {data: 次の行}
    ExpTable->>EC: (experimentSelectionChanged) {origin: 'table'}
    EC->>Store: 縮小表示なら dispatch experimentSelectionChanged（URL が動く）

    SmTable->>SmTable: setTimeout 0 で .table-card.selected か tr.ui-state-highlight を探す
    SmTable->>SmTable: scrollIntoView({block: 'nearest'})

キー操作は sm-table のホスト要素が受けるので、テーブル内のどこかに DOM フォーカスが 無いと反応しない。そのためのフォーカス当てが図2。

incrementIndex の中で「残り3件を切ったら追い読み」を判断しているので、 キーを押し続けるだけで無限スクロールが進む。

図2: 選択行にフォーカスとスクロールを合わせる

sequenceDiagram
    autonumber
    participant BaseTable as BaseTableView
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table

    Note over BaseTable: ① 初回のみ
    BaseTable->>BaseTable: effect: table() が生えたら
    BaseTable->>SmTable: setTimeout 0 → focusSelected()<br/>（.selected の要素に focus()）
    BaseTable->>BaseTable: afterTableInit() → setTimeout 200 → scrollToElement(選択行)
    BaseTable->>BaseTable: この effect を destroy() して二度と走らせない

    Note over ExpTable: ② 選択が変わるたび
    ExpTable->>ExpTable: effect: prevExperiment()?.id !== selectedExperiment()?.id
    ExpTable->>SmTable: setTimeout 0 → contextMenuActive() でなければ focusSelected()
    Note right of ExpTable: メニューが開いている間は奪わない<br/>（メニュー内の入力欄からフォーカスが飛ぶため）

    Note over SmTable: ③ スクロール位置の計算
    SmTable->>SmTable: scrollToElement → tableData から index を求める
    SmTable->>SmTable: virtualScroll なら scrollToVirtualIndex、<br/>そうでなければ tr の offsetTop まで smooth スクロール

computedPrevious(this.selectedExperiment) で「1つ前の値」を作り、id が変わったときだけ フォーカスし直している。同じタスクのデータが更新されただけではフォーカスを動かさない。

図3: パネル開閉のあとの再計算

sequenceDiagram
    autonumber
    participant Split as as-split

    Split->>EC: (transitionEnd)（幅アニメーション完了）
    EC->>SmTable: experimentsTable.table()?.resize(100)
    EC->>ExpTable: experimentsTable.afterTableInit()
    ExpTable->>SmTable: scrollToElement(選択行)
    Note over EC,SmTable: テンプレートから孫の公開メソッドを直に呼んでいる。<br/>実 DOM の幅が必要なのでアニメーション中は測れない
