このファイルは、ClearML の「Experiments / Tasks 一覧画面」を統括するコンテナコンポーネントです。

テーブル自身の描画ロジックよりも、次の要素をつなぐ役割を担当しています。

- NgRx Store
- URL・ルーティング
- Experiment一覧テーブル
- 詳細／比較パネル
- フィルター・ソート・列設定
- 一括操作フッター
- コンテキストメニュー

対象: [experiments.component.ts](experiments.component.ts:142)

## 全体構造

```text
URL / ユーザー操作
        ↓
ExperimentsComponent
        ↓ dispatch
NgRx Actions → Effects/API → Reducer
        ↓
Selectors
        ↓
ExperimentsComponent
        ↓ Input
Header / Table / Detail / Footer / Context Menu
```

このコンポーネントはAPIを直接呼びません。基本的に `store.dispatch(...)` でActionを発行し、StoreのSelectorから結果を受け取ります。

## 2. Storeから画面状態を取得

[experiments.component.ts:177](experiments.component.ts:177)

Storeの状態は、主に2種類の形式で取得しています。

- `store.select(...)` → `Observable`
- `store.selectSignal(...)` → Angular Signal

代表例は次のとおりです。

```ts
protected tableFilters$ =
  this.store.select(selectTableFilters);

override tableMode =
  this.store.selectSignal(selectTableMode);
```

主な状態は以下です。

| 状態 | 用途 |
|---|---|
| `experiments$` | 表示するExperiment一覧 |
| `checkedExperiments$` | チェックボックスで選択したExperiment |
| `tableFilters$` | テーブルフィルター |
| `tableSortFields$` | ソート条件 |
| `tableCols$` | 表示対象の列 |
| `tags$` | タグ候補 |
| `parents$` | 親Task候補 |
| `metricVariants$` | Metric列候補 |
| `hyperParams$` | Hyperparameter列候補 |
| `tableMode` | `table` / `info` / `compare` |

`experiments$` では、Storeの一覧をそのまま表示せず、現在のアーカイブモードに合わせて追加フィルタリングしています。

```ts
map(([experiments]) =>
  filterArchivedExperiments(
    experiments,
    this.inArchivedMode()
  )
)
```

## 3. 選択状態とハイライト

[experiments.component.ts:228](experiments.component.ts:228)

この画面には、似ていますが異なる2種類の選択があります。

- `checkedExperiments`
  - 一括操作や比較対象としてチェックされたExperiment
- `selectedTableExperiment` / `highlited`
  - テーブル上で現在フォーカス・ハイライトされているExperiment

```ts
protected selectedTableExperiment = toSignal(
  this.store.select(selectSelectedTableExperiment)
);

private previousTableExperiment =
  computedPrevious(this.selectedTableExperiment);
```

直前のExperimentを保持しているため、詳細画面との切り替え中にStore上の選択が一時的に消えても、ハイライトを維持できます。

比較モードでは通常の単一行ハイライトを無効にします。

```ts
protected highlited = computed(() =>
  this.tableMode() === 'compare'
    ? null
    : this.selectionState().highlited()
);
```

## 5. URLと画面モードの同期

この画面には3モードあります。

| モード | 意味 |
|---|---|
| `table` | 一覧のみ |
| `info` | 一覧＋Experiment詳細 |
| `compare` | 複数Experiment比較 |

URLからモードを判定するのが次のメソッドです。

[experiments.component.ts:523](experiments.component.ts:523)

```ts
public getTableModeFromURL() {
  if (!this.route.snapshot.firstChild) {
    return 'table';
  }

  return this.route.snapshot.firstChild?.url[0].path === 'compare'
    ? 'compare'
    : this.route.snapshot.firstChild?.routeConfig.path === undefined
      ? 'table'
      : 'info';
}
```

`selectExperimentFromUrl()` は、URL、Experiment一覧、Store上のモードを同期します。

[experiments.component.ts:479](experiments.component.ts:479)

主な処理は以下です。

- URLの `experimentId` に該当するExperimentを探す
- 比較URLの `ids` から比較対象を読み込む
- 詳細表示対象が未指定なら先頭Experimentを選択する
- URLとStoreの `tableMode` を一致させる
- 選択ExperimentをStoreへ登録する

`modeChanged()` は逆方向、つまり画面操作からURL・Storeを更新します。

## 9. 操作可能／不可能の判定

[experiments.component.ts:741](experiments.component.ts:741)

`getSingleSelectedDisableAvailable()` は、Experimentの状態から各操作が可能かを計算します。

例えば次のような制約です。

- 実行中でなければAbortできない
- Queue待ちでなければDequeueできない
- 読み取り専用なら削除・移動できない
- Pipelineとして実行可能か

複数選択時の判定結果はStoreの `selectSelectedExperimentsDisableAvailable` から取得します。

## 要点

このコンポーネントの本質は、次の3つです。

1. Storeの状態を各UIコンポーネントへ渡す
2. UIイベントをNgRx Actionへ変換する
3. URLとStoreの選択・表示モード・テーブル設定を同期する

したがって、一覧取得そのものを追う場合は `getExperiments` のEffect、状態更新を追う場合は `./reducers`、実際のテーブル描画を追う場合は `ExperimentsTableComponent` を次に確認すると理解しやすいです。
