# 実験管理画面の検索・ステータス・タグ絞り込みの構成

## Q. 検索・ステータス・タグ絞り込みは、それぞれ別クラスで振る舞いを管理しているか

一部だけ別クラスです。

- **検索**と**列の絞り込み（ステータス・タグ）**は別系統です。UIクラス、URLパラメータ、Storeの保存先がそれぞれ異なります。
- **ステータスとタグは別クラスではありません。** 同じ `TableFilterSortComponent` が列ごとに1つずつ生成されます。振る舞いの違いは、列定義（`ISmCol`）のフラグと、親の `ExperimentsTableComponent` が渡す選択肢・現在値で決まります。ステータス専用やタグ専用のクラスはありません。
- 検索と絞り込みは、API呼び出しの直前に `getGetAllQuery()` で1つのリクエスト（`tasks.get_all_ex`）にまとめられます。

| 項目 | 検索 | ステータス絞り込み | タグ絞り込み |
|---|---|---|---|
| UIクラス | `CommonSearchComponent`（入力欄は `SearchComponent`） | `TableFilterSortComponent` + `CheckboxThreeStateListComponent` | 左と同じ |
| 配置場所 | ヘッダー（`ExperimentHeaderComponent`） | テーブルの列ヘッダー | テーブルの列ヘッダー |
| 振る舞いの違いを決めるもの | ― | 列定義の `filterable` | 列定義の `filterable` `searchableFilter` `paginatedFilterPageSize` `excludeFilter` `andFilter` |
| URLパラメータ | `q`、`qreg` | `filter` | `filter` |
| Storeの保存先 | `commonSearch.searchQuery` → `experimentsView.globalFilter` | `experimentsView<br> .projectColumnFilters[projectId]<br>.status` | `experimentsView.projectColumnFilters[projectId].tags`（システムタグは `system_tags`） |
| APIパラメータ | `_any_` | `status` | `filters.tags`、`system_tags` |

## コンポーネント構成

```text
ExperimentsComponent                         Storeとの接続・actionのdispatch
├─ ExperimentHeaderComponent
│   ├─ CommonSearchComponent                 検索（アプリ共通部品）
│   │   └─ SearchComponent                   入力欄
│   └─ ClearFiltersButtonComponent           絞り込みの一括解除
└─ ExperimentsTableComponent                 extends BaseTableView。列ごとの選択肢・現在値を計算
    └─ TableComponent <sm-table>
        ├─ pTemplate="sort-filter"           列ヘッダーごとに1つ
        │   └─ TableFilterSortComponent      STATUS列もTAGS列もこのクラス
        │       └─ CheckboxThreeStateListComponent
        └─ pTemplate="cardFilter"            カード表示（minimizedView）時
            └─ TableCardFilterComponent
```

## 1. 検索

### 関係するクラス

| クラス | 役割 |
|---|---|
| `CommonSearchComponent` | 入力値をURLの `q` に書き込む。URLの `q` を読んで `commonSearch` stateへ反映する |
| `ExperimentsComponent` | `commonSearch` stateを購読し、実験一覧用の `globalFilterChanged` に変換する |
| `CommonExperimentsViewEffects` | `globalFilterChanged` を受けて一覧を再取得する |

`CommonSearchComponent` は実験管理画面専用ではなく、他の一覧画面でも使う共通部品です。実験管理画面に固有の処理は、`ExperimentsComponent.syncAppSearch()` による接続部分だけです。

### 処理の流れ

1. 入力されると、`CommonSearchComponent.search()` が `router.navigate()` でURLの `q`（正規表現モードなら `qreg` も）を更新します。この時点ではStoreへdispatchしません。
   - [common-search.component.ts:103-122](../src/app/webapp-common/common-search/containers/common-search/common-search.component.ts#L103-L122)
2. 同じコンポーネントが `NavigationEnd` を購読しています。URLの `q` とStoreの値が異なる場合は、`setSearchQuery` をdispatchします。
   - [common-search.component.ts:59-84](../src/app/webapp-common/common-search/containers/common-search/common-search.component.ts#L59-L84)
   - [common-search.reducer.ts](../src/app/webapp-common/common-search/common-search.reducer.ts)
3. `ExperimentsComponent.syncAppSearch()` が `selectSearchQuery` を購読し、`globalFilterChanged` をdispatchします。reducerはこの値を `experimentsView.globalFilter` に保存します。
   - [experiments.component.ts:467-477](../src/app/webapp-common/experiments/experiments.component.ts#L467-L477)
   - [experiments-view.reducer.ts:186-192](../src/app/webapp-common/experiments/reducers/experiments-view.reducer.ts#L186-L192)
4. effect `reFetchExperiment` が `globalFilterChanged` を受けて一覧を再取得します。`getGetAllQuery()` は検索語を `_any_: {pattern, fields}` に変換します。正規表現モードでない場合は `escapeRegex()` でエスケープします。
   - [common-experiments-view.effects.ts:240-245](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L240-L245)
   - [common-experiments-view.effects.ts:1053-1058](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L1053-L1058)

画面を離れるときは、`stopSyncSearch()` が `resetSearch` と `resetGlobalFilter` をdispatchし、検索状態を初期化します（[experiments.component.ts:462-465](../src/app/webapp-common/experiments/experiments.component.ts#L462-L465)）。

## 2. ステータス・タグの絞り込み

### 共通の1クラスが列定義で分岐する

`TableFilterSortComponent` のテンプレートは、列定義の `filterType` で表示を切り替えます。`duration` 系以外は `@default` の分岐に入り、`CheckboxThreeStateListComponent` を表示します。STATUS列もTAGS列も `filterType` を指定していないため、どちらもこの分岐に入ります。

- [table-filter-sort.component.html:37-87](../src/app/webapp-common/shared/ui-components/data/table/table-filter-sort/table-filter-sort.component.html#L37-L87)

ステータスとタグの違いは、次の列定義で表現されています。

```ts
{
  id: EXPERIMENTS_TABLE_COL_FIELDS.TAGS,
  getter: ['tags', 'system_tags'],
  filterable: true,
  searchableFilter: true,           // メニュー内に検索欄を出す
  paginatedFilterPageSize: 100,     // 選択肢を100件ずつ表示する
  excludeFilter: true,              // 含む → 除外 → 解除 の3状態にする
  andFilter: true,                  // Any / All の切替ボタンを出す
  columnExplain: 'Click to include tag. Click again to exclude.',
  ...
},
{
  id: EXPERIMENTS_TABLE_COL_FIELDS.STATUS,
  filterable: true,                 // チェックボックスの選択・解除だけ
  ...
},
```

- [experiment.consts.ts:50-72](../src/app/webapp-common/experiments/experiment.consts.ts#L50-L72)

各フラグの効き方は次のとおりです。

| フラグ | 参照する箇所 | 結果 |
|---|---|---|
| `searchableFilter` | `<sm-menu [enableSearch]>` | メニュー上部に検索欄が出る |
| `paginatedFilterPageSize` | `TableFilterSortComponent.paginatedOptions` | 選択肢を指定件数ずつ表示し、末尾に追加読み込みを出す |
| `excludeFilter` | `CheckboxThreeStateListComponent [supportExcludeFilter]` | 除外状態を持てる。除外値は `excludedKey` を接頭辞に付けた文字列で表す |
| `andFilter` | テンプレートの `@if (column().andFilter)` | Any / All ボタンが出る。All のとき `matchMode: 'AND'` になる |

### 選択肢と現在値は `ExperimentsTableComponent` が作る

`TableFilterSortComponent` は列の意味を知りません。列ごとの選択肢と現在値は、`ExperimentsTableComponent` の `computed` が列IDで振り分けて作ります。

| computed | ステータス | タグ |
|---|---|---|
| `filtersOptions` | `FILTERED_EXPERIMENTS_STATUS_OPTIONS()`。`EXPERIMENTS_STATUS_LABELS` から `closed` を除いた固定リスト | `calcOptionalTagsList()`。Storeのタグ一覧と現在の選択値を合わせ、先頭に `(No tags)`（値は `null`）、次に選択済みのタグを並べる |
| `filtersValues` | `tableFilters.status.value` | `tableFilters.tags.value` |
| `filtersMatch` | ― | `tableFilters.tags.matchMode` |
| `filtersSubValues` | ― | `tableFilters.system_tags.value` |

### 処理の流れ

ステータスとタグは同じ経路を通ります。

1. `CheckboxThreeStateListComponent` が選択後の配列を `filterChanged` でemitします。`TableFilterSortComponent.emitFilterChanged()` が `{value, andFilter}` にまとめて上へ渡します。
   - [table-filter-sort.component.ts:175-185](../src/app/webapp-common/shared/ui-components/data/table/table-filter-sort/table-filter-sort.component.ts#L175-L185)
2. `ExperimentsTableComponent` のテンプレートが `tableFilterChanged(col, $event)` を呼びます。このメソッドは基底クラス `BaseTableView` にあり、`{col, value, andFilter}` をemitしてテーブルを先頭までスクロールします。
   - [experiments-table.component.html:86-103](../src/app/webapp-common/experiments/dumb/experiments-table/experiments-table.component.html#L86-L103)
   - [base-table-view.ts:140-143](../src/app/webapp-common/shared/ui-components/data/table/base-table-view.ts#L140-L143)
3. `ExperimentsComponent.filterChanged()` が `tableFilterChanged` をdispatchします。
   - [experiments.component.ts:563-571](../src/app/webapp-common/experiments/experiments.component.ts#L563-L571)
4. effect `tableFilterChange` が、現在の絞り込み条件に今回の変更を重ねて `setURLParams` をdispatchします。`RouterEffects.setTableParams` がそれを `filter` クエリパラメータにエンコードし、URLを更新します。
   - [common-experiments-view.effects.ts:164-181](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L164-L181)
   - [router.effects.ts:28-50](../src/app/webapp-common/core/effects/router.effects.ts#L28-L50)
5. `ExperimentsComponent` がURLの変更を購読しています。`filter` を `decodeFilter()` で戻して `setTableFilters` をdispatchし、続けて `getExperiments` をdispatchします。reducerは条件を `projectColumnFilters[projectId]` に保存します。effect `setUserPreferences` は同じ内容をユーザー設定にも保存します。
   - [experiments.component.ts:313-326](../src/app/webapp-common/experiments/experiments.component.ts#L313-L326)
   - [experiments-view.reducer.ts:265-284](../src/app/webapp-common/experiments/reducers/experiments-view.reducer.ts#L265-L284)
6. effect `reFetchExperiment` が一覧を再取得します。この effect は `tableFilterChanged`、`setTableFilters`、`getExperiments` などのいずれでも起動しますが、`auditTime(50)` と `switchMap` によって、短時間に続いたトリガーは1回の取得にまとまります。
   - [common-experiments-view.effects.ts:240-260](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L240-L260)

### APIパラメータへの変換

`getGetAllQuery()` が、列IDを指定して値を取り出し、列ごとに異なる形式へ変換します。

| 条件 | 変換後 | 補足 |
|---|---|---|
| ステータス | `status: [...]` | `completed` が含まれる場合、呼び出し前に `closed` も追加する |
| タグ | `filters.tags: {any \| all: {include, exclude}}` | `getTagsFilters()` が `excludedKey` 付きの値を `exclude` に振り分ける。汎用の `filters` からは `delete filters['tags']` で外してから専用形式で入れ直す |
| システムタグ | `system_tags: [...]` | 固定の除外条件（hidden、pipeline、dataset、reports）の後ろに、選択値を連結する |
| 検索 | `_any_: {pattern, fields}` | 「1. 検索」を参照 |

- [common-experiments-view.effects.ts:785-791](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L785-L791)（`closed` の追加）
- [common-experiments-view.effects.ts:964-1078](../src/app/webapp-common/experiments/effects/common-experiments-view.effects.ts#L964-L1078)（`getGetAllQuery()`）

## 3. 解除

絞り込みの解除には2つの入口があります。

- ヘッダーの `ClearFiltersButtonComponent`：`clearTableFiltersHandler()` で絞り込みだけを解除します。
- 該当なし表示の「Clear filters」リンク：`clearTableFiltersAndSearchHandler()` が `others: {q: null}` を付けて呼ぶため、URLの `q` も消え、検索も同時に解除されます。

どちらも `tableFilterChanged` を経由してURLを書き換えるため、その後は「2. 処理の流れ」の4以降と同じ経路を通ります。

- [experiments.component.ts:721-733](../src/app/webapp-common/experiments/experiments.component.ts#L721-L733)

## まとめ

| 観点 | 実装 |
|---|---|
| 別クラスになっているもの | 検索UI（`CommonSearchComponent`）と絞り込みUI（`TableFilterSortComponent`） |
| 同じクラスを共有しているもの | ステータスとタグ（ほかの USER、TYPE、PROJECT などの列も同じ） |
| 列ごとの違いの置き場所 | UI表示：列定義のフラグ<br>選択肢・現在値：`ExperimentsTableComponent` の `computed` 内の列ID指定<br>API変換：`getGetAllQuery()` 内の列ID指定 |
| 状態の経路 | 検索も絞り込みも、UI → URL → Store → effect → API の順に流れる。URLを正とし、Storeはそれを反映する |
| 合流点 | `getGetAllQuery()` |

列の種類ごとにクラスを分ける設計ではありません。汎用のUIクラスを列定義で設定し、列固有の処理はテーブルコンポーネントとクエリ組み立て関数の中で列IDを見て分岐させる設計です。
