# 02 状態経路

実験名は Store の3か所に置かれている。書き換える Action と、読む画面部品がそれぞれ違う。

| 置き場所 | 書き換える Action | 読む側 |
| --- | --- | --- |
| `experiments.info.infoData` | `experimentDetailsUpdated`（dispatch 直後）<br/>`updateExperimentInfoData`（API 成功後）<br/>`setExperimentInfoData`（再取得後） | InfoHeader の `infoData()` → Inline の `originalText` |
| `experiments.info.selectedExperiment` | `updateExperimentInfoData`（API 成功後）<br/>`setExperiment`（再取得後） | Output の `selectedExperiment` Signal → InfoHeader の名前表示 |
| `experiments.view.experiments` | `updateExperiment`（API 成功後と再取得後の2回） | `selectExperimentsList` → EC → 一覧カード |

編集中フラグは `experiments.info.activeSectionEdit` にあり、`activateEdit` / `deactivateEdit` で切り替わる。

## 図1: Action と Store の流れ

```mermaid
sequenceDiagram
    autonumber
    participant Output as sm-experiment-output
    participant Info as Store（experiments.info）
    participant InfoEff as CommonExperimentsInfoEffects
    participant Server as tasks.update
    participant View as Store（experiments.view）

    Output->>Info: experimentDetailsUpdated({id, changes: {name}})
    Info->>Info: infoData に name をマージ（先行して反映）
    Info->>InfoEff: 同じ Action を受ける
    InfoEff->>Server: POST tasks.update
    Server-->>InfoEff: 成功
    InfoEff->>Info: experimentUpdatedSuccessfully({id})
    Note over InfoEff,Info: 詳細の再取得のきっかけ（03-02 図4）
    InfoEff->>View: updateExperiment({id, changes})
    View->>View: experiments の id 一致行だけ {...ex, ...changes}
    InfoEff->>Info: updateExperimentInfoData({id, changes})
    Info->>Info: selectedExperiment / infoData にマージ
    Note over InfoEff,View: 再取得の結果で setExperimentInfoData / setExperiment /<br/>updateExperiment（サーバ値で2回目）が出る
```

- 一覧の `view.experiments` は、API が成功するまで旧名のまま。`experimentDetailsUpdated` を処理する Reducer は `info` 側にしかない。
- `updateExperiment` は `view.selectedExperiment` と `view.selectedExperiments` の該当要素も同じ変更で差し替える。

## 図2: Store から画面部品への流れ（Observable と Signal）

```mermaid
sequenceDiagram
    autonumber
    participant View as Store（experiments.view）
    participant Info as Store（experiments.info）
    participant EC as ExperimentsComponent
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table
    participant Card as sm-table-card
    participant Output as sm-experiment-output
    participant InfoHeader as sm-experiment-info-header

    View-->>EC: selectExperimentsList（Observable）
    EC->>EC: experiments$: null 除外 → filterArchivedExperiments
    EC->>ExpTable: ngrxPush → input Signal experiments
    ExpTable->>SmTable: input Signal tableData
    SmTable->>Card: p-table [value] → cardTemplate → input Signal cardName

    Info-->>Output: selectSelectedExperiment を subscribe（id 一致のみ）
    Output->>Output: selectedExperiment.set(experiment)（WritableSignal）
    Output->>InfoHeader: input Signal experiment
    Info-->>Output: infoData$（Observable）
    Output->>InfoHeader: ngrxPush → input Signal infoData
```

- Store から先は、コンポーネント境界ごとに Signal input で受け渡す。Observable のまま渡るのは EC と Output の中だけ。
- Inline 内部の状態は Store に置かない。`active`（編集モード）と `inlineValue`（入力値、`[(ngModel)]` と双方向）はどちらも Inline の WritableSignal。

## 編集中フラグの影響

```mermaid
sequenceDiagram
    autonumber
    participant InfoHeader as sm-experiment-info-header
    participant Info as Store（experiments.info）
    participant Output as sm-experiment-output

    InfoHeader->>Info: activateEdit('ExperimentName')
    Info->>Info: activeSectionEdit = true<br/>infoDataFreeze = infoData
    Info-->>Output: selectIsExperimentInEditMode = true
    Output->>Output: refresh.tick の購読が filter で止まり、<br/>詳細の自動再取得をしない
    InfoHeader->>Info: deactivateEdit
    Info->>Info: activeSectionEdit = false
```
