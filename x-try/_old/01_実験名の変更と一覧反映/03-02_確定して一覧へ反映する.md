# 03-02 確定して一覧へ反映する

本線。入力を確定してから、一覧カードに新しい名前が描画されるまで。

## 図1: 確定から dispatch まで

```mermaid
sequenceDiagram
    autonumber
    participant User
    participant Inline as sm-inline-edit
    participant InfoHeader as sm-experiment-info-header
    participant Output as sm-experiment-output
    participant Store as NgRx Store（info）

    alt Enter / Tab
        User->>Inline: (keydown.enter) / (keydown.tab)
    else ✓ボタン
        User->>Inline: (click) → $event.stopPropagation()
    end
    Inline->>Inline: form.checkValidity() が true なら inlineSaved()
    Inline->>Inline: inlineValue.set(inlineInput().value)
    Inline->>Inline: 値が originalText() と異なることを確認
    Inline->>InfoHeader: textChanged.emit(新しい名前)
    InfoHeader->>Output: onNameChanged() → experimentNameChanged.emit(name)
    Output->>Output: updateExperimentName(name)<br/>name.trim().length > 2 を確認
    Output->>Store: dispatch experimentDetailsUpdated<br/>({id: selectedExperiment().id, changes: {name}})
    Store->>Store: infoData.name = 新しい名前
    Inline->>Inline: active.set(false)
    Inline->>InfoHeader: inlineActiveStateChanged.emit(false)
    InfoHeader->>Store: dispatch deactivateEdit
```

- `textChanged.emit()` から dispatch と `infoData` の更新までは同期で進む。それが終わってから Inline が編集モードを閉じる。
- `trim()` は長さの確認にだけ使う。`changes.name` には前後の空白を含む入力値がそのまま入る。
- 値が変わっていない場合と、検証で止まる場合は [03-03](./03-03_編集を取り消す.md) / [03-04](./03-04_保存されない分岐.md)。

## 図2: API で保存し、Store を更新する

```mermaid
sequenceDiagram
    autonumber
    participant Store as NgRx Store
    participant InfoEff as CommonExperimentsInfoEffects
    participant TasksApi as ApiTasksService
    participant Server

    Store->>InfoEff: ofType(experimentDetailsUpdated)
    InfoEff->>Store: concatLatestFrom<br/>infoData / info.selectedExperiment / フォームの妥当性
    InfoEff->>InfoEff: filter(valid)
    InfoEff->>TasksApi: tasksUpdate({task: id, name})
    TasksApi->>Server: POST tasks.update
    Server-->>TasksApi: 200
    TasksApi-->>InfoEff: res
    InfoEff->>InfoEff: changes = res?.fields || action.changes
    InfoEff->>Store: experimentUpdatedSuccessfully({id})
    InfoEff->>Store: updateExperiment({id, changes})
    Store->>Store: view.experiments の id 一致行だけ {...ex, ...changes}
    opt info.selectedExperiment.id が action.id と同じ
        InfoEff->>Store: updateExperimentInfoData({id, changes})
        Store->>Store: info.selectedExperiment / infoData にマージ
    end
```

- `mergeMap` の中で `tasksUpdate` を呼ぶため、続けて別の名前を確定しても前のリクエストは取り消されない。
- `changes.tags` があれば `getTags` も出るが、名前の変更では出ない。

## 図3: 一覧カードとヘッダーの再描画

```mermaid
sequenceDiagram
    autonumber
    participant Store as NgRx Store
    participant EC as ExperimentsComponent
    participant ExpTable as sm-experiments-table
    participant SmTable as sm-table
    participant Card as sm-table-card
    participant Output as sm-experiment-output
    participant InfoHeader as sm-experiment-info-header
    participant User

    par 一覧カード
        Store-->>EC: selectExperimentsList（新しい配列）
        EC->>EC: experiments$: null 除外 → filterArchivedExperiments
        EC->>ExpTable: [experiments]="$any(experiments$ | ngrxPush)"
        ExpTable->>SmTable: [tableData]="experiments()"
        SmTable->>SmTable: p-table [value]="tableData()"
        SmTable->>Card: minimizedView() のため cardTemplate<br/>[cardName]="experiment.name"
        Card-->>User: {{cardName()}} に新しい名前
    and ヘッダー
        Store-->>Output: selectSelectedExperiment（id 一致）
        Output->>Output: selectedExperiment.set(experiment)
        Output->>InfoHeader: [experiment]="selectedExperiment()"
        InfoHeader-->>User: {{experiment()?.name}} に新しい名前
    end
```

- 一覧は `tasks.get_all_ex` を呼び直さない。`updateExperiment` で差し替わった配列が Selector から流れるだけ。
- ヘッダーの名前表示は `info.selectedExperiment` を読むため、`updateExperimentInfoData` まで旧名のまま。

## 図4: 後続の再取得

```mermaid
sequenceDiagram
    autonumber
    participant Store as NgRx Store
    participant InfoEff as CommonExperimentsInfoEffects
    participant TasksApi as ApiTasksService
    participant Server

    Store->>InfoEff: getExperimentInfo$ が experimentUpdatedSuccessfully を受ける
    InfoEff->>Store: getExperiment({experimentId}) ほか
    Note over InfoEff: この Action のときは last_change の比較に関係なく<br/>getExperiment まで進む
    Store->>InfoEff: fetchExperiment$ が getExperiment を受ける
    InfoEff->>TasksApi: tasksGetByIdEx({id: [id], only_fields})
    TasksApi->>Server: POST tasks.get_by_id_ex
    Server-->>InfoEff: task
    InfoEff->>Store: setExperimentInfoData / setExperiment
    InfoEff->>Store: updateExperiment({id, changes: experiment})
    InfoEff->>Store: deactivateEdit ほか
    Note over Store: 一覧の該当行はサーバ値でもう一度差し替わる。<br/>名前は同じなので表示は変わらない
```
