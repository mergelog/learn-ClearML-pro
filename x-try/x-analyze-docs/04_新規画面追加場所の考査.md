迷います。なので、フォーク側では「既存の置き場所に合わせる」のではなく、**新規コードの責務と所有者**で決めるルールが必要です。

このプロジェクトなら、こう切るのがよいです。

| ケース | 新規作成先 |
|---|---|
| 新しい画面・画面専用の state / API / 部品 | `src/app/features/<feature>/` |
| 複数の自作 feature で共有するもの | `src/app/shared/` |
| ClearML 既存画面・既存部品の流用だけ | `src/app/webapp-common/` は参照するだけ |
| `webapp-common` の部品を少し変えたい | 自作 feature 側に wrapper / adapter を作る |

要は、`webapp-common` は「既存 ClearML 資産の参照先」であって、**フォーク側の新規機能の追加先ではない**と定義します。そうすれば既存部品を再利用しても、新しい設計判断や依存が upstream 由来の領域へ混ざりません。
