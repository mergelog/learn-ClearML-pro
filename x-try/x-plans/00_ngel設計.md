# Angular DOM階層抽出ツール 実装指示書

Chrome DevTools の Elements から取得したHTMLを加工し、Angularアプリの実装階層を追いやすいHTML資料を生成するスクリプトを作成してください。

## 目的

Chrome DevTools から取得した実DOMには大量の `div` などが含まれており、Angularコンポーネントの階層を把握しづらい状態です。

これを整理し、

- `<sm-...>`
- `<as-split>`
- `<notifi...>`
- `<al-drawer>`
- その他のカスタム要素
- Angularコンポーネント／Directiveに関係する可能性がある要素

などの階層を追いやすい資料にします。

これはAngularの静的な親子関係解析ではなく、ブラウザ上に実際に描画されたDOMの階層を確認するための資料です。

参考資料：

`x-try/x-analyze-docs/02_親子関係の実現技術_全面調査.md`

## 基本方針

スクリプトとして実装してください。

「残すタグを指定する」方式にはしないでください。

今後の開発で未知のAngularコンポーネントや外部ライブラリのCustom Elementが追加される可能性があるためです。

逆に、

「明らかに不要と判断したタグだけを削除対象として指定する」

方式にしてください。

初回実装では削除対象を `div` のみにしてください。

`span`、`button`、`section` その他の標準HTMLタグについては、現時点では削除しないでください。

初回成果物を確認した後、削除対象を追加するか判断します。

## `div` の扱い

`div` 内部に存在する子要素まで削除しないでください。

例えば、

`<sm-parent><div><sm-child></sm-child></div></sm-parent>`

は、

`<sm-parent><sm-child></sm-child></sm-parent>`

となる必要があります。

つまり `div` 要素そのものだけを取り除き、内部の要素は元の階層関係を保ったまま残してください。

## HTML整形

現在取得できるHTMLには、

`<div><sm-foo>`

のように同一行へ複数要素が並んでいる箇所があります。

加工後のHTMLは、親子関係を目視で追えるよう、適切な改行とインデントを付けて整形してください。

特にAngularコンポーネントのネスト構造を見たときに、階層が一目で分かることを重視してください。

## 情報保持

初回実装では、`div` を取り除くこと以外の情報削減は極力行わないでください。

以下は原則として保持してください。

- 未知のHTMLタグ
- Custom Element
- 属性
- class
- id
- Angularや外部ライブラリ由来と思われる属性
- 子要素の順序

「不要そうだから」という推測だけで情報を削除しないでください。

まず情報を多めに残した成果物を作り、それを確認してから削減対象を検討します。

## 正規表現について

HTML構造そのものを正規表現だけで加工する実装にはしないでください。

ネスト構造を壊さず処理できる方法を使用してください。

具体的なライブラリや実装方式については、既存プロジェクトとの相性を確認した上で選択してください。

## 出力先

加工後のHTMLは以下へ保存してください。

`x-ngel/`

ファイル名は次の形式とします。

`ngel-{連番}-___undefined___-{日時}.html`

例：

`ngel-001-___undefined___-20260928-120000.html`

連番は既存の `ngel-` ファイルを確認し、使用済みの最大番号の次を使用してください。

途中のファイルが削除されていても既存ファイル名と衝突しないようにしてください。

`___undefined___` 部分については、現段階ではそのまま固定文字列として扱って構いません。

## 入力

Chrome DevTools の Elements から取得したHTMLを入力として処理できるようにしてください。

入力方法については、今後変更する可能性があります。

そのため、

「HTMLの取得処理」

と

「HTMLを加工してファイルへ出力する処理」

は必要以上に密結合させないでください。

初回では複雑なChrome自動操作などは不要です。

## 今回やらないこと

初回実装では以下は不要です。

- `sm-*` など特定prefixだけを残す処理
- Custom Elementだけを残す処理
- Angular DevToolsとの連携
- `ng.getComponent()` 等を使用したAngular Component判定
- Chrome DevTools ProtocolによるChrome直接操作
- PlaywrightによるDOM自動取得
- `span` や `button` 等の追加削除
- classや属性の削除
- テキストノードの積極的な削除
- Angularの静的ソース解析
- コンポーネント名からの自動ファイル検索

まずは最小限の加工のみ行い、実際の成果物を確認します。

## 初回完了条件

以下を満たした段階で一旦作業を完了してください。

1. Chrome DevTools由来のHTMLを入力できる
2. `div` 自体だけが取り除かれる
3. `div` の子要素は削除されない
4. 未知のCustom Elementがそのまま残る
5. その他のタグを勝手に削除しない
6. 親子階層が分かるようHTMLが整形される
7. `x-ngel/ngel-{連番}-___undefined___-{日時}.html` として保存される
8. 元HTMLの階層構造を壊していない
9. 実際のHTMLを1件以上処理し、生成結果を確認する

実装完了後は、追加の最適化を進めず、一旦生成されたHTMLの内容を提示してください。

その成果物を確認してから、次に削除するタグや属性を判断します。
