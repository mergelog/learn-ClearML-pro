# 実験名・モデル名の長さの下限が、入力欄（2文字以上）と保存処理（前後の空白を除いて3文字以上）で食い違い、検証を通った名前が保存されない

| 項目 | 内容 |
|---|---|
| カテゴリー | 処理値 |
| 不具合内容 | 2文字の名前や、前後の空白で入力欄の下限を満たした名前で確定すると、入力欄の検証は通って編集が閉じるが、保存処理で止まりエラー通知だけが出る。通知文 `Name must be more than three letters long`（4文字以上と読める）も、実際の条件（前後の空白を除いて3文字以上）と1文字ずれる |
| 期待動作 | 入力欄の検証と保存処理が同じ条件を使い、保存できない名前は入力欄の段階で確定できない。通知文が実際の条件と一致する |
| 直さないと困ること | 利用者は確定できたと思った名前が保存されず、入力も消えるため、下限を知って入力し直す必要がある。通知文を信じて4文字以上にこだわる利用者も出る |
| 修正規模 | 中 |

| 項目 | 内容 |
|---|---|
| 画面 | 実験管理 > 詳細ヘッダー > 名前のインライン編集、モデル > 詳細ヘッダー > 名前のインライン編集。フェーズ2で、タスクのクローンのダイアログとレポートのカードの名前変更を追加 |
| 観点 | B（文字列の値の扱い）、G（フォームと検証） |
| 重大度 | S3 |
| 確度 | 再現済み（実験名）。モデル名・レポート名はコード上確定。クローンはダイアログが短い名前を送ることを再現済み（サーバの拒否はコード上確定）。下限の値そのもの（日本語の2文字の名前を許すか）は要確認 |
| 由来 | 上流 |
| 発生条件 | 前後の空白を除いた長さが2文字以下で、入力欄の下限（2文字）は満たす名前で確定する |
| 関連 | [04](./04_インライン編集の通常のEnterで保存処理が2回走る.md)（Enter で確定するとエラー通知が2つ出る） |

## 症状

| 入力 | 確定の方法 | ✓ボタン | 結果 |
|---|---|---|---|
| `実験`（2文字） | Enter | 有効 | 編集が閉じ、通知が2つ出る（[04](./04_インライン編集の通常のEnterで保存処理が2回走る.md)）。保存されない |
| `実験`（2文字） | ✓ | 有効 | 編集が閉じ、通知が1つ出る。保存されない |
| ` 実験 `（前後に空白、計4文字） | Enter | 有効 | 編集が閉じ、通知が2つ出る。保存されない |
| `abc`（3文字） | Enter | 有効 | 保存される（通知文は「3文字より多く」と読めるが、3文字で通る） |

どの場合も、編集が閉じた時点で入力は消え、もう一度編集を開くと元の名前に戻っている。

前後の空白だけで下限を満たした名前は、✓ボタンでは押せない場合がある。✓ボタンは前後の空白を除いた長さも見る（`inlineValue()?.trim().length < minLength()`）が、Enter・Tab は `form.checkValidity()`（空白を含む長さ）しか見ないためである。たとえば ` a `（空白を除いて1文字）は、✓ボタンは無効だが Enter では確定でき、保存処理で止まる。

## 再現手順

1. 実験管理画面で実験を選び、詳細ヘッダーの名前をクリックして編集モードにする
2. 名前を全選択して `実験` に置き換え、Enter を押す
3. 編集が閉じ、「Name must be more than three letters long」が表示される。名前は元のまま

Playwright（モック API）では [scripts/01-inline-edit-name.spec.ts](./scripts/01-inline-edit-name.spec.ts) の「06 名前の長さの下限」で、上の表の4通りを確かめた。

## 期待する動作

入力欄の検証が保存処理と同じ条件（前後の空白を除いた長さ）を使い、保存できない名前では Enter・Tab・✓のどれでも確定できず、入力欄にエラーが出る。通知文を残す場合は実際の条件に合わせる（「at least 3 characters」など）。

## 原因

下限が2段に分かれている。

| 段 | 条件 | 箇所 |
|---|---|---|
| 入力欄 | `[minLength]="2"`。空白を含む長さで判定する。Enter・Tab は `form.checkValidity()` でこれだけを見る | [experiment-info-header.component.html:10](../src/app/webapp-common/experiments/dumb/experiment-info-header/experiment-info-header.component.html#L10)、[inline-edit.component.html:30](../src/app/webapp-common/shared/ui-components/inputs/inline-edit/inline-edit.component.html#L30) |
| ✓ボタン | 上に加えて、前後の空白を除いた長さが `minLength`（2）以上 | [inline-edit.component.html:54](../src/app/webapp-common/shared/ui-components/inputs/inline-edit/inline-edit.component.html#L54) |
| 保存処理 | `name.trim().length > 2`（前後の空白を除いて3文字以上）。満たさなければエラー通知を出し、`experimentDetailsUpdated` を dispatch しない | [base-experiment-output.component.ts:178](../src/app/webapp-common/experiments/containers/experiment-ouptut/base-experiment-output.component.ts#L178) |

インライン編集は、`textChanged` を出した時点で編集モードを閉じる（[inline-edit.component.ts:94](../src/app/webapp-common/shared/ui-components/inputs/inline-edit/inline-edit.component.ts#L94)）。保存処理で止まったことはインライン編集に伝わらないため、編集は閉じたままになる。処理の流れは [x-sequense/01 03-04](../x-sequense/01_実験名の変更と一覧反映/03-04_保存されない分岐.md) の図1にある。

## 影響範囲と同種箇所

| 箇所 | 入力欄の下限 | 保存処理の下限 |
|---|---|---|
| 実験名（詳細ヘッダー） | 2 | 前後の空白を除いて3（[base-experiment-output.component.ts:178](../src/app/webapp-common/experiments/containers/experiment-ouptut/base-experiment-output.component.ts#L178)） |
| モデル名（詳細ヘッダー） | 2（[model-info-header.component.html:9](../src/app/webapp-common/models/dumbs/model-info-header/model-info-header.component.html#L9)） | 前後の空白を除いて3。通知文も同じ（[model-info.component.ts:172](../src/app/webapp-common/models/containers/model-info/model-info.component.ts#L172)） |
| 比較画面の名前変更ダイアログ（参考） | 前後の空白を除いて3（`minLengthTrimmed(3)`） | 前後の空白を除いて保存 |
| クローンのダイアログのタスク名（フェーズ2で追加） | 下限なし（`Validators.required` だけ。2文字の名前も全角空白だけの名前も通る）（[clone-dialog.component.ts:85](../src/app/webapp-common/experiments/shared/components/clone-dialog/clone-dialog.component.ts#L85)） | フロントエンドでは確かめず、そのまま `tasks.clone` に送る。サーバが拒否し、`Clone Task failed` の通知が出る（[common-experiments-menu.effects.ts:215](../src/app/webapp-common/experiments/effects/common-experiments-menu.effects.ts#L215) の `catchError`）。ダイアログは閉じており入力は残らない |
| レポートのカードの名前変更（フェーズ2で追加） | 3。空白を含む長さで判定する（Enter・Tab）（[report-card.component.html:13](../src/app/webapp-common/reports/report-card/report-card.component.html#L13)） | フロントエンドでは確かめず、そのまま `updateReport` を dispatch する。` ab `（前後に空白、計4文字）は入力欄を通り、サーバが拒否する |

比較画面の名前変更ダイアログは、共通のバリデータ [minLengthTrimmed()](../src/app/webapp-common/shared/validators/minLengthTrimmed.ts) で入力欄と保存の条件が揃っている。同じ実験名でも、変更する場所によって下限と空白の扱いが違う。

サーバ（apiserver 2.4.0）は、タスク名・モデル名・キュー名を `StrippedStringField(min_length=3)` で持つ（`database/model/task/task.py`・`model.py`・`queue.py`）。保存時に前後の空白（全角空白を含む。Python の `str.strip()`）を除き、3文字未満なら検証エラーにする。レポートはタスクとして保存されるため同じ条件になる。プロジェクト名は `min_name_length = 1` である。フロントエンドの下限がこれより緩い箇所では、入力欄を通った名前がサーバで拒否される。フェーズ2（観点 B）で、実験名・モデル名以外の名前の入力欄を洗い、上の表の最後の2行を追加した。新規タスク・新規レポート・新規キュー・パイプラインの実行ダイアログは `minLengthTrimmed(3)` で、サーバと揃っている。ただし文字数の数え方が違い、フロントエンドの `length` は UTF-16 の単位で絵文字（サロゲートペア）を2と数え、サーバ（Python の `len`）は1と数える。`😀😀` はフロントエンドの下限（3）を満たすが、サーバでは2文字として拒否される（コード上確定。画面では確かめていない）

日本語は2文字で意味の通る名前（「実験」「検証」など）が多い。下限を3文字にそろえるか、2文字に下げるかは、仕様として判断が要る。下限を2文字に下げる場合は、サーバの `min_length=3` も変える必要がある（フロントエンドだけでは2文字の名前を保存できない）。

## 対策案

入力欄の検証を保存処理と同じ条件にする。インライン編集の入力欄に、前後の空白を除いた長さで判定するバリデータ（`minLengthTrimmed` と同じ判定のディレクティブ）を足し、実験・モデルの詳細ヘッダーの `[minLength]` を保存処理の下限（3）に合わせる。Enter・Tab・✓がすべて同じ `form.checkValidity()` で判定されるようになり、保存処理の長さ確認は二重の防御として残せる。あわせて通知文を実際の条件に直す。

共通部品（インライン編集）へのバリデータの追加と、2つの詳細ヘッダー・2つの保存処理の変更、単体テストで「中」とした。

## 検証範囲

- 確認したこと：Playwright（モック API）で、実験名の上の表の4通り。モデル名の保存処理が同じ条件と通知文であること（コード）
- 確認したこと（フェーズ2で追加）：Playwright（モック API）で、クローンのダイアログが `実験`（2文字）と全角空白だけの名前をそのまま `tasks.clone` に送ること（[scripts/p2b-clone-name.spec.ts](./scripts/p2b-clone-name.spec.ts)）。起動中の apiserver のコード（`docker exec` で読み取りだけ）で、名前のフィールドの定義と前後の空白の除去
- 確認していないこと：モデル名の画面での操作。Tab での確定（コード上は Enter と同じ判定）。実際のサーバに短い名前を送ったときの応答（書き込みを伴うため行っていない）。レポートのカードの名前変更の画面での操作
- 由来：実験の詳細ヘッダー・保存処理・インライン編集のファイルは、比較資料で上流と一致する（エイリアス改名のみのものを含む）。モデルの詳細ヘッダーはカスタマイズ（比較資料 §2.3）があるが、変更箇所は ID バッジ横のデータカタログへの導線であり、名前の入力欄（`[minLength]="2"`）とは別の要素である
