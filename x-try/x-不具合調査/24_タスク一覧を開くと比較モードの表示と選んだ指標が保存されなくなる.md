# タスク一覧を開いた後は、一覧の比較モードで選んだ表示（Scalars / Plots）と指標が保存されず、新しいタブなどで開き直すと前の値に戻る

| 項目 | 内容 |
|---|---|
| カテゴリー | 状態 |
| 不具合内容 | タスク一覧を一度でも開くと、以後、一覧の比較モードの表示（Scalars / Plots）と、比較モードで表示する指標の選択が localStorage に保存されなくなる。新しいタブや再読み込みの後に一覧から比較モードに入ると、タスク一覧を開く前に保存された値（無ければ既定値）で開く |
| 期待動作 | 比較モードで選んだ表示と指標が保存され、再読み込みの後も同じ表示になる |
| 直さないと困ること | 比較モードで指標を選び直しても、次に開いたときには選択が戻っているため、毎回選び直すことになる。保存の仕組み（metaReducers）がタスク一覧を開いた時点で外れるため、上流が意図した保存は実質的に一度も働かない |
| 修正規模 | 極小 |

| 項目 | 内容 |
|---|---|
| 画面 | 実験管理 > 一覧の比較モード（`/projects/:id/tasks/compare`） |
| 観点 | F（同じ feature key の二重登録） |
| 重大度 | S3 |
| 確度 | 再現済み（Scalars / Plots。指標の選択は同じ仕組みのためコードから判断） |
| 由来 | 上流 |
| 発生条件 | 同じタブでタスク一覧（`/projects/:id/tasks` 以下）を1回以上開いた後。データセットの版の画面を後から開くと、保存の仕組みが元に戻る（コードから判断） |
| 関連 | なし |

## 症状

モック API で、比較モードの表示を切り替える action（ヘッダーの選択欄が出すものと同じ `setCompareView`）を dispatch し、Store と localStorage の `_saved_experiment_state_` を記録した（[scripts/p2f-experiments-meta-reducer.spec.ts](./scripts/p2f-experiments-meta-reducer.spec.ts)）。

| 手順 | Store の `tableCompareView` | localStorage の `view.tableCompareView` | 確認 |
|---|---|---|---|
| ダッシュボード（タスク一覧を開く前）で Plots を選ぶ | plots | plots（保存される） | 再現（モック API） |
| アプリ内でタスク一覧へ移り、Scalars を選ぶ | scalars | plots（保存されない） | 同上 |
| 再読み込みする | plots（最後に選んだ Scalars ではない） | plots | 同上 |
| タスク一覧を直接開き、Plots を選ぶ | plots | なし（保存されない） | 同上 |
| 画面の操作：一覧で全件を選んで比較モードにし、選択欄で Plots を選ぶ | plots | なし（保存されない） | 再現（モック API） |
| 画面の操作：一覧（`/projects/:id/tasks`）を読み込み直し、全件を選んで比較モードに入る | scalars（URL は `compare/scalars`） | なし | 同上 |

利用者の操作では、比較モードの表示は一覧のヘッダーの選択欄（Scalars / Plots）で、指標はグラフの設定で選ぶ。どちらもタスク一覧の中の操作なので、保存されることが無い。比較モードの URL（`compare/plots`）のまま再読み込みした場合は、URL から表示が決まるため Plots のままになる（`compareViewStateGuard`）。保存値が使われるのは、比較モードの URL を持たずに一覧を開いて比較モードに入るときである。

## 再現手順

1. localStorage の `_saved_experiment_state_` を消す（DevTools の Application）
2. タスク一覧を開き、表の見出しのチェックボックスで全件を選び、表示モードの切り替え（表の上、右端の Compare view）で比較モードにする
3. 右上の選択欄で Plots を選ぶ
4. DevTools で localStorage を見る。`_saved_experiment_state_` が作られていない
5. 新しいタブで同じプロジェクトのタスク一覧（`/projects/:id/tasks`）を開き、全件を選んで比較モードにする。Plots ではなく既定の Scalars で開く

手順5の比較モードへの移動は、Store の `tableCompareView` を使って `compare/scalars` か `compare/plots` へ移す（[compare-navigation.guard.ts](../src/app/webapp-common/experiments/compare-navigation.guard.ts) の `selectTableCompareUrlParts`）。Store の値は、読み込みの時点で localStorage から読み戻される。スクリプトは [scripts/p2f-experiments-meta-reducer.spec.ts](./scripts/p2f-experiments-meta-reducer.spec.ts)（手順5は新しいタブの代わりに同じタブで読み込み直した）。

## 期待する動作

どの画面を開いた後でも、`EXPERIMENTS_` で始まる action で比較モードの表示・指標が変わるたびに localStorage に保存される。

## 原因

experiments の feature state（`EXPERIMENTS_STORE_KEY`）が、設定の違う3箇所で `provideState` されている。

| 登録箇所 | 環境インジェクター | metaReducers |
|---|---|---|
| [app.config.ts:44](../src/app/app.config.ts#L44) の `experimentsProviders` | ルート | あり（`EXPERIMENT_CONFIG_TOKEN`） |
| [app.routes.ts:89](../src/app/app.routes.ts#L89) の `tasks` ルートの `experimentsProviders`（[dataset-version.routes.ts:7](../src/app/webapp-common/dataset-version/dataset-version.routes.ts#L7) も同じ） | ルートごと | あり |
| [experiment-routes.ts:28](../src/app/webapp-common/experiments/experiment-routes.ts#L28) の `commonExperimentsProviders`（`tasks` の子の `''` ルート） | ルートごと | なし（`provideState(EXPERIMENTS_STORE_KEY, reducers)` に設定を渡していない） |
| [experiment-shared.config.ts:49](../src/app/features/experiments/shared/experiment-shared.config.ts#L49) の `experimentSharedProviders` | — | どこからも使われていない |

metaReducers は [experiments.providers.ts:28](../src/app/features/experiments/shared/experiments.providers.ts#L28) の `getExperimentsConfig()` が返す2つで、1つ目が `EXPERIMENTS_` で始まる action のたびに `view.tableMode`・`view.tableCompareView`・`view.compareSelectedMetrics`・`view.compareSelectedMetricsPlots` を localStorage に保存し、初回の呼び出しで読み戻す。

`provideState` は、そのインジェクターが作られたときに `ReducerManager.addFeatures()` を呼ぶ。`addFeatures()` は `this.reducers = {...this.reducers, ...reducers}` で同じキーの reducer を後から来たもので置き換える（`@ngrx/store` 22 の `ReducerManager.addReducers()`）。state の値は残り、reducer の関数（metaReducers を含むかどうか）だけが入れ替わる。ルートの環境インジェクターは最初にそのルートを開いたときに作られて以後残るため、どの reducer が使われるかは、ルートを初めて開いた順で決まる。

タスク一覧を開くと、`tasks` ルート（metaReducers あり）、子の `''` ルート（なし）の順にインジェクターが作られ、最後に登録された metaReducers なしの reducer が残る。以後、保存する metaReducer を通らないため、localStorage は書き換わらない。

子のインジェクターの `provideState` が登録するのは、そのインジェクターの `_STORE_FEATURES`（multi の provider）だけである。子で provider を宣言すると親の multi の値を合わせずに子の値だけが返るため、子の登録は experiments の1件だけになり、ほかの feature は置き換わらない。

## 影響範囲と同種箇所

- 保存が止まるのは上の4つの値だけである。これらは localStorage 以外に保存されない。`tableMode` は URL から決まるため、保存されなくても表示は変わらない
- 2つ目の metaReducer（`createUserPrefFeatureReducer`）は、保存するキーの指定が空（`[]`）で、利用者設定を読み込んだとき（初回と `setPreferences`）に Store へ合わせるだけである。タスク一覧を開いた後は `setPreferences` を受けても experiments の値に合わせなくなる。どの値に影響するかは確かめていない
- タスク一覧の後にデータセットの版の画面（`dataset-version.routes.ts`）を初めて開くと、metaReducers ありの reducer が再び登録される。その初回の呼び出しで localStorage の古い値が Store に合わさるため、同じタブの中で比較モードの表示や指標が古い値に戻る可能性がある（コードから判断。確かめていない）
- 同じキーを複数箇所で登録しているのは、ほかに `projects`（[common-projects.providers.ts:9](../src/app/webapp-common/projects/common-projects.providers.ts#L9) と [pipelines.providers.ts:37](../src/app/webapp-common/pipelines/pipelines.providers.ts#L37)）だけである。こちらの metaReducer は初回に localStorage の `_saved_pipeline_state_` を読み込むだけで保存はしない（保存は `showExamplePipeline` の Effect が直接行う）ため、置き換わっても失われるものは無い

## 対策案

第一案は、[experiment-routes.ts:28](../src/app/webapp-common/experiments/experiment-routes.ts#L28) の `provideState(EXPERIMENTS_STORE_KEY, reducers)` を削除する。親の `tasks` ルートとルートの `app.config.ts` が同じキーを metaReducers 付きで登録済みで、子で登録し直す必要が無い。1行の削除のため「極小」とした。あわせて、どこからも使われていない `experimentSharedProviders` を削除すると、登録箇所の見通しがよくなる。

登録を1箇所に集める場合は、`app.config.ts`（ルート）だけに残し、`app.routes.ts:89` と `dataset-version.routes.ts:7` の `experimentsProviders` から `provideState` を外す。この場合は Effect の登録も合わせて整理が要るため、修正の範囲が広がる。

## 検証範囲

- 確認したこと：Playwright（Chromium）とモック API で、タスク一覧を開く前は `setCompareView` が localStorage に保存され、開いた後（アプリ内の遷移・直接開いた場合の両方）は保存されないこと、再読み込みで保存済みの古い値に戻ること。画面の操作（全件の選択、比較モードへの切り替え、選択欄の Plots）でも保存されず、一覧を読み込み直して比較モードに入ると Scalars で開くこと。`ReducerManager.addReducers()` の置き換えと `featureStateProviderFactory()` の登録の流れは `@ngrx/store` 22 のソースで確かめた
- 確認していないこと：指標の選択（`compareSelectedMetrics`）の保存（同じ metaReducer のため同じになると判断した）。データセットの版の画面を後から開いた場合の再登録。`createUserPrefFeatureReducer` の合わせ込みが無くなる影響
- 由来：比較資料 §3.1 で、feature key・登録場所・reducer は上流と一致する。子のインジェクターの multi の provider が親の値を含まないこと、`addReducers()` が同じキーを置き換えることは、Angular・NgRx の従来からの挙動である。`@ngrx/store` 21.1.1 の `addReducers()`・`featureStateProviderFactory()` が同じであることを、作業用ディレクトリに取得して確かめた
