# 取り消せない操作に退路を用意する

| 項目 | 内容 |
| --- | --- |
| 分類 | UX体験 |
| 領域 | 自作（`features/data-catalog`・`features/quality-pipeline`） |
| 直る体験 | 押し間違い・移動の巻き添えで、入力や実行を失わない |
| 規模 | 小 |
| 状態 | 未着手 |

## いま画面で起きていること

自作画面には、押した瞬間に取り返しがつかない操作が3つある。どれにも確認も取り消しも無い。

| 操作 | 場所 | いまの挙動 |
| --- | --- | --- |
| 実行の停止 | [run-summary.component.html:18](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html#L18) | 押すと即 `tasks.stop` が飛ぶ。確認なし |
| メタデータの保存 | [catalog-metadata-form.component.html:23](../src/app/features/data-catalog/components/catalog-metadata-form/catalog-metadata-form.component.html#L23) | 直前の値は保持されず、取り消せない |
| 編集中の離脱 | [data-catalog.routes.ts:53-63](../src/app/features/data-catalog/data-catalog.routes.ts#L53) | `canDeactivate` が無い。タグを書き換えた状態でリンクを踏むと黙って消える |

取り込み領域には道具が揃っている。離脱前の確認は2本あり、性質が違う。

| ガード | 何から dirty を判定するか | 使われ方 |
| --- | --- | --- |
| [`leavingBeforeSaveAlertGuard`](../src/app/webapp-common/shared/guards/leaving-before-save-alert.guard.ts) | 引数で渡した store の selector | `models.routes.ts` で10箇所、`experiment-routes.ts` で6箇所、`reports.routes.ts` で1箇所 |
| [`generalLeavingBeforeSaveAlertGuard`](../src/app/webapp-common/shared/guards/general-leaving-before-save-alert.guard.ts#L13) | component が持つ `isDirty()` signal | 参照0件。定義だけがある |

確認ダイアログ自体は [`ConfirmDialogComponent`](../src/app/webapp-common/shared/ui-components/overlay/confirm-dialog/confirm-dialog.component.ts) である。通知に取り消しボタンを載せる経路は [layout.actions.ts:95-98](../src/app/webapp-common/core/actions/layout.actions.ts#L95) の `userActions` にある。

## なぜ変えるか

操作の重さと退路の重さは釣り合っている必要がある。停止は実行中の計算を捨てる操作で、押し直しても元には戻らない。一方でメタデータの保存は、保存前の値さえ覚えておけば戻せる。同じ「確認ダイアログ」を両方に出すと、軽いほうで確認を読まなくなり、重いほうでも読まなくなる。

そのため、退路は3段に分ける。元に戻せるものは事後の取り消し、元に戻せないものは事前の確認、失うのが入力だけのものは離脱時の確認である。

## 解決とみなす状態

1. 停止は `ConfirmDialogComponent` で確認する。本文にどの実行を止めるか（名前と Dataset version）を入れる。実行中でないときはボタンを押せない状態にする（[run-summary.component.html:18](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html#L18) の `canCancel` は既にある）
2. メタデータの保存は確認を出さない。代わりに保存後の通知へ「元に戻す」を `userActions` として置き、押すと保存前のタグと説明で `tasks.update` / `models.update` を送り直す
3. 詳細の経路に離脱前の確認を付ける。どちらのガードを使うかは選べる
   * 編集中の値を state へ上げ、`leavingBeforeSaveAlertGuard` に selector を渡す。使用実績のある側だが、いま component だけが持っている「まだ適用していない入力値」を state へ移すことになる
   * component に `isDirty` を持たせ、`generalLeavingBeforeSaveAlertGuard` を使う。入力値の置き場は変えずに済むが、参照0件の凍結領域のコードを初めて使うことになる。上流が消しても気付けないため、自作側に同じ数行を持つほうが安全な場合がある
4. 起動と停止のボタンは、要求を送っている間は押せない状態にする。Effects 側は既に `exhaustMap` で二重送信を捨てている（[quality-pipeline.effects.ts:103](../src/app/features/quality-pipeline/state/quality-pipeline.effects.ts#L103)）が、押せてしまう見た目は「効いていない」と読まれる

## 変更の範囲

* 変更：`run-summary` と、停止を dispatch する [quality-pipeline-page.component.ts](../src/app/features/quality-pipeline/containers/quality-pipeline-page/quality-pipeline-page.component.ts)
* 変更：[catalog-asset-detail-page.component.ts](../src/app/features/data-catalog/containers/catalog-asset-detail-page/catalog-asset-detail-page.component.ts) に `isDirty: Signal<boolean>` を足す
* 変更：[data-catalog.routes.ts](../src/app/features/data-catalog/data-catalog.routes.ts) に `canDeactivate`
* 追加：`data-catalog.actions.ts` に「保存前の値へ戻す」action

## 確かめ方

* 単体：`isDirty` が、フォームの値と読み込んだ値の比較で決まること。タグの並び順だけが違う場合を dirty としないこと
* E2E：[e2e/data-catalog.spec.ts](../e2e/data-catalog.spec.ts) に、書き換えた状態で一覧へ戻るとダイアログが出ることを足す

## 注意

`generalLeavingBeforeSaveAlertGuard` の本文は英語の固定文言である（[同:23](../src/app/webapp-common/shared/guards/general-leaving-before-save-alert.guard.ts#L23)）。文言を変えるなら凍結領域の変更になるため、[07](./07_時刻・数値・言語の表記を揃える.md) の言語方針と合わせて一度に決める。
