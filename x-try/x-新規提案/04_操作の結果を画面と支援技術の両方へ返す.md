# 操作の結果を画面と支援技術の両方へ返す

| 項目 | 内容 |
| --- | --- |
| 分類 | UX体験 |
| 領域 | 自作（両 feature）。live region の置き場によっては凍結領域の外枠 |
| 直る体験 | 押した操作が通ったのか、一覧が何件になったのかが分かる。画面を見ていなくても分かる |
| 規模 | 小 |
| 状態 | 未着手 |

## いま画面で起きていること

`src/app` のテンプレート全体で `aria-live` は0件である。非同期に内容が入れ替わる箇所は多いが、入れ替わったことを読み上げる側へ伝える宣言がどこにも無い。

失敗だけは届く。自作画面の失敗は `role="alert"` の段落として描かれ（[data-catalog-page.component.html:11](../src/app/features/data-catalog/containers/data-catalog-page/data-catalog-page.component.html#L11)）、[e2e/accessibility.spec.ts:58-66](../e2e/accessibility.spec.ts#L58) がそれを検査している。`role="alert"` は暗黙に `aria-live="assertive"` として働くため、失敗は割り込みで読み上げられる。

届かないのは成功と件数である。

| 出来事 | 画面の変化 | 読み上げ |
| --- | --- | --- |
| 絞り込みを適用して一覧が入れ替わる | 表の行が置き換わる | 何も起きない |
| 一覧が0件になる | [catalog-assets-table.component.html:47](../src/app/features/data-catalog/components/catalog-assets-table/catalog-assets-table.component.html#L47) の文が出る | 何も起きない |
| メタデータを保存し終える | ボタンの文字が `Saving…` から `Save` へ戻るだけ | 何も起きない |
| 実行の状態が queued → running → completed と変わる | [run-summary.component.html:3](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html#L3) の文字が変わる | 何も起きない |

保存に成功したことを示すものは、ボタンの文字が戻ることだけである。これは「保存した」と「保存しようとして何も起きなかった」を区別しない。

## なぜ変えるか

axe は、この欠落を見つけられない。[e2e/accessibility.spec.ts](../e2e/accessibility.spec.ts) が0件で通っているのは、静的な構造に違反が無いからであって、変化が伝わっているからではない。axe が見るのは1時点の DOM であり、「変わったのに黙っていた」は検査項目に無い。

画面を見ている利用者にとっても、成功の合図は要る。保存ボタンを押した後に何も変わらない画面は、押せていないのか、保存が終わったのかを区別できない。

## 解決とみなす状態

1. 自作画面の根に、`aria-live="polite"` の領域を1つ置く。視覚的には隠す（`.cdk-visually-hidden` が Angular CDK にある）
2. 次の出来事を、その領域へ短い1文として流す。「12件」「該当なし」「保存しました」「実行が完了しました」
3. 失敗はいまどおり `role="alert"` のまま。polite と assertive を混ぜない
4. 保存の成功は、加えて通知（`addMessage`）としても出す。通知には [03](./03_取り消せない操作に退路を用意する.md) の「元に戻す」を載せる
5. 件数は表の見出しにも出す。いまの `<caption>` は「Assets」と打ち切りの注記だけで（[catalog-assets-table.component.html:2-7](../src/app/features/data-catalog/components/catalog-assets-table/catalog-assets-table.component.html#L2)）、何件あるかを言っていない

## 変更の範囲

* 追加：`shared/` に live region の部品（入力は文字列1つ、変化したときだけ差し替える）
* 変更：2つの container のテンプレートと、件数・保存結果を文字列に変える純関数
* 変更：`catalog-assets-table` の `<caption>`

## 確かめ方

* 単体：件数・空・打ち切りの3状態から文面を作る関数を、境界値（0件、上限ちょうど、上限超え）で確かめる
* E2E：既存の a11y 検査に、絞り込みを適用した後 live region の文字列が変わることを足す。axe の違反0件は維持する

## 注意

live region は、内容を一度空にしてから入れ直さないと同じ文字列が再読み上げされない実装がある。件数が2回続けて同じになる場合（絞り込みを変えたが結果が同じ）に何も読まれないのは許容するか、末尾に区別を付けるかを決めておく。
