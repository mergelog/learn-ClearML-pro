## いま画面で起きていること

自作画面の入力欄は、値の形に関わらずすべて素の `<input>` である。

| 欄 | 値の形 | いまの入力欄 | 起きること |
| --- | --- | --- | --- |
| Tags（絞り込み） | 複数の語 | 区切り文字を説明した `type="text"` ＋ `datalist`（[catalog-filters.component.html:31-46](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.html#L31)） | 打ち込んだ語が既存のタグと一致しているか、押すまで分からない |
| Tags（編集） | 複数の語 | 同上（[catalog-metadata-form.component.html:3-12](../src/app/features/data-catalog/components/catalog-metadata-form/catalog-metadata-form.component.html#L3)） | 候補の提示すら無い |
| Project | 既存の集合から1つ | `datalist` 付きの自由入力（[同:7-18](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.html#L7)） | 存在しない名前を入れても、0件になるまで分からない |
| Updated from / to | 期間 | 独立した `type="date"` 2つ（[同:49-55](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.html#L49)） | from > to を入れても止まらない |
| Dataset version | `1.0.0` 形式 | `type="text"` ＋ 正規表現（[start-run-form.component.html:17-24](../src/app/features/quality-pipeline/components/start-run-form/start-run-form.component.html#L17)） | 存在しない版でも書式さえ合えば起動できる |

絞り込みのフォームには検証が1つも無い（[catalog-filters.component.ts:53-62](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.ts#L53)）。

`aria-invalid` の付け方にも問題がある。[start-run-form.component.html:22](../src/app/features/quality-pipeline/components/start-run-form/start-run-form.component.html#L22) は `form.controls.datasetVersion.invalid` をそのまま渡すため、画面を開いた直後の空欄が「不正」として読み上げられる。まだ何も打っていない欄を誤りとして扱っている。

取り込み領域には、複数の語を扱う入力欄がある。[`SelectAutocompleteWithChipsComponent`](../src/app/webapp-common/shared/ui-components/inputs/select-autocomplete-with-chips/) と [`ChipsComponent`](../src/app/webapp-common/shared/ui-components/buttons/chips/) である。自作 feature からの参照は0件である。

## なぜ変えるか

入力欄の形は、その欄が受け付ける値の説明である。区切り文字を文章で説明しなければならない時点で、欄の形が値と合っていない。タグを1つ消すのに文字列の途中からカンマごと削るのは、値が複数であることを欄が表現していないからである。

検証の時機も分かれている。押す前に断れるもの（書式、期間の前後関係）と、送ってみないと分からないもの（その版の Dataset が存在するか）は別である。前者を送ってから断るのは待ち時間の無駄で、後者を押す前に断るふりをするのは嘘になる。

## 解決とみなす状態

1. タグの欄をチップにする。1つずつ消せて、既存のタグから選べる。絞り込みと編集の両方で同じ部品を使う
2. プロジェクトの欄を、既存の集合から選ぶ形にする。選択肢が読めなかったときだけ自由入力へ落とす（[catalog-filters.component.ts:42-44](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.ts#L42) の判断を維持する）
3. 期間の検証を足す。from > to のときは Apply を押せない状態にし、理由を欄の下に出す
4. `aria-invalid` と誤りの表示は、その欄を離れた後（touched）に限る。空欄の初期状態を誤りとしない
5. Dataset version は書式の検証を残したうえで、既知の版を候補として出す。候補に無い版でも起動できる状態は変えない（[15](./15_実行の起動を入力から選択へ変える.md) で扱う）

## 変更の範囲

* 変更：`catalog-filters`・`catalog-metadata-form`・`start-run-form` のテンプレートと TS
* 判断：チップの部品を凍結領域から借りるか、自作側に1つ作るか。借りる場合は `imports` に足すだけで、凍結領域の変更にはあたらない。ただし見た目は Material に揃うため、自作画面の残りと食い違う（[18](./18_自作画面と取り込み画面の見た目を揃える.md)）

## 確かめ方

* 単体：期間の前後関係の検証。タグの重複と空文字の除去
* E2E：a11y 検査を維持する。チップの追加・削除がキーボードだけでできることを [e2e/accessibility.spec.ts](../e2e/accessibility.spec.ts) に足す
