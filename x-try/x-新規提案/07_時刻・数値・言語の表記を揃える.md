# 時刻・数値・言語の表記を揃える

| 項目 | 内容 |
| --- | --- |
| 分類 | UX体験 |
| 領域 | 自作（両 feature）。言語の方針は凍結領域を含む全体の判断 |
| 直る体験 | 同じ実行の時刻が、画面ごとに違う値に見えない |
| 規模 | 時刻と数値は小。言語は大 |
| 状態 | 未着手（言語は方針の決定が先） |

## いま画面で起きていること

### 時刻

自作画面は4つの component がそれぞれ別の書式を宣言し、すべて UTC 固定である。

| 場所 | 書式 | 時間帯 |
| --- | --- | --- |
| [catalog-assets-table.component.ts:35](../src/app/features/data-catalog/components/catalog-assets-table/catalog-assets-table.component.ts#L35) | `yyyy-MM-dd HH:mm z` | UTC |
| [catalog-asset-facts.component.ts:26](../src/app/features/data-catalog/components/catalog-asset-facts/catalog-asset-facts.component.ts#L26) | `yyyy-MM-dd HH:mm z` | UTC |
| [run-summary.component.ts:26](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.ts#L26) | `y-MM-dd HH:mm:ss z` | UTC |
| [pipeline-steps-table.component.ts:22](../src/app/features/quality-pipeline/components/pipeline-steps-table/pipeline-steps-table.component.ts#L22) | `HH:mm z` | UTC |

取り込み領域は [constants.ts:11](../src/app/webapp-common/constants.ts#L11) の `TIME_FORMAT_STRING = 'MMM d yyyy H:mm'` を17ファイルで共有し、時間帯を指定しない（＝ブラウザの現地時刻）。

この2つが噛み合わない。台帳で `2026-09-12 03:14 UTC` と読んだ実行を、ClearML 側の画面（[catalog-asset-facts.component.html:45](../src/app/features/data-catalog/components/catalog-asset-facts/catalog-asset-facts.component.html#L45) のリンク先）で開くと `Sep 12 2026 12:14` と出る。同じ実行の同じ時刻である。

ステップの表はさらに日付を落としている。`HH:mm z` だけなので、前日に走ったステップと今日のステップが同じ表記になる。

### 詳細の日時

詳細画面の Facts は、値を素の文字列として出している。[data-catalog.adapter.ts:137-164](../src/app/features/data-catalog/data-access/data-catalog.adapter.ts#L137) が作る `Registered`・`Started`・`Finished` は ClearML の応答そのままで、[catalog-asset-facts.component.html:39](../src/app/features/data-catalog/components/catalog-asset-facts/catalog-asset-facts.component.html#L39) は `{{ fact.value }}` としか書いていない。同じ画面の上半分（`Updated`）は書式を通り、下半分（`Started`）は通らない。[production-model-card.component.html:9-10](../src/app/features/quality-pipeline/components/production-model-card/production-model-card.component.html#L9) の `Promoted at` も同じである。

### 言語

`src/index.html` の `lang` は `en` 固定（[index.html:2](../src/index.html#L2)）で、`$localize` も翻訳の仕組みも入っていない。画面の文言はすべて英語で、利用者は日本語話者である。

## なぜ変えるか

時刻の表記は、値そのものではなく値の読み方を決める。同じ瞬間が画面によって9時間ずれて見えると、利用者は差を時差として理解するのではなく、別の実行を見ていると理解する。

UTC 固定という選択自体には理由がある。ML の実行はサーバ側の時刻で記録され、ログやコンテナの時刻と突き合わせるときは UTC のほうが揃う。問題は、その選択が画面の半分にしか適用されていないことである。

## 解決とみなす状態

1. 書式の定義を1箇所へ寄せる。自作側の `shared/` に定数を置き、4つの component はそれを読む
2. 日付を落とさない。ステップの表も日付を含む書式にする（列幅が足りないなら、相対表記と絶対表記を組み合わせる）
3. 詳細の Facts のうち日時であるものを、値ではなく型として持つ。`CatalogFact` に `kind: 'text' | 'timestamp' | 'id'` を足し、テンプレート側で書式を決める
4. UTC と現地時刻のどちらを既定にするかを1度決め、決めた側に全画面を揃える。両方出す場合は、片方を主、もう片方を補足（`title` 属性かツールチップ）にする
5. 言語は別の決定として切り出す。決めるのは、自作画面だけ日本語にするか、凍結領域を含めて仕組みを入れるか、英語のままにするかの3択である

## 変更の範囲

* 変更：上表の4 component と `data-catalog.adapter.ts`・`data-catalog.model.ts`（`CatalogFact` の型）
* 判断：時間帯の既定。ADR に残す価値がある
* 判断：言語の方針。`$localize` を入れると凍結領域の1687ファイルが対象になり、費用は自作分に出ない（[BL-05](../docs/backlog/05_zoneless.md) と同じ構造の判断になる）

## 確かめ方

* 単体：`CatalogFact` の種別ごとの表示を確かめる。空文字（[data-catalog.adapter.ts:138](../src/app/features/data-catalog/data-access/data-catalog.adapter.ts#L138) は `?? ''` で埋める）を日時として描かないこと
* 目視：同じ実行を台帳と ClearML の両画面で開き、時刻が一致すること
