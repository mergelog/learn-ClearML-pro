# 来歴を鎖として見せる

| 項目 | 内容 |
| --- | --- |
| 分類 | ML体験 |
| 領域 | 自作（`features/data-catalog`） |
| 直る体験 | どのデータからどのモデルが出たかを、一目で辿れる |
| 規模 | 小〜中 |
| 状態 | 未着手 |

## いま画面で起きていること

来歴の表示は、この feature の存在理由として作られている。[catalog-lineage.component.ts:9-11](../src/app/features/data-catalog/components/catalog-lineage/catalog-lineage.component.ts#L9) は「ClearML の画面は Dataset は Dataset、Model は Model と縦に割れていて、『このモデルはどのデータから来たのか』を一画面で答える場所が無い」と書いている。

出てくるのは、順序付きリストの3行である。

```
Dataset   wafer-defects 1.0.0
Run       semiconductor-quality-training 1.0.0
Model     semiconductor-quality-classifier
```

［[catalog-lineage.component.html:1-22](../src/app/features/data-catalog/components/catalog-lineage/catalog-lineage.component.html#L1)］

この表示には、3つの情報が落ちている。

**向き。** 並びが `Dataset → Run → Model` で固定であることは component の注釈に書かれているが、画面には出ていない。`<ol>` の並び順としてしか表現されていないため、これが流れの向きなのか、単なる一覧なのかが読み取れない。

**いまどこを見ているか。** state はそれを持っている。[data-catalog.model.ts:123-124](../src/app/features/data-catalog/data-catalog.model.ts#L123) の `CatalogLineage.origin` がそれで、型の注釈も「画面は『いま見ている資産がどこにいるか』を `origin` で知る」と書いている。ところが [data-catalog.selectors.ts:71-74](../src/app/features/data-catalog/state/data-catalog.selectors.ts#L71) は3つの節だけを取り出し、`origin` を捨てている。component の入力にも無い（[catalog-lineage.component.ts:35-41](../src/app/features/data-catalog/components/catalog-lineage/catalog-lineage.component.ts#L35)）。結果として、Model から開いても Dataset から開いても同じ3行が出る。

**切れ方の区別。** 節が消えていること（`nodes` に現れない）と、節はあるが実体が消えていること（`asset === null`）は別々に描き分けられている。しかし両者は離れた場所に出る。実体が消えた節は行の中（[同:8-11](../src/app/features/data-catalog/components/catalog-lineage/catalog-lineage.component.html#L8)）、節が足りないことはリストの外の段落（[同:24-28](../src/app/features/data-catalog/components/catalog-lineage/catalog-lineage.component.html#L24)）である。どの位置が切れているかは分からない。

## なぜ変えるか

来歴は、節の一覧ではなく繋がりである。繋がりを読み取らせたいなら、節と節のあいだに何かが要る。矢印1つで足りる。

いま見ている資産の位置は、来歴を読むときの起点になる。「このモデルの出所」を知りたくて開いた画面で、どれが「このモデル」なのかが分からないのは、情報が足りないのではなく、持っている情報を渡していないだけである。

## 解決とみなす状態

1. 節のあいだに向きを描く。矢印でよい。図の描画ライブラリは要らない
2. `origin` を selector から component まで渡し、いま見ている節を区別できるようにする。`aria-current` を付けて、読み上げる側にも伝える
3. 切れている位置を鎖の中で示す。3つの節の枠は常に描き、辿れなかった節はその位置で「辿れなかった」と言う。いまの「実体が消えた節」の扱い（IDを残す）と揃う
4. 節に、その節を判断するための1行を添える。Dataset なら版数、Run なら状態と終了時刻、Model なら提供中かどうかである。いまは名前だけで、リンクを踏まないと何も分からない
5. 3節より長い鎖（Dataset が別の Dataset から派生している場合など）を扱うかどうかを決める。扱わないなら、扱わないことを画面で言う

## 変更の範囲

* 変更：[data-catalog.selectors.ts](../src/app/features/data-catalog/state/data-catalog.selectors.ts)（`origin` と、節ごとの欠落理由を渡す形へ）
* 変更：[catalog-lineage](../src/app/features/data-catalog/components/catalog-lineage/) の3ファイル
* 変更：`CatalogLineageNode` に、節ごとの1行分の情報を足す。`CatalogAsset` に既にある値で足りるかを先に確かめる

## 確かめ方

* 単体：`origin` が3種別それぞれのときに、正しい節が現在として印されること。節が欠けているときに位置がずれないこと
* E2E：[e2e/data-catalog.spec.ts](../e2e/data-catalog.spec.ts) の詳細画面の検査に、現在位置の印を足す。axe の違反0件を維持する
