| 項目 | 内容 |

## いま何が検出できているか

体験に関わる検査は、すでに3層ある。

| 層 | 何を見ているか | 場所 |
| --- | --- | --- |
| lint | テンプレートの規則（`templateAccessibility`） | [eslint.config.js:76-84](../eslint.config.js#L76) |
| E2E | 自作画面の axe 違反0件、失敗の読み上げ、キーボードだけでの起動 | [e2e/accessibility.spec.ts](../e2e/accessibility.spec.ts) |
| 境界 | 依存の方向と公開面 | [web-boundaries.json](../web-boundaries.json)、[data-catalog.surface.published.json](../src/app/features/data-catalog/data-catalog.surface.published.json) |

自作の範囲は baseline を作らず0件で固定するという決め方も明記されている（[e2e/accessibility.spec.ts:6-18](../e2e/accessibility.spec.ts#L6)）。

この3層が見ていないものが、この提案書で挙げた課題の大半である。

| この提案書で挙げた課題 | いまの検査で見つかるか | 理由 |
| --- | --- | --- |
| 焦点が見えない（[08](./08_フォーカスが見えるようにする.md)） | 見つからない | axe は `outline: none` を違反としない。E2E は `toBeFocused()` を見ており、見えるかは見ていない |
| 変化が読み上げられない（[04](./04_操作の結果を画面と支援技術の両方へ返す.md)） | 見つからない | axe は1時点の DOM を見る。変化したのに黙っていたことは検査項目に無い |
| 時刻の表記が画面ごとに違う（[07](./07_時刻・数値・言語の表記を揃える.md)） | 見つからない | 個々の画面としては正しい |
| 未保存のまま離れられる（[03](./03_取り消せない操作に退路を用意する.md)） | 見つからない | 経路の設定に `canDeactivate` が無いことは、どの検査も見ていない |
| 待ち時間の表示が画面ごとに違う（[01](./01_待ち時間の見せ方を揃える.md)） | 見つからない | 同上 |

つまり、いまの検査は「1つの画面が規則に適合しているか」を見ていて、「画面をまたいで同じ約束が守られているか」を見ていない。

## なぜ変えるか

この提案書の19件を一度直しても、次に画面を1つ足したときに同じ状態へ戻る。戻らないようにする費用は、直す費用より小さい。

ただし、置く層を誤ると費用が跳ね上がる。E2E の枠は 29/30 で1件しか空いていない（[BL-09](../docs/backlog/09_E2Eと初期束の余裕.md)）。観点を1つ足すたびに E2E を1本増やす形は、テストの層の設計（[ADR 005](../docs/_archive/adr/005_20260911_test_pyramid.md)）と衝突する。

一方で、画面をまたいだ約束の多くは、実行しなくても確かめられる。ファイルの中身を読めば分かるものは、E2E ではなく script の検査にできる。

## 解決とみなす状態

1. 「画面をまたいだ約束」を script の検査にする。既に同じ形の検査が `scripts/` に並んでいる（`web-boundaries.mjs`・`pipeline-contract.mjs`・`docs-links.mjs`）ので、そこへ1本足す形になる。見る対象は次のようなものである
   * 時刻の書式を、共通の定数以外から取っている component が無いこと
   * 編集を持つ経路に `canDeactivate` が付いていること
   * 自作のテンプレートに `outline: none` が無いこと
2. 焦点の可視性は、E2E ではなく手順として残す。自動で測るには描画の比較が要り、揺らぎが大きい
3. 読み上げの変化は、live region の中身を見る単体テストにする。部品として作れば（[04](./04_操作の結果を画面と支援技術の両方へ返す.md)）、その部品の単体テストで足りる
4. 凍結領域の違反を、自作の0件と混ぜない。いまの `include(OWN_SCREEN)` の切り方を維持する。凍結領域の a11y 違反は `x-不具合調査` の 29・32〜35・37 として既に台帳にある
5. 新しい画面を足すときの確認項目を1枚にまとめる。この提案書の19件のうち、画面を足すたびに関わるものを抜き出したもの

## 変更の範囲

* 追加：`scripts/` に検査を1本。`web:gates:test` の対象（`scripts/tests/**`）へ単体テストも足す
* 変更：[.github/workflows/ci.yml](../.github/workflows/ci.yml) の `web` の段に追加
* 追加：確認項目の1枚（置き場は `docs/phase7_チーム開発標準/` か、この `x-新規提案/` か）

## 注意

検査を足すときは、何を見ないかも書く。`docs-links.mjs` の冒頭（[scripts/docs-links.mjs:9-11](../scripts/docs-links.mjs#L9)）が「リンクの先に在るかだけを見る。書いてある説明が正しいかは読まなければ分からない」と書いているのと同じ形にする。見ていないものを見ているつもりになる検査は、無い検査より悪い。
