# ログの「Filter By Regex」が、貼り付けなどキー操作を伴わない入力では反映されない

| 項目 | 内容 |
|---|---|
| カテゴリー | 操作 |
| 不具合内容 | CONSOLE（ログ）のフィルタ欄は keyup で値を読むため、右クリックの貼り付け、ドラッグ、変換候補のクリックでの確定など、キーを離す操作を伴わない入力ではログが絞り込まれない。入力欄には文字が入っているのに、ログは絞り込み前のまま表示される。次に何かのキーを押すと反映される |
| 期待動作 | 入力欄の値が変わるたびに、どの手段で入力してもフィルタが反映される |
| 直さないと困ること | 利用者が、入力欄の条件で絞り込んだ結果だと思い込み、該当する行を見落とす、または一致する行が無いと誤解する |
| 修正規模 | 極小 |

| 項目 | 内容 |
|---|---|
| 画面 | 実験管理 > 詳細 > CONSOLE、パイプラインのステップのログ、データセット版の詳細のログ（`sm-experiment-output-log` を使う画面） |
| 観点 | A（キーボード操作と IME） |
| 重大度 | S3 |
| 確度 | 再現済み（貼り付けの代わりに、keyup を発生させない Playwright の `fill` で確認） |
| 由来 | 上流 |
| 発生条件 | 右クリックメニューの貼り付け、テキストのドラッグ＆ドロップ、IME の変換候補のクリックでの確定、ブラウザの自動入力 |
| 関連 | なし |

## 症状

ログが31行表示されている状態で、フィルタ欄に一致する行の無い文字列を `fill` で入れても31行のまま変わらない。続けて End キーを押すと、0行になる。

変換中は、打鍵ごとの keyup で未確定の文字列（「えぽっk」など）で絞り込まれる。絞り込みは画面内で行われ API は呼ばれないため、これ自体の実害は小さい。ただし確定を候補のクリックで行うと keyup が届かないため、確定後の文字列ではなく最後の keyup の時点の文字列で絞り込まれたまま残るはずである（コードからの推論で、実機では確かめていない）。

## 再現手順

実バックエンドの既存タスク（ログのあるもの）で行う（読み取りだけ）。

1. タスクの詳細で CONSOLE を開く
2. 別の場所でコピーした文字列を、フィルタ欄に右クリックメニューから貼り付ける
3. ログが絞り込まれない。フィルタ欄で End キーなどを押すと絞り込まれる

スクリプトは [scripts/p2a-log-filter-keyup.spec.ts](./scripts/p2a-log-filter-keyup.spec.ts)。Playwright の `fill` は input イベントだけを発生させ keydown / keyup を発生させないため、貼り付けの代わりに使った。

## 期待する動作

入力欄の値が変わった時点で（input イベントで）フィルタが反映される。

## 原因

[experiment-output-log.component.html:16](../src/app/webapp-common/experiments/containers/experiment-output-log/experiment-output-log.component.html#L16) が `(keyup)="filterLog($event)"` で値を拾い、[filterLog()](../src/app/webapp-common/experiments/containers/experiment-output-log/experiment-output-log.component.ts#L151) が `event.target.value` を `setLogFilter` に渡す。値の変化ではなくキーを離す操作に反応しているため、キーを伴わない入力を取りこぼす。

## 影響範囲と同種箇所

`sm-experiment-output-log` を使う画面すべて（実験の CONSOLE、[pipeline-controller-info](../src/app/webapp-common/pipelines-controller/pipeline-controller-info/pipeline-controller-info.component.html) のステップのログ、[open-dataset-version-info](../src/app/webapp-common/dataset-version/open-dataset-version-info/open-dataset-version-info.component.html) のログ）。

`(keyup)` で入力値を読む箇所は、ほかに `duration-input`・`duration-input-list`（数字の桁送り）と `period-selector`（日付範囲、`keyup.enter`）がある。前者はフォーカスの移動だけで値の反映は `(input)` や blur で行っており、後者は blur でも確定するため、同じ症状は出ない。

## 対策案

`(keyup)` を `(input)` に替える。変換中の途中経過で絞り込むのを避ける場合は、[09](./09_検索欄で変換中の文字列で検索が走り確定後の検索語と食い違う.md) と同じく `compositionend` で確定値を反映する。前者だけならテンプレートの1箇所の変更のため「極小」とした。

## 検証範囲

- 確認したこと：Playwright（Chromium、実バックエンドの既存タスク）で、`fill` ではログが絞り込まれず、続く End キーで絞り込まれること。変換中の文字列を置いて keyup を合成すると、未確定の文字列で絞り込まれること
- 確認していないこと：実際の右クリックメニューからの貼り付け（Playwright から操作できない）と、実機の IME の変換候補のクリックでの確定
- 由来：`experiment-output-log.component.*` は比較資料で上流と一致する（§5 の `@ngrx/signals` 使用ファイルの表で「完全一致」）
