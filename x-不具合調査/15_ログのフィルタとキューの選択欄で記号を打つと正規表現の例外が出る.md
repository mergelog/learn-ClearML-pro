# ログのフィルタとキューの選択欄で、`(` などの記号を打つと正規表現の例外が出て、表示が入力と合わなくなる

| 項目 | 内容 |
|---|---|
| カテゴリー | 画面UI |
| 不具合内容 | CONSOLE（ログ）の「Filter By Regex」に正規表現として完結していない文字列（`(`、`[INFO` など）を入れると例外が出て、ログの表示が入力と対応しない状態になる。Enqueue ダイアログのキューの選択欄では、キュー名に含まれる記号（`(` など）を打つと例外が出て、候補の強調表示が崩れる。`.` を打つと、候補の名前の全文字が1文字ずつ強調される |
| 期待動作 | ログのフィルタは、正規表現として不正な間は絞り込みを保留するか、エラーを示す。キューの選択欄は、打った文字をそのままの文字列として強調する |
| 直さないと困ること | ログを正規表現で絞り込む途中（`(error|warn)` を打ち終えるまで）や、`[INFO]` のような記号を含む語を探すときに、表示が入力と合わず、利用者が絞り込みの結果を誤解する |
| 修正規模 | 小 |

| 項目 | 内容 |
|---|---|
| 画面 | 実験管理 > 詳細 > CONSOLE ほかログの表示（[10](./10_ログのフィルタがキー操作を伴わない入力では反映されない.md) と同じ画面）、実験のメニュー > Enqueue、ワーカーとキュー > キューの詳細からのタスクの移動 |
| 観点 | B（文字列の値の扱い：検索語の扱い） |
| 重大度 | S3（ログのフィルタ）。キューの選択欄は S4 |
| 確度 | 再現済み（ログのフィルタは実バックエンド、キューの選択欄はモック API） |
| 由来 | 上流 |
| 発生条件 | ログのフィルタ：正規表現として不正な文字列。キューの選択欄：キュー名に正規表現の記号（`(`・`)`・`[`・`.`・`+`・`*`・`?` など）が含まれ、その記号を含む語を打つ |
| 関連 | [10](./10_ログのフィルタがキー操作を伴わない入力では反映されない.md)（同じフィルタ欄の別の不具合） |

## 症状

| 箇所 | 入力 | 起きること | 確認 |
|---|---|---|---|
| ログのフィルタ | `zzz` → 消して `(` | `SyntaxError: Invalid regular expression: /(/i: Unterminated group` がコンソールに出る。ログは31行中1行だけが表示され、どの条件とも対応しない | 再現（実バックエンド） |
| キューの選択欄（キュー名 `gpu(2)`） | `gpu(` | `SyntaxError: Invalid regular expression: /gpu(/gi: Unterminated group`。候補の `gpu(2)` の強調（太字）が消える | 再現（モック API） |
| キューの選択欄（キュー名 `v1.2-queue`） | `.` | 候補の絞り込みは `.` を含む名前だけになる（正しい）が、強調は `v`・`1`・`.`・`2`・…と全文字が1文字ずつ太字になる | 再現（モック API） |

ログのフィルタは正規表現で絞り込む欄であり、`[INFO]` が文字クラスとして解釈されること自体は仕様である。問題は、不正な正規表現を入れたときに例外で処理が中断し、表示が入力と食い違うことである。

## 再現手順

ログのフィルタ（実バックエンドのログのあるタスク、読み取りだけ）：

1. タスクの CONSOLE を開く
2. 「Filter By Regex」に `(` と打つ
3. コンソールに `SyntaxError` が出て、ログの表示が入力と対応しなくなる

キューの選択欄（モック API で、`gpu(2)`・`default`・`v1.2-queue` の3つのキューを返す）：

1. 下書きのタスクのメニューから Enqueue を選ぶ
2. キューの欄に `gpu(` と打つ。コンソールに `SyntaxError` が出る
3. 欄を空にして `.` と打つ。`v1.2-queue` の全文字が1文字ずつ太字になる

スクリプトは [scripts/p2b-regex-input.spec.ts](./scripts/p2b-regex-input.spec.ts)。

## 期待する動作

- ログのフィルタ：正規表現として不正な間は、直前の有効な条件か絞り込みなしで表示し、入力欄にエラーを示す
- キューの選択欄：打った文字を文字どおりに探して強調する（絞り込みの `includes` と同じ扱い）

## 原因

ログのフィルタは、[experiment-log-info.component.ts:73](../src/app/webapp-common/experiments/dumb/experiment-log-info/experiment-log-info.component.ts#L73) の入力の setter が、`hasFilter` を更新した後に [getRegexFromString()](../src/app/webapp-common/experiments/dumb/experiment-log-info/experiment-log-info.component.ts#L185) で `new RegExp(filter, 'i')` を作る。例外処理が無いため、不正な文字列で例外が投げられると、`regex` は前の値のまま `hasFilter` だけが更新され、行の再計算（`calcLines()`）も行われない。

キューの選択欄は、候補の絞り込み（[select-queue.component.ts:78](../src/app/webapp-common/experiments/shared/components/select-queue/select-queue.component.ts#L78)）は `includes` で文字どおりに比べるが、強調表示（[select-queue.component.html:54](../src/app/webapp-common/experiments/shared/components/select-queue/select-queue.component.html#L54)）は [splitLine()](../src/app/webapp-common/shared/utils/shared-utils.ts#L271) が打った文字を `new RegExp(search, 'gi')` に渡す。エスケープしていないため、記号を含む語で例外になるか、`.` のように意味の違う正規表現として働く。プロジェクトに既にある [escapeRegex()](../src/app/webapp-common/shared/utils/escape-regex.ts) を通していない。

## 影響範囲と同種箇所

利用者の入力を `new RegExp` に渡す箇所を全体で探した（`new RegExp(` の grep）。一覧の検索（`_any_.pattern`）は、正規表現モードでないときにすべて `escapeRegex()` を通している。エスケープも例外処理も無いのは上の2箇所だけだった。

`sm-select-queue` は、実験のメニューの Enqueue（[experiment-menu.component.ts:204](../src/app/webapp-common/experiments/shared/components/experiment-menu/experiment-menu.component.ts#L204)）と、キューの詳細（[queue-info.component.ts:135](../src/app/webapp-common/workers-and-queues/dumb/queue-info/queue-info.component.ts#L135)）から開く。

## 対策案

- ログのフィルタ：`getRegexFromString()` を try/catch で囲み、不正なら絞り込みを保留してエラーの状態を持つ（入力欄の下にエラーを出す）
- キューの選択欄：`splitLine()` の中で `escapeRegex(search)` を通す

2ファイルの数行の変更と、入力欄のエラー表示の追加で「小」とした。

## 検証範囲

- 確認したこと：Playwright（Chromium）で、ログのフィルタ（実バックエンドの既存タスク）に `(` を入れたときの例外と表示の行数。キューの選択欄（モック API）で、`gpu(` での例外と `.` での強調表示
- 確認していないこと：実バックエンドのキュー名（記号を含むキューが無く、作成は書き込みを伴うため行っていない）。キューの詳細から開いたときの画面上の症状（同じ部品のため同じになると判断した）
- 由来：`experiment-log-info`・`select-queue`・`shared-utils` は比較資料で上流と一致する
