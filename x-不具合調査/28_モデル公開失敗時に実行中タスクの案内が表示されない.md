# モデル公開が実行中タスクのため失敗しても、原因別の案内が表示されない

| 項目 | 内容 |
|---|---|
| カテゴリー | 画面UI |
| 不具合内容 | モデルの公開が作成元タスクの実行中（API の `result_subcode=110`）で失敗しても、作成元タスクへのリンクを含む案内ではなく、一般的な失敗文だけが表示される |
| 期待動作 | 実行中の作成元タスクを止めるか完了させて再試行できることを、該当タスクへのリンク付きで案内する |
| 直さないと困ること | 利用者は公開失敗の理由と次の操作を把握できず、作成元タスクを手作業で探す必要がある |
| 修正規模 | 小 |

| 項目 | 内容 |
|---|---|
| 画面 | モデル > 一覧・詳細 > PUBLISH |
| 観点 | I（HTTP とエラー表示） |
| 重大度 | S3 |
| 確度 | コード上確定 |
| 由来 | 上流 |
| 発生条件 | `models.publish_many` が `result_subcode=110` を返し、選択モデルに作成元タスクがある場合 |
| 関連 | [23](./23_APIが一度失敗するとタスクの作成やキューの削除などが再読み込みまで何もしなくなる.md)（API 失敗の扱い） |

## 症状

本来は「このモデルを作成したタスクが実行中かもしれない」と表示し、該当タスクを開けるようにしている。しかし公開 Effect は選択モデルの**配列**を渡し、メッセージ生成側は単体モデルの `task` を読むため、この分岐には到達しない。常に `Your attempt to publish models failed.` が表示される。

## 再現手順

1. 実行中の training task が出力した、未公開のモデルを開く
2. **PUBLISH** を実行する
3. サーバーが「作成元タスクが実行中」の失敗（`result_subcode=110`）を返す
4. 汎用的な失敗文だけが表示され、原因と作成元タスクへのリンクが出ない

実バックエンドへの公開書き込みは避けた。選択モデルの配列と単体モデルの不一致、110 分岐への到達不能はコードで確認した。

## 原因

[models-menu.effects.ts:53](../src/app/webapp-common/models/effects/models-menu.effects.ts#L53) は `action.selectedEntities`（`SelectedModel[]`）を `publishModelFailedText()` に渡す。一方、同メソッドは [同:97](../src/app/webapp-common/models/effects/models-menu.effects.ts#L97) で `model.task` を読む。配列自身には `task` がないため、110 であっても [同:108](../src/app/webapp-common/models/effects/models-menu.effects.ts#L108) の一般メッセージへ落ちる。

## 影響範囲と同種箇所

- モデル一覧からの複数選択と、モデル詳細からの単体選択のどちらも同じ `publishModelClicked` Effect を通る
- 作成元タスクを持たないモデル、または 110 以外の失敗では一般メッセージで問題ない
- タスクの公開など、他の公開操作にはこの `publishModelFailedText()` を使う箇所はない

## 対策案

引数を `models: SelectedModel[]` として扱い、110 のときは作成元タスクを持つモデルを選ぶ。複数のモデルが失敗した場合は、API 応答で対象を特定できるときだけリンクを出し、特定できない場合は一般メッセージへ戻す。単体の `model` を渡す設計にする場合でも、Effect 側で `action.selectedEntities[0]` を明示し、複数選択時の文言を別にする必要がある。

## 検証範囲

- 確認したこと：公開要求、HTTP 失敗、`result_subcode=110` の条件、メッセージ生成引数の型とプロパティ参照を追跡した
- 確認していないこと：実バックエンドでの 110 応答。調査用モデルを公開済みに変えないため、書き込みはしていない
- 由来：`models-menu.effects.ts` は比較資料で実質差分に含まれない
