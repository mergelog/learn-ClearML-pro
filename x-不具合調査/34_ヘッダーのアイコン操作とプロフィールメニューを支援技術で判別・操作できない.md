# ヘッダーのアイコン操作とプロフィールメニューを支援技術で判別・操作できない

| 項目 | 内容 |
|---|---|
| カテゴリー | 操作 |
| 不具合内容 | 全体検索・ヘルプのアイコンボタンに accessible name がなく、プロフィールメニューの trigger が対話要素ではない `span` のため不正な ARIA 属性になる |
| 期待動作 | 各操作に目的を表す accessible name を付け、メニュートリガーはキーボード操作できる button にする |
| 直さないと困ること | スクリーンリーダー利用者はヘッダーの検索・ヘルプ・プロフィールメニューを判別またはキーボード操作できない |
| 修正規模 | 小 |

| 項目 | 内容 |
|---|---|
| 画面 | 全画面共通ヘッダー |
| 観点 | J（操作性とアクセシビリティ） |
| 重大度 | S2 |
| 確度 | 再現済み（axe） |
| 由来 | 上流 |
| 発生条件 | スクリーンリーダー、音声操作、またはキーボードでヘッダーを操作する場合 |
| 関連 | [29](./29_実験詳細のアイコンボタンに操作名がなく支援技術で判別できない.md)、[35](./35_共通のアイコン操作に操作名がない.md) |

## 症状

`/dashboard` の `sm-header` に axe 4.13.0 を実行すると、critical の違反が出る。

| axe ルール | 対象 | 検出内容 |
|---|---|---|
| `button-name` | 全体検索、Resources（ヘルプ） | アイコンだけで名前がない |
| `aria-allowed-attr` | プロフィールの `span.menu-trigger` | `MatMenuTrigger` が付与する ARIA 属性を `span` が許容しない |

## 再現手順

1. ダッシュボードを開く
2. `npx playwright test -c x-不具合調査/scripts/playwright.config.ts p3-later-screens.spec.ts --grep 'axe'` を実行する
3. `/dashboard` の `button-name` と `aria-allowed-attr` を確認する

## 原因

- [header.component.html:31](../src/app/webapp-common/layout/header/header.component.html#L31) の全体検索ボタンと[同:38](../src/app/webapp-common/layout/header/header.component.html#L38) の Resources ボタンは、`aria-label` も可視テキストも持たない
- [同:41](../src/app/webapp-common/layout/header/header.component.html#L41) は、メニュートリガーを非対話要素の `span` に付けている
- `smTooltip` は hover 用で、ボタンの accessible name にはならない

## 影響範囲と同種箇所

`sm-header` はログイン後の全画面に置かれるため、フェーズ3で確認したダッシュボード、プロジェクト、パイプライン、データセット、レポート、ワーカー、エンドポイント、設定、enterprise すべてに影響する。

## 対策案

全体検索と Resources にそれぞれ `aria-label="全体を検索"`、`aria-label="ヘルプとリソース"` を付ける。プロフィールの `span` は `button type="button"` に置き換え、`aria-label="プロフィールメニュー"` を付け、既存の見た目はヘッダーのスタイルで維持する。

## 検証範囲

- 確認したこと：実バックエンドでログイン後、Playwright（Chromium）と axe 4.13.0 でヘッダーを検査した
- 確認していないこと：実スクリーンリーダーでの読み上げ
- 由来：対象ファイルは比較資料で実質差分に含まれない
