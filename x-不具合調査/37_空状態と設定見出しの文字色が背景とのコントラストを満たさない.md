# 空状態と設定見出しの文字色が背景とのコントラストを満たさない

| 項目 | 内容 |
|---|---|
| カテゴリー | 画面UI |
| 不具合内容 | レポート・エンドポイントの空状態メッセージと設定画面の見出しが、通常文字に必要なコントラストを満たさない |
| 期待動作 | 通常サイズの文字色と背景色のコントラスト比が WCAG AA の 4.5:1 以上になる |
| 直さないと困ること | 視力が低い利用者や明るい環境では、空状態の案内や設定項目を読み取りにくい |
| 修正規模 | 中 |

| 項目 | 内容 |
|---|---|
| 画面 | レポート、モデルエンドポイント、設定 |
| 観点 | C（文字列の表示とレイアウト）、J（アクセシビリティ） |
| 重大度 | S3 |
| 確度 | 再現済み（axe） |
| 由来 | 上流 |
| 発生条件 | 通常テーマで、レポートまたはエンドポイントが0件のとき、設定画面を表示したとき |
| 関連 | [35](./35_共通のアイコン操作に操作名がない.md) |

## 症状

axe 4.13.0 は serious の `color-contrast` を次の実画面で報告する。

| 画面 | 対象 |
|---|---|
| `/reports` | `NO REPORTS TO SHOW` |
| `/endpoints/active` | `NO ACTIVE MODEL ENDPOINTS` |
| `/settings/profile` | 設定の見出し・ラベル |

## 再現手順

1. レポート、エンドポイント、設定プロフィールを開く
2. `npx playwright test -c x-不具合調査/scripts/playwright.config.ts p3-later-screens.spec.ts --grep 'axe'` を実行する
3. `/reports`、`/endpoints/active`、`/settings/profile` の `color-contrast` を確認する

## 原因

[reports-list.component.scss:15](../src/app/webapp-common/reports/reports-list/reports-list.component.scss#L15) と [serving-empty-state.component.scss:11](../src/app/features/serving/empty-state/serving-empty-state.component.scss#L11) は、空状態の通常サイズ文字に `--color-empty-state` を使う。[colors.scss:108](../src/app/webapp-common/styles/customizations/colors.scss#L108)・[同:148](../src/app/webapp-common/styles/customizations/colors.scss#L148) のテーマ値が背景との組合せで不足する。設定の見出しも [settings.component.scss:105](../src/app/webapp-common/settings/settings.component.scss#L105) で低コントラストの `--color-outline` を本文サイズに使う。

## 影響範囲と同種箇所

`--color-empty-state` はレポート・エンドポイント以外の空状態にも使われているため、テーマトークンを変更する場合は全空状態を確認する必要がある。`--color-outline` は境界線と補助文字の双方に使われており、本文色として使う箇所だけを区別する必要がある。

## 対策案

本文用には背景とのコントラストを満たす専用トークンを定義するか、`--color-on-surface` に寄せる。ダーク・ライト両テーマで文字色と背景色の比を測定し、主要な空状態・設定画面を axe の回帰対象に加える。

## 検証範囲

- 確認したこと：実バックエンドの0件画面を Playwright（Chromium）と axe 4.13.0 で検査した
- 確認していないこと：全テーマ、全空状態、実ユーザー環境での可読性
- 由来：対象ファイルは比較資料で実質差分に含まれない
