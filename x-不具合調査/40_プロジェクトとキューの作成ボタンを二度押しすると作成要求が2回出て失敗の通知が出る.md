## 症状

モック API で作成の応答を400ms 遅らせ、2回目以降の作成をサーバと同じく「既に存在する」で失敗させて、作成ボタンをダブルクリックした。

| ダイアログ | 作成の要求 | 通知 | ダイアログ |
|---|---:|---|---|
| NEW PROJECT | `projects.create` 2回 | 「Project Created Failed」だけ | 開いたまま |
| NEW QUEUE | `queues.create` 2回 | 「Queue Created Successfully」と「Queue Created Failed」 | 閉じる |

プロジェクトは、1回目の要求がサーバに届いていれば作成されている。画面は失敗を伝えてダイアログを残すため、利用者はもう一度 CREATE PROJECT を押し、同じ名前のため再び失敗する。

## 再現手順

1. プロジェクトの一覧で **NEW PROJECT** を押す
2. 名前を入れて **CREATE PROJECT** をダブルクリックする
3. 「Project Created Failed」が出て、ダイアログが残る。プロジェクトの一覧を再読み込みすると、プロジェクトはできている

キューは **NEW QUEUE** で同じ操作をする。

Playwright の再現は [scripts/p4-double-click-create.spec.ts](./scripts/p4-double-click-create.spec.ts)。モック API を使うため、実データは作らない。

## 原因

プロジェクトの作成ボタンは、フォームが無効なときだけ無効になり、要求中は押せる（[create-new-project-form.component.html:78](../src/app/webapp-common/shared/project-dialog/create-new-project-form/create-new-project-form.component.html#L78)）。押すたびに `createNewProject` が dispatch され、Effect は `switchMap` で受ける（[project-dialog.effects.ts:43](../src/app/webapp-common/shared/project-dialog/project-dialog.effects.ts#L43)）。2回目の action で1回目の要求の購読が解除され、1回目の成功（ダイアログを閉じる処理、[同:45](../src/app/webapp-common/shared/project-dialog/project-dialog.effects.ts#L45)）は捨てられる。購読を解除しても、送信済みの要求はサーバで処理される。2回目は同じ名前のため失敗し、`catchError` が「Project Created Failed」を出す（[同:52](../src/app/webapp-common/shared/project-dialog/project-dialog.effects.ts#L52)）。

キューの作成ボタンも要求中は押せ（[create-new-queue-form.component.html:36](../src/app/webapp-common/shared/queue-create-dialog/create-new-queue-form/create-new-queue-form.component.html#L36)）、Effect は `mergeMap` で2回の要求を両方処理する（[queue-create-dialog.effects.ts:26](../src/app/webapp-common/shared/queue-create-dialog/queue-create-dialog.effects.ts#L26)）。1回目の成功でダイアログが閉じ（[queue-create-dialog.component.ts:45](../src/app/webapp-common/shared/queue-create-dialog/queue-create-dialog.component.ts#L45)）、2回目の失敗の通知も出る。

サーバ（apiserver 2.4.0）はプロジェクト名・キュー名を会社内で一意にする（`unique_with=company`）ため、2回目は必ず失敗する。

## 影響範囲と同種箇所

- プロジェクトの編集（`updateProject`）も同じ Effect の作りで、保存ボタンの二度押しで要求が2回出る（同じ値の更新のため結果は変わらない）
- キューの編集（`updateQueue`）も `mergeMap` で2回処理され、成功の通知が2回出る
- ほかの作成・確定のダイアログ（タスク・レポートの作成、クローン、移動、Enqueue など）は、確定ボタンでダイアログを先に閉じてから `afterClosed()` で1回だけ dispatch するため、二度押しで要求は増えない

## 対策案

作成・保存の要求中はボタンを無効にする。ダイアログは既に作成の状態（`CREATION_STATUS`）を Store に持つので、要求中の状態を足してボタンの `disabled` に加える。

Effect 側では、作成に `switchMap` を使わず `exhaustMap` にする。要求中に届いた2回目の action を捨てるため、ボタン以外の経路（Enter など）で二重に dispatch されても要求は1回になる。

## 検証範囲

- 確認したこと：モック API で、ダブルクリックにより作成の要求が2回出ること、プロジェクトは失敗の通知だけが出てダイアログが残ること、キューは成功と失敗の通知が出ることを確認した。サーバの一意性は起動中の apiserver のコード（`database/model/project.py`・`queue.py`）で確かめた（読み取りだけ）
- 確認していないこと：実バックエンドでの再現（実データのプロジェクト・キューが増えるため）。購読の解除で中断された1回目の要求がサーバで処理されることは、HTTP の性質による推定で、実際には確かめていない
- 由来：`project-dialog.effects.ts`・`create-new-project-form`・`queue-create-dialog` は比較資料で実質差分に含まれない
