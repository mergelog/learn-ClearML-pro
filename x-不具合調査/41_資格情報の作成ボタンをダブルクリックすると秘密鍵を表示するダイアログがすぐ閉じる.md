# 資格情報の作成ボタンをダブルクリックすると、秘密鍵を表示するダイアログがすぐ閉じる

| 項目 | 内容 |
|---|---|
| カテゴリー | 操作 |
| 不具合内容 | 設定の Workspace で「Create new credentials」をダブルクリックすると、1回目のクリックで資格情報が作成されてダイアログが開き、2回目のクリックがダイアログの背景に当たってダイアログが閉じる。秘密鍵はこのダイアログでしか表示されないため、作成された資格情報は使えないまま残る |
| 期待動作 | 作成した資格情報のダイアログは、利用者が閉じる操作をするまで残る |
| 直さないと困ること | 秘密鍵を控えられず、資格情報を作り直す必要がある。使えない資格情報が一覧に残り、手で削除する必要がある |
| 修正規模 | 極小 |

| 項目 | 内容 |
|---|---|
| 画面 | 設定 > Workspace > API CREDENTIALS |
| 観点 | J（連打したときの二重実行） |
| 重大度 | S3 |
| 確度 | 再現済み（モック API） |
| 由来 | 上流 |
| 発生条件 | 「Create new credentials」をダブルクリックする |
| 関連 | [40](./40_プロジェクトとキューの作成ボタンを二度押しすると作成要求が2回出て失敗の通知が出る.md)（作成の二度押しの別件） |

## 症状

モック API で「Create new credentials」を押した結果を比べた。

| 操作 | `auth.create_credentials` | 作成後のダイアログ |
|---|---:|---|
| クリック1回 | 1回 | 残る（Access key・Secret key と設定の手順を表示） |
| ダブルクリック | 1回 | 閉じている。一覧には作成された資格情報（`AK-TEST`）が増える |

## 再現手順

1. 設定の **Workspace** を開く
2. API CREDENTIALS の **Create new credentials** をダブルクリックする
3. 一覧に資格情報が1件増えるが、Secret key を表示するダイアログは表示されない（開いた直後に閉じる）

Playwright の再現は [scripts/p4-double-click-create.spec.ts](./scripts/p4-double-click-create.spec.ts)（「資格情報」の2件）。モック API を使うため、実データは作らない。

## 原因

`createCredential()` は、ダイアログを開いてから作成の action を dispatch する（[user-credentials.component.ts:47](../src/app/features/settings/containers/admin/user-credentials/user-credentials.component.ts#L47)、[同:49](../src/app/features/settings/containers/admin/user-credentials/user-credentials.component.ts#L49)）。ダイアログは `disableClose` を指定していないため、背景のクリックで閉じる。ダブルクリックの2回目は、開いたばかりのダイアログの背景に当たり、ダイアログを閉じる。

ボタンは作成中に `disabled` クラスを付けるが（[user-credentials.component.html:21](../src/app/features/settings/containers/admin/user-credentials/user-credentials.component.html#L21)）、2回目のクリックはボタンではなく背景に届くため、この指定では防げない。作成の action は1回しか出ていないので、要求の二重実行ではない。

## 影響範囲と同種箇所

- 秘密鍵を一度だけ表示するのはこのダイアログだけで、閉じた後に秘密鍵を取り出す手段は無い
- ほかのボタンでも、ダイアログを開く操作をダブルクリックすると同じく背景のクリックで閉じるが、開き直せば済むため不具合として数えない
- 初回の案内（welcome message）の「CREATE NEW CREDENTIALS」は、押した時点でボタンを消し、ダイアログの中に結果を表示するため、同じ問題は無い

## 対策案

作成した資格情報のダイアログを `disableClose: true` で開き、閉じる操作をボタン（閉じる、コピーの後に閉じるなど）に限る。秘密鍵を一度しか表示しない画面は、誤操作で閉じられないことが前提になる。

## 検証範囲

- 確認したこと：モック API で、クリック1回ではダイアログが残り、ダブルクリックでは作成の要求が1回出たうえでダイアログが閉じていることを確認した
- 確認していないこと：実バックエンドでの再現（実データに資格情報が増えるため）。背景に当たったことは、ダイアログが `disableClose` を持たないことと結果から判断しており、クリックの着地点そのものは記録していない
- 由来：`user-credentials.component` は比較資料で実質差分に含まれない
