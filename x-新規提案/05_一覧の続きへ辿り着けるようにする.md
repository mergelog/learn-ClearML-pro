# 一覧の続きへ辿り着けるようにする

| 項目 | 内容 |
| --- | --- |
| 分類 | UX体験 |
| 領域 | 自作（`features/data-catalog`） |
| 直る体験 | 上限を超えた資産に辿り着ける。並べ替えて上位だけを見られる |
| 規模 | 中 |
| 状態 | 未着手 |

## いま画面で起きていること

台帳の一覧は 50件で打ち切られ、その先へ行く手段が無い。

[data-catalog.consts.ts](../src/app/features/data-catalog/data-catalog.consts.ts) の `CATALOG_PAGE_SIZE` が 50、`PER_KIND_PAGE_SIZE` が同じ 50 である。種別ごとに 50件ずつ引いて混ぜ、そこから 50件へ切る。打ち切ったことは黙らず、表の `<caption>` と本文で知らせている。

```
— showing the first {{ pageLimit }}; narrow the filters to see the rest.
```

［[catalog-assets-table.component.html:5](../src/app/features/data-catalog/components/catalog-assets-table/catalog-assets-table.component.html#L5)］

続きを見る方法として案内されているのは、絞り込みを狭めることだけである。並べ替えも無いため、「最近更新された順で上位20件」のような見方もできない。表の列見出しは `<th scope="col">` の文字で、押せる要素ではない（[同:10-15](../src/app/features/data-catalog/components/catalog-assets-table/catalog-assets-table.component.html#L10)）。

取り込み領域には、続きを読む部品が2つある。[`DotsLoadMoreComponent`](../src/app/webapp-common/shared/ui-components/indicators/dots-load-more/dots-load-more.component.ts) と、その内側が使う [`ScrollEndDirective`](../src/app/webapp-common/shared/ui-components/directives/scroll-end.directive.ts) である。プロジェクト一覧・パイプライン一覧・Dataset 一覧・タグのメニューが、この部品で続きを読んでいる。

## なぜ変えるか

「絞り込みを狭めてください」は、探しているものが何か分かっている利用者にしか通じない。台帳の役割は横断して見渡すことで（[data-catalog-page.component.html:4-7](../src/app/features/data-catalog/containers/data-catalog-page/data-catalog-page.component.html#L4)）、見渡す前に狭めろと言うのは役割と噛み合わない。

さらに、50件の切り方が「混ぜてから切る」である以上、切られた50件が何を基準に選ばれたかは画面から読み取れない。並べ替えが無い状態での打ち切りは、「上位50件」ですらなく「たまたま先頭に来た50件」である。

## 解決とみなす状態

1. 更新日時・名前・種別・プロジェクトの4列で並べ替えられる。並べ替えの条件は URL のクエリに乗る（既存の `QUERY_KEYS` に `sort` を足す）
2. 並べ替えは ClearML 側へ渡す。混ぜてから並べ替えると、切られた分が並べ替えに参加しない
3. 続きを読む導線がある。`DotsLoadMoreComponent` を使い、押すたびに次の50件を足す。無限スクロールにはしない（何件見たかが分からなくなり、URL でも共有できない）
4. 何件目まで見ているかを表示する。「50 / まだある」で足りる。総件数は種別ごとに別の問い合わせになるため出さない（[data-catalog.model.ts](../src/app/features/data-catalog/data-catalog.model.ts) の `CatalogPage.hasMore` の判断を維持する）
5. 書き出し（Export JSON）は、いま画面にあるものの写しという性質を変えない（ADR 010）。読み足した分は書き出しにも入る

## 変更の範囲

* 変更：`data-catalog.query.ts`（`sort` の読み書き）、`data-catalog.consts.ts`（`QUERY_KEYS`）
* 変更：`data-catalog-api.service.ts`（並べ替えと続きの読み込みを ClearML の `order_by` / `page` へ渡す）
* 変更：reducer に「読み足した結果を末尾へ足す」経路を追加する。条件が変わったときは足さずに置き換える
* 変更：`catalog-assets-table` の列見出しを `<button>` にする。`aria-sort` を付ける

## 確かめ方

* 単体：条件が変わったときに読み足し分が捨てられること。同じ条件での読み足しが重複行を作らないこと
* E2E：[e2e/data-catalog.spec.ts](../e2e/data-catalog.spec.ts) に、並べ替えた URL を直接開いて同じ並びになることを足す

## 注意

種別ごとに別の問い合わせを出して混ぜる構造のままでは、「更新日時の降順で51件目」を正しく取るのに種別ごとの継続位置を別々に覚える必要がある。単純な `page` の加算では、種別間で件数が偏ったときに抜けが出る。継続位置を種別ごとに持つか、並べ替えを更新日時に限って時刻をカーソルにするかを、着手時に決める。
