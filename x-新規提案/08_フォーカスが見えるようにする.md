| 項目 | 内容 |
| --- | --- |
| 分類 | UX体験 |
| 領域 | 凍結（`webapp-common/styles/reboot.scss`）。影響は自作画面を含む全画面 |
| 直る体験 | キーボードで操作したとき、いまどこにいるか分かる |
| 規模 | 小（変更は数行）。ただし影響範囲は全画面 |
| 状態 | 未着手 |

## いま画面で起きていること

大域のスタイルが、すべての要素の輪郭線を打ち消している。

```scss
* {
  outline: none !important;
}
```

［[reboot.scss:3-5](../src/app/webapp-common/styles/reboot.scss#L3)］

`reboot.scss` は [style.scss:5](../src/app/webapp-common/styles/style.scss#L5) から `@forward` され、[angular.json:52-56](../angular.json#L52) で `global-styles` として全画面に注入される。`!important` 付きの全称セレクタなので、後から書いたどの規則よりも強い。

`src` 全体で `:focus-visible` を使った規則は0件である。個別の `outline: none` も3箇所ある（[drawer](../src/app/webapp-common/shared/ui-components/panel/drawer/drawer.component.scss#L52)、[markdown-editor](../src/app/webapp-common/shared/components/markdown-editor/markdown-editor.component.scss#L214)、[search](../src/app/webapp-common/shared/ui-components/inputs/search/search.component.scss#L33)）。

自作画面は素の `<button>`・`<a>`・`<input>` で組まれているため（[catalog-filters.component.html](../src/app/features/data-catalog/components/catalog-filters/catalog-filters.component.html)、[run-summary.component.html](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html)）、ブラウザ既定の輪郭線以外に焦点の手がかりが無い。それが消されている。

このリポジトリの scss には、焦点の見た目を定める規則が1つも無い。`:focus-visible` は0件で、`:focus` を使った規則も[expansion-panel.scss:20](../src/app/webapp-common/styles/customizations/expansion-panel.scss#L20) の1件だけである。つまり焦点が見えるかどうかは、Material と PrimeNG の内部の実装が `outline` 以外の手段（擬似要素や影）を使っているかどうかに委ねられていて、この側では決めていない。どの画面で見えてどの画面で見えないかは、実機で確かめる必要がある。

## なぜ変えるか

[e2e/accessibility.spec.ts:78-96](../e2e/accessibility.spec.ts#L78) は「キーボードだけで実行を起動できる」ことを検査していて、通っている。しかしこの検査が見ているのは Tab を押した後にどの要素が `:focus` になるかであり、その要素が見えるかどうかではない。axe も `outline: none` を違反として報告しない。適合の検査が通っていることと、キーボードで使えることは別である。

`x-不具合調査` の [43](../x-不具合調査/43_hoverでだけ表示するボタンにキーボードのフォーカスが当たっても見えない.md) は、hover のときだけ現れるボタンに焦点が当たっても見えない件として登録されている。あれは同じ問題の一部で、根は全称セレクタのほうにある。

## 解決とみなす状態

1. `reboot.scss` の全称セレクタを外す。代わりに `:focus-visible` に対する輪郭線を1つ定義する。太さと色はテーマ変数から取り、明暗どちらのテーマでも背景との対比を満たす
2. `:focus`（マウスでの押下を含む）には輪郭線を出さない。全称セレクタが置かれた動機はおそらくここにあり、`:focus-visible` はその動機を満たしたまま焦点を残せる
3. 個別の `outline: none` 3箇所を、同じ理由で見直す
4. hover のときだけ現れる操作は、焦点が当たったときにも現れるようにする（`:focus-within` を hover と並べる）

## 変更の範囲

* 変更：[reboot.scss](../src/app/webapp-common/styles/reboot.scss)（数行）
* 変更：上記3ファイルの個別指定
* 確認：Material・PrimeNG の部品で、いままで輪郭線が消えていた前提で組まれた見た目が崩れないか

## 確かめ方

* 目視：主要な画面で Tab を押し続け、焦点の位置が常に見えること。明暗の両テーマで見る
* E2E：焦点の可視性は自動で測りにくい。スクリーンショットの比較を1画面だけ置くか、目視の手順として残すかを着手時に決める

## 注意（凍結領域）

これはレビュー基準 [§4.6](../docs/phase7_チーム開発標準/62_レビュー基準.md) が言う「自作側で解けないかを見て、解けないときだけ入れる」に当たる。自作側の `.scss` から `!important` 付きの全称セレクタを上書きすることは、同じ強さの `!important` を自作側に書けば技術的には可能である。ただしそれは、全画面に効いている規則を自作画面だけ例外にする形になり、画面ごとに焦点が見えたり見えなかったりする状態を固定する。上流の更新で `reboot.scss` が変わったときに衝突する範囲は、この3行に限られる。
