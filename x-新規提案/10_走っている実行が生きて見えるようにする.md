# 走っている実行が生きて見えるようにする

| 項目 | 内容 |
| --- | --- |
| 分類 | ML体験 |
| 領域 | 自作（`features/quality-pipeline`）。共有部品を借りる場合は凍結領域の参照のみ |
| 直る体験 | 画面が自動で追いかけていることが分かる。止まっているのか動いていないのかを区別できる |
| 規模 | 小 |
| 状態 | 未着手 |

## いま画面で起きていること

追跡そのものは実装されている。[quality-pipeline.effects.ts:213-220](../src/app/features/quality-pipeline/state/quality-pipeline.effects.ts#L213) の `follow()` が `timer(0, REFRESH_INTERVAL_MS)` で5秒ごとに読み直し、終端に達したら止め、画面を離れたら `takeUntil` で止める。

画面側には、その追跡が見えない。

* 「いま自動で追いかけている」という表示が無い
* 「最後に読んだのはいつか」が無い
* 手動の再読込ボタンはあるが（[run-summary.component.html:17](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html#L17)）、自動追跡との関係が示されていない
* 追跡を止める手段が無い

状態の文字（[同:3](../src/app/features/quality-pipeline/components/run-summary/run-summary.component.html#L3)）が `queued` のまま数分変わらないとき、利用者には3つの可能性が区別できない。実行が待たされている、読み直しが失敗し続けている、画面が最初の一度しか読んでいない、である。2つめは実際に起こりうる。`keepFollowing` は読み直しの失敗では止まらない設計で（[同:266](../src/app/features/quality-pipeline/state/quality-pipeline.effects.ts#L266)）、失敗しても5秒ごとに叩き続ける。

取り込み領域には、同じ問題を解いた部品がある。

| 仕組み | 場所 | 自作側の状況 |
| --- | --- | --- |
| 自動更新の間隔（10秒） | [app.constants.ts:131](../src/app/app.constants.ts#L131) | 別に5秒を持つ |
| タブが見えているときだけ更新 | [refresh.service.ts:19-27](../src/app/webapp-common/core/services/refresh.service.ts#L19) の `selectAppVisible` | 無い。裏に回しても叩き続ける |
| 自動更新の入切 | [refresh-button.component.html:46-52](../src/app/webapp-common/shared/components/refresh-button/refresh-button.component.html#L46) の切替 | 無い |

`RefreshService` は、定義を除いて20ファイルから参照されているが、自作 feature からの参照は0である。

## なぜ変えるか

学習の実行は分単位で進む。利用者はその間、画面を開いたまま別の作業をする。戻ってきたときに最初に確かめるのは「この画面の数字は、いつのものか」である。

タブが見えていないあいだの問い合わせには、得るものが無い。5秒ごとに `tasks.get_all_ex` と、ステップ分の問い合わせを出し続ける。実行が数時間に及べば、誰も見ていない画面からの問い合わせが数千回になる。

## 解決とみなす状態

1. 追跡中であることを画面に出す。状態の横に、更新を続けていることを示す表示を置く
2. 最後に読み直した時刻を出す。失敗が続いている場合は「N分前から更新できていない」に変わる
3. タブが見えていないあいだは読み直さない。`selectAppVisible` を購読するか、`RefreshService` の tick に乗る
4. 読み直しが続けて失敗したときは間隔を広げる。5秒のまま叩き続けない。復帰したら元の間隔へ戻す
5. 間隔の定数を1つにするか、自作側が別に持つ理由を `quality-pipeline.consts.ts` に書く。いまの [REFRESH_INTERVAL_MS](../src/app/features/quality-pipeline/quality-pipeline.consts.ts) の注釈は5秒を選んだ理由を書いているが、アプリ全体が10秒であることには触れていない

## 変更の範囲

* 変更：[quality-pipeline.effects.ts](../src/app/features/quality-pipeline/state/quality-pipeline.effects.ts) の `follow()`（可視性の条件と、失敗時の間隔）
* 変更：reducer に「最後に読み直した時刻」と「連続失敗回数」を足す
* 変更：[run-summary](../src/app/features/quality-pipeline/components/run-summary/) のテンプレート
* 判断：`RefreshService` に乗るか、自前で `selectAppVisible` を読むか。前者はアプリ全体の自動更新の入切に従うことになり、この画面だけ止められなくなる

## 確かめ方

* 単体：可視性が false のあいだ読み直しが出ないこと。失敗が続いたときに間隔が広がること
* E2E：[e2e/quality-pipeline.spec.ts](../e2e/quality-pipeline.spec.ts) に、一定時間で `tasks.get_all_ex` の回数が増えることと、背面にしたときに増えないことを足す
