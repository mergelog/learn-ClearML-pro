# 実行の起動を入力から選択へ変える

| 項目 | 内容 |
| --- | --- |
| 分類 | ML体験 |
| 領域 | 自作（`features/quality-pipeline`） |
| 直る体験 | 存在しない版で起動して、失敗するまで気付かない、ということが無くなる |
| 規模 | 中 |
| 状態 | 未着手 |

## いま画面で起きていること

起動の入力は、`1.0.0` を初期値に持つ自由入力である。

```ts
datasetVersion: ['1.0.0', [Validators.required, Validators.pattern(DATASET_VERSION_PATTERN)]],
```

［[start-run-form.component.ts:44](../src/app/features/quality-pipeline/components/start-run-form/start-run-form.component.ts#L44)］

検証は書式だけである。この判断は意図されたもので、[quality-pipeline.consts.ts](../src/app/features/quality-pipeline/quality-pipeline.consts.ts) の `DATASET_VERSION_PATTERN` の注釈にこう書かれている。

> 書式の違う値でも起動要求は通ってしまい、Pipelineが実行時にDatasetを見つけられずに落ちるまで誤りが分からない。押す前に画面側で断る。

断っているのは書式の誤りだけで、存在しない版は断れていない。`2.0.0` と打てば書式を通り、Task が複製され、Queue に入り、Worker が拾い、Dataset を探して落ちる。誤りが分かるのはそこである。

初期値の `1.0.0` にも根拠が無い。その版が登録されているとは限らず、画面は確かめていない。

起動が何をするかも画面に出ていない。複製元の名前は出ているが（[start-run-form.component.html:3](../src/app/features/quality-pipeline/components/start-run-form/start-run-form.component.html#L3)）、どの Queue へ入るか（`PIPELINE_QUEUE = 'semiconductor-pipeline'`）は出ていない。その Queue を待っている Worker がいるかどうかも分からない。Worker がいなければ、実行は `queued` のまま永遠に進まない。この状態は、失敗ではないので失敗の表示にも出ない。

Queue が存在しない場合だけは、[quality-pipeline-api.service.ts:203-207](../src/app/features/quality-pipeline/data-access/quality-pipeline-api.service.ts#L203) が「Check that the queue exists.」と言う。存在するが誰も見ていない、という最も起きやすい状態には触れていない。

## なぜ変えるか

起動は、この画面の唯一の書き込み操作である。押してから失敗が分かるまでの時間が長いほど、押す前の確認の価値が上がる。Dataset の存在は、押す前に確かめられる。台帳側が既に同じ問い合わせをしている（[data-catalog-api.service.ts](../src/app/features/data-catalog/data-access/data-catalog-api.service.ts) が `data_processing` の Task を引き、[data-catalog.adapter.ts:174](../src/app/features/data-catalog/data-access/data-catalog.adapter.ts#L174) の `readRuntimeVersion` が版数を読む）。

自由入力を選択に変えると、書式の検証そのものが要らなくなる場合が多い。ただし完全には置き換えない。登録されたばかりで一覧に載っていない版を指定したい場合があるためである。

## 解決とみなす状態

1. 登録されている Dataset の版数を読み、選択肢として出す。新しい順に並べる
2. 選択肢に無い版も入力できる状態を残す。その場合は「一覧にありません」と添え、押せる状態は変えない
3. 初期値を、登録されている最新の版にする。読めなかったときだけ空にする。`1.0.0` の直書きをやめる
4. 押す前に、何が起きるかを1行で出す。複製元・Dataset の版数・入る Queue の3つ
5. その Queue を待っている Worker の有無を出す。いなければ「実行は待ち行列に入りますが、いま処理する Worker がいません」と添える。起動は止めない
6. 前回起動した版を覚えて初期値にするかどうかを決める。覚えるなら、どこに置くかを決める（`UserPreferences` は凍結領域の仕組みである）

## 変更の範囲

* 追加：`quality-pipeline-api.service.ts` に、Dataset の版数一覧と Queue の状態を読む経路
* 変更：state に選択肢と Queue の状態を足す
* 変更：[start-run-form](../src/app/features/quality-pipeline/components/start-run-form/)
* 判断：Dataset の版数を読む処理が、台帳と品質パイプラインの両方に出る。どちらかへ寄せるか、2つ持つかを決める。`data-catalog` の `data-access` は ClearML の語彙をその内側に留める約束になっているため、そのまま共有はできない

## 確かめ方

* 単体：選択肢に無い版を入力したときに、警告は出るが押せること
* E2E：[e2e/quality-pipeline.spec.ts](../e2e/quality-pipeline.spec.ts) の起動の検査を、選択に変えた後も通す。[e2e/accessibility.spec.ts:78-96](../e2e/accessibility.spec.ts#L78) がキーボードだけでの起動を見ているため、選択肢の部品がキーボードで操作できることが条件になる
